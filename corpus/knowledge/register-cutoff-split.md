# Independent register cutoffs do not authorize rotation

## The plateau caused by one shared cutoff

The prior `introduction_history` collects additions of both
`registry/append-only-accepted.tsv` and `registry/append-only-exempt.tsv`, then
orders that union topologically. Its grader explicitly binds both ledgers to
the earliest introduction (round76 module lines 145-152). A strict event that
postdates the earlier register cannot enter the later register under that
shared fence, even when the later register legitimately begins after the
event. Appending rows cannot repair a predicate that rejects their chronology.

Round77 C2 instead derives each register's first addition independently, using
`--diff-filter=A` and topological ordering rather than commit timestamps. It
reports both `accepted_cutoff` and `exempt_cutoff`, plus introduction counts
for each path. The plan also explicitly admits row events ancestral to the
audit revision: growth in an already existing register is append-only history,
not automatically rotation. The introduction cutoff identifies a register's
historical origin; it must not be paraphrased as forbidding all later growth.

This is a frozen policy description, not evidence that the new counter enforces
it. The input revision is explicit and register blobs are read there, not from
a convenient working-tree TSV. Every event is accounted exactly once.

## Carriage classes are not blanket exemptions

- **Accepted:** a line-bound row in the accepted register, under that register's
  own introduction policy.
- **Exempt-head:** the exempt register binds the audit's mechanical class, exact
  ungraded deleted-line count and complete parent-section list. An ungraded
  status alone is insufficient.
- **Permitted carriage:** the audit already marks narrowly allowed mutable
  SOURCES cells as permitted. The event qualifies only when permitted equals
  deleted and both graded and ungraded equal zero. One line in another class
  prevents this shortcut; it must fall through to the register rules.
- **Out-of-region carriage:** the file must declare an `only=` region in its
  append-only contract, and every deleted line must lie outside every declared
  region, as re-derived through the audit's `file_regions`. Any deleted line
  inside a declared region defeats the class. Missing `only=` is not an empty
  region granting universal exemption.
- **Restored or disclosed:** restoration must still be held at the audited
  revision; a disclosure must be backed by its applicable row.

The planned base partition is events=241, accepted=53, exempt=56, permitted=28,
out_of_region=4, restored=95, disclosed=5, unaccounted=0. These are the frozen
plan's expected counts, not measurements generated by this entry. Nine strict
rows alone still leave the 28+4 carriage events unnamed.

## Rotation test

Track additions for each register path across its complete reachable history.
If a path is deleted and reintroduced, compare its reintroduced row set with
the last version preceding that reintroduction. A new row absent from that
prior set is rotation, even if its event otherwise has valid ancestry or count.
Do not reset the cutoff to the re-add commit.

The frozen `rotation-reintroduced` arm must re-add a register with one new row
and exit 1 naming rotation. A clean non-rotating control is also needed;
`rotation_safe=1` printed without this witness is not execution evidence.
Other required discriminators include `missing-row`, `wrong-count`,
`wrong-class` and `inside-region`; the last prevents laundering a deletion in
`## Errata` as out-of-region.
