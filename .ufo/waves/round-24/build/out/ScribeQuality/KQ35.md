## The round-23 closure, named

Round 23 closed the C1/D4 calibration claim (isolation from repository-local Git state) with an
**unconditional refusal**, not with a measurement:

- `tools/report-landing-audit.py:438-465` — `check_history_repo(repo)` raises
  `EvalError(f"{repo}: partial clone (promisor pack)")` for any `.promisor` marker whose
  `.pack` sibling exists (`:455-457`), and `EvalError(f"{repo}: partial clone ({key})")` for
  `extensions.partialclone` or any `remote.*.promisor` key that is boolean-true (`:462-465`).
- `tools/report-landing-audit.py:948-950` — `EvalError` prints `could-not-evaluate: …` and
  returns exit 2.
- The refusal is unconditional on content: it fires before any check of whether the objects
  the audit needs are present locally. The function's own docstring (`:438-443`) says
  "whose missing objects belong to a promisor remote (absence is not evidence there)" — the
  docstring states the evidence rule the code does not apply.
- The r23 lesson recorded this as a **declared trade**, not a defect:
  `corpus/lessons/round-23.md:83-84` — "Declared tradeoffs: partial clones and shallow clones
  are refused even when every cited object is local (grid T01; RevCalibrationAxis, CritNoHarm)";
  and `corpus/lessons/round-23.md:206-209` — "a complete blobless partial clone (T01) and a
  paired promisor pack without promisor config (F23) are refused (exit 2) where frozen gave a
  verdict".

Round 24's canonical assignment reclassifies that closure: **promisor metadata alone refused
complete local repositories**, so the r23 outcome is rejected as *harmed*, not merely
over-scoped. KQ35 names the harm: the refusal is operability harm even when it is disclosed,
because a disclosure changes who is told, not whether a correct complete-state workflow is
refused. This is the same shape as the r23 M6 lesson (over-refusal shipped as isolation:
`corpus/lessons/round-23.md` M6, `comment-only-grafts` frozen 0 → current 2), one level up:
M6 was a comment-only grafts file, KQ35 is the whole promisor class.

## Why the metadata cannot carry the refusal (evidence)

- `corpus/SOURCES.md` S099 (supersedes S092, opened 2026-10-21, tier A) — git's partial-clone
  documentation, §Handling Missing Objects: "no check as to whether the missing object is
  actually a promisor object is performed". Git itself does not treat a promisor declaration
  as a statement about any particular object's presence, so a lane that refuses on the
  declaration is refusing on a fact git never asserted about the audited objects.
- The r23 grid already contains the counterexamples that make the metadata-only rule
  unfalsifiable as written:
  - `tests/report-audit/repo-state-grid.py:539-543` — `C09-promisor-false-config` expects
    exit 0 (a `remote.origin.promisor=false` key is accepted, because `git_bool` is false);
  - `tests/report-audit/repo-state-grid.py:545-549` — `C10-orphan-promisor-marker` expects
    exit 0 (a `.promisor` marker with no paired `.pack` is accepted);
  - `tests/report-audit/repo-state-grid.py:195-212` — `F23-promisor-pack-without-config`
    expects exit 2, and its fixture premise is a **genuinely absent blob**
    (`git cat-file -e <blob>` fails). Under a per-object availability rule F23 still refuses
    — but for the missing blob, not for the marker. Its pinned reason (`:704`, inside the
    `REASONS` map at `:695-708`) is currently `"promisor pack"`, which is the metadata string;
    the r24 policy change must re-pin it to the unavailable object.
  - `tests/report-audit/repo-state-grid.py:272-287` — `F06-lazy-fetch-command` is the second
    metadata-reason row: the fixture sets `extensions.partialClone`, `remote.origin.promisor`
    and `core.sshCommand` and cites a commit that does not exist locally, and the row expects
    exit 2 with the pinned reason `"partial clone"` (`:698`). Under the availability policy the
    refusal is still correct (the cited commit is genuinely absent and `--no-lazy-fetch`
    keeps it absent) but the reason must name the unavailable commit, not the declaration.
  - `tests/report-audit/repo-state-grid.py:482-496` — `F27-filter-only-promisor-remote` shows
    that `remote.<name>.partialclonefilter` alone makes a promisor remote; under the blanket
    rule it is refused for the same metadata reason, and under the availability rule it is
    refused only if a required object is really absent.

## The blanket-refusal mutant, named

**Mutant.** Take the repaired auditor (the candidate that measures local availability) and
restore the round-23 refusal: re-raise `EvalError` on any promisor metadata, i.e. the
inverse of `tests/report-audit/isolation-mutants.py:46-47` (`M14-promisor-config`) and
`:64-65` (`M22-promisor-pack`) — "metadata alone refuses". Related weakening mutants in the
same family are `M27-promisor-boolean` (`:75`) and `M29-promisor-pack-pairing` (`:78-79`).

**Why it must be in the round-24 population.** The r23 grid cannot kill it. `F23` refuses in
both arms (repaired and blanket), `T01` is a `tradeoff` row (reported, never graded — grid
docstring `:13-15`: "`open` rows … and `tradeoff` rows (declared new refusals) are reported,
never graded"), `C09`/`C10` carry no promisor metadata, and the complete-local metadata-marked
case does not exist as a graded row at all. A mutant that is mutually blind with the row that
supposedly grades it cannot be credited (KQ34's rule that kill credit goes to a channel only
when that channel's row fails with the fault the row names; KQ20's rule that a detector counts
only when the graded comparison can fail).

**How it is killed.** The repaired auditor must be run on a **paired population**: for each
promisor-marked case, an otherwise identical full clone of the same history with the same
citations (the round-24 oracle's "Full-clone and metadata-marked pairs"). Expected results:

| case | full clone | metadata-marked clone (repaired) | blanket-refusal mutant |
|---|---|---|---|
| every required object local, cited commit valid | exit 0 clean (or exit 1 landed-omitted with the same finding kinds) | same exit and same finding kinds | exit 2 → row fails → grid exit 1 → mutant killed |
| a required commit/tree/blob/report object genuinely absent (offline fixture) | exit 2 could-not-evaluate naming the object | exit 2 could-not-evaluate naming the object (reason pinned) | exit 2 → row still passes → not killed here (mutual blindness) |
| a citation unresolvable in a promisor-backed repository | exit 2 unknown, unless the same object is found locally in another audited repository | same | exit 2 (right answer, wrong reason) → not killed here |

The kill therefore comes **only** from the first row class, and the credit belongs to the
complete-local paired row, not to the missing-object row. Per `corpus/lessons/round-23.md` M1
and KQ25, the mutant is killed only when the grid exits 1; a grid that exits 2 (fixture premise
failed, could-not-evaluate) kills nothing and the run must report the mutant as surviving, not
killed.

**What the mutant must not be allowed to do.** The mutant may not be credited through a refusal
that both arms share (F23), through a `tradeoff` row (T01 is reported, never graded), or through
a grid that could not evaluate. If the round-24 promisor grid cannot kill the blanket refusal
on a complete-local paired row, the round-24 repair is not demonstrated, and the criterion's
admission clause is unmet — which is exactly the r23 defect this row exists to prevent.

## Anchors

- **KQ20 (detector must fail when the graded comparison is removed).** The blanket-refusal
  mutant is the round-24 instance of KQ20 for this channel: without the complete-local paired
  row, the graded comparison cannot fail, and the refusal is unfalsifiable.
- **KQ25 (kill credit needs the subject's verdict and a completed run).** The mutant is killed
  on grid exit 1 only; exit 2 kills nothing. This is the rule that keeps a could-not-evaluate
  from laundering into a kill.
- **KQ24/KQ17 (could-not-evaluate kept distinct from a failed observation).** Exit 2 on a
  genuinely unavailable object is the correct outcome and is not a failure; the criterion
  separates it from the exit 2 that the blanket refusal produces for a complete repository.
- **KQ32 (scope limit to trusted lane/fleet repositories).** Unchanged and still in force. KQ35
  narrows *which refusals are justified inside* that scope; it does not extend the audit's use
  to arbitrary or untrusted repositories, and the row says so.
- **KQ34 (committed, non-self-selecting crosswalk).** Unchanged. KQ35 adds one channel
  (promisor metadata) whose policy row must be present, paired and graded, and whose mutant
  must be killed on a named row.
- **KQ33 (source-reference classification) and KQ28 (report-wide hash rule).** Unchanged; the
  r24 repair changes which repositories reach them, not what they require.

## Drafting notes (for the maintainer, not part of the row)

1. The row's "admit only when" clause is written against the **measured** policy, so it stays
   true whichever way the availability check is implemented (`git rev-list --objects
   --missing=print --no-object-names`, `git cat-file -e`, or an equivalent local probe). The
   criterion constrains the outcome and the evidence, not the mechanism.
2. The reason string pinned for an exit-2 refusal must name the unavailable object and its
   repository. The r23 `REASONS` map (`tests/report-audit/repo-state-grid.py:695-708`) pins
   `"promisor pack"` for F23 and `"partial clone"` for F06; under KQ35 both are metadata
   reasons and must be re-pinned to the missing object (the blob for F23, the cited commit for
   F06). This is a policy-row expectation change and must be recorded as such in the round-24
   grid (the round-24 preregistration's "policy-row expectation changes"), not applied
   silently.
3. `T01` (`tradeoff`, grid `:689`) is a `--filter=blob:none` clone. It is not a
   "complete local" case: a blobless clone genuinely lacks blobs, so it cannot serve as the
   complete-local twin. The r24 paired population needs a *complete* clone that merely
   **carries** promisor metadata (for example, promisor config set on a full clone, or a
   partial clone whose required objects are all present locally). If T01 is retained as a
   `tradeoff` row, it must be re-labelled with what it actually demonstrates.
4. `remote.<name>.partialclonefilter` (F27) makes a remote promisor without
   `remote.<name>.promisor`; the r23 audit refused it through the config loop at
   `tools/report-landing-audit.py:462-465` only because `git_bool` sees a non-empty value as
   true. KQ35 must not accidentally widen that loop into "any remote config key" — the
   criterion turns on object availability, not on the set of config spellings.
5. KQ35 does not claim a new exit code, a new finding kind, or a new verdict vocabulary. It
   constrains which refusals are justified, requires the justification to name the missing
   object, and requires the detector that proves it (the blanket-refusal mutant).
6. Not verified by this seat: no grid, mutant run, selftest or probe was executed. The
   availability measurement, its deadline, and the paired fixtures are owned by the repair and
   grid lanes; the row is written to be satisfiable by any correct implementation of the
   declared policy.
