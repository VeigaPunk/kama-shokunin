## 4. Kill evidence
- Killed-by-selftest (exact reasons from `_selftest`):
  - m02: `AssertionError: provenance-member-size-mismatch: not raised` (selftest expects the size-mismatch token with `server_size=1`).
  - m04: `AssertionError: provenance-archive-not-regular: got provenance-archive-unreadable` (dir path now passes `S_ISREG`, fails later at `open()`).
  - m16: `AttributeError: 'NoneType' object has no attribute 'isfile'` (`found=None` falls through to `.isfile()`).
  - m01/m06: selftest does not terminate. Direct bounded probe (`signal.alarm(8)` around `verify_archive_member` with the C1 `sparse-1e15` GNU-sparse PAX member): pristine raises `SetupError('provenance-member-sparse')` instantly; m01 and m06 **hang >8 s inside member hashing** (`for chunk in iter(lambda: fh.read(1<<20), b'')` never ends on the extracted sparse stream). The sparse guard is therefore not only a correctness gate — it is what makes `verify_archive_member` total (the C1 `cap_leg` 30 s subprocess timeout would also have flagged both, had selftest let them through).
- Killed-by-counter (per-leg failure modes from `c1-<id>.out`):
  - m07: `no ready.json (replay exit None)` ×3 — ready.json lacks `pid`, so the counter never treats it as ready, never writes `release`, and the replay only exits after its own 120 s hold timeout; counter then FAILs.
  - m11: `no ready.json (replay exit 0)` ×3 — hold returns immediately after writing ready.json; teardown races the counter's 0.2 s poll, so `ready.json`/server are gone before observation.
  - m18: `rerun receipt does not record witness.released true` ×3 (observe otherwise ok).
  - r01/r02: `no ready.json (replay exit …)` — witness never requested, no ready.json.
  - r03: `replay exit 2 match False refused could-not-run:TypeError:…` — float argv element.
  - r05: `replay exit 2 … refused could-not-run:FileNotFoundError: No such file or directory: '--witness-dir'` — `argv[0:0]` replaces the interpreter slot.
  - r06: live `parser.error` (witness dir now "must not exist") → live exit 2 → replay `no-rerun-receipt`.

## 5. Survivors = coverage findings (proposed killing cases)
1. **m03 / m05 (archive caps unobserved).** Neither selftest nor `cap_leg` builds a >4096-member or >1 GiB archive. *Killing case:* add to `_provenance_selftest`/`cap_leg` an archive with `MEMBER_MAX_COUNT+1` index entries asserting `provenance-archive-too-many-members`, and a member-count/byte cap probe (e.g. `ftruncate`/sparse file > `ARCHIVE_MAX_BYTES` with a tiny real index) asserting `provenance-archive-too-large`.
2. **m08 (ready.json schema unvalidated).** The counter only type-checks `pid`/`port` ints (`round49-replay-witness-audit.py:306-308`); schema is ignored. *Killing case:* require `ready["schema"] == "kama-live-witness/v1"` (and the rerun receipt's `witness.schema`) before observing.
3. **m10 / m17 (release semantics unenforced — highest-value finding).** `hold_for_witness` (live 295-296) may ignore the `release` file entirely (m10) or react up to 60 s late (m17) and the counter still passes: it writes `release`, then only checks *after replay exit* that the server is gone (`round49-replay-witness-audit.py:327-329`). `released: True` in the receipt merely reflects that the release file exists — not that the loop acted on it. *Killing case:* after writing `release`, poll `pid_alive(pid)` / `port_refuses(port)` with a strict latency bound (e.g. ≤5 s) before allowing the replay to finish; m10 (full 120 s hold) and m17 (60 s poll) both die.
4. **m12 (post-witness `verify_live` invisible).** Removing the tool's own post-witness liveness gate (live 1864-1867) is not observed; the counter's /proc checks cover the *outside* view only. *Killing case:* receipt must record an explicit `witness.post_verify: "ok"` field (set only by the gate) that the counter asserts.
5. **m15 (`waited_ms` units).** The counter never reads `waited_ms`. *Killing case:* compare `waited_ms` to the counter's own measured hold duration (release − ready) within a tolerance (±5 s); the seconds-unit bug then fails by ~1000×.
6. **m13 (≈equivalent).** `isfile` vs `exists` on the release path differs only for a directory named `release`; low risk. Confirm/improve contract text if desired.
7. **r04 (≈equivalent).** Dropping `+witness_timeout` from the subprocess deadline (replay 281) only matters when download+hold exceed the base 600 s; keep the term. Optional counter check: `replay` must still complete within `timeout + witness_timeout` when a hold is requested.
