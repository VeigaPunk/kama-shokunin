## 6. Findings

**F1 (minor, robustness — non-falsifying): SIGTERM still leaks a full tree export.** Neither counter installs a SIGTERM handler, and CPython's default SIGTERM disposition terminates the process without interpreter shutdown, so `atexit` never runs. Command and evidence in §5 row 6. The frozen C2 predicate is unaffected — preregistration.json C2: "both round-41 counters, run with TMPDIR set to an empty private directory, leave it empty (hygiene=1)" — and the frozen counter's hygiene leg (`tools/round42-digest-audit.py:325-338`) likewise exercises only the normal path (it runs the counters with `subprocess.run(..., timeout=900)` and checks `os.listdir(priv)` is empty; it never signals them). So `hygiene=1` at the tip is honest. But the defect R41A10-10 routed was disk filling, and a `kill -TERM`/`timeout`/service-stop during a slow counter re-creates it (a complete export is ~260 MB / ~19.7k files). Proposed fix (both files, in `main()` before `evaluate`, or after the imports):

```python
import signal
signal.signal(signal.SIGTERM, lambda *_: sys.exit(143))
```

A handler raising `SystemExit` unwinds the interpreter normally, so the existing `atexit` registration then removes the export. SIGKILL remains uncoverable (pre-declared known gap).

**F2 (observation, no action): the frozen hygiene leg does not pin the counters' exit codes** (`tools/round42-digest-audit.py:330-333` discards the return of `subprocess.run`), so a counter that crashed *before* creating its export would still score `hygiene=1`. Harmless today (rows 2–4 show the real exit paths clean), noted only as a limit of what `hygiene=1` certifies.

**F3 (transparency, resolved): my first signal attempt was invalid and leaked into shared /tmp.** The first three `timeout -s TERM/KILL` runs were launched without the `TMPDIR=` prefix (my command error) and leaked three exports (~180 MB: `r41c1-bpax35ii` 77 MB, `r41c2-1c7nxri9` 52 MB, `r41c2-trgrcmp9` 52 MB) into `/tmp`. I removed exactly those three (`REMAINING=1` afterwards) and redid the tests correctly (§5). The incident is itself a live demonstration of F1's point at the caller level.

**F4 (observation, transient): a concurrent seat leaked into /tmp mid-wave.** `/tmp/r41c1-yc6zkmy4` appeared at 19:04:24 (121 MB, mid-extraction, not mine) and was gone by ~19:10 — consistent with a patched-counter run under the default TMPDIR that cleaned at its own exit. No residue at end of seat: `ls -d /tmp/r41c1-* /tmp/r41c2-*` → `TMP_R41_LEFTOVER=0`.
