- `corpus/SOURCES.md` already carries a per-row freshness cadence: 171 `on-release`,

  targets is already scheduled — S196 (`v0.17.0`), S330 (`v0.19.1`), S347 (`v0.9.0`),

  (S474, landed this round, is `180d`).
- The S472 row already states the exact recheck command **with its expected value and
  a flip condition** (`corpus/knowledge/sglang-docs-version-pinning-amendment-2026-10-23.md`,
  `recheck:` line: re-run `git ls-remote --tags … | sort -V | tail -1`, expect
  `v0.5.22`; "any later name reopens this entry"). The trigger the proposal asks for
  is therefore already in the corpus, in a form a reader can execute.

Measured live today (read-only network, 2026-10-25):
- `git ls-remote --tags https://github.com/sgl-project/sglang.git` → exit 0; highest
  release tag is still `v0.5.22`; `refs/tags/v0.5.23` and `v0.5.24` count **0**.
  A watch run today would report no change — the proposal's trigger fires on nothing.
- The proposal's own version list is incomplete. It names four vLLM versions
  (`v0.9.0, v0.17.0, v0.19.1, v0.32.0`); the registry actually pins **five**
  docs-site versions — `v0.9.0, v0.17.0, v0.19.1, v0.25.0, v0.32.0` (S022 carries
  `v0.25.0` at `recheck=on-release`, `status=queued`). A watch built from the
  proposal's list would silently skip a pinned row.
- Namespace mismatch for the vLLM half. The five vLLM versions the rows cite
  (`v0.9.0, v0.17.0, v0.19.1, v0.25.0, v0.32.0`) are **docs-site** versions
  (`docs.vllm.ai/en/vX.Y.Z/…`, S022/S196/S327/S330/S347/S363); upstream `vllm` git tags
  are a different set. Measured: upstream has `v0.32.0` (release) and `v0.32.1rc0`
  but **no** `v0.32.1` release; the docs site serves `v0.30.0`/`v0.31.0`/`v0.32.0`
  (HTTP 200) and 404s `v0.31.1`, `v0.32.1`, `v0.33.0`. All four cited doc URLs still
  return 200. A "newer release appeared" check over git tags cannot detect a newer
  *docs* version, and it would false-positive on rc/post tags — the same hazard the
  S472 amendment itself records ("`sort -V` … ranks `v0.5.10rc0` above `v0.5.10`").
  A correct watch needs a release-only filter *and* a docs-site version list.
- Freshness is not this round's axis. Round-40 authority: "operability + calibration;
  calibration 7 is the lowest non-retired numeric axis" (preregistration.json).
  Freshness (8) is not claimed and not the lowest.

Premise corrections (the reflection's own numbers are the C1 defect class):
- "round 34 launched 33 seats with `rc=1` for all of them and only 5 committed
  reports" — the committed r34 receipt supports 33 members all `rc=1`
  (`w1/out/seat-exit-codes.json`), and `wave-census.md` says 5 of 33 reports were

  with --auto` — a CLI flag clash that killed all 33 at spawn, after which the wave
  was re-dispatched. A yield line that labelled this "rate limit" would be wrong.

  attributes w1's 18 dead seats to `provider.auth_error: 403 "You have run out of
  credits or need a Grok subscription"` (quota/auth), not a route failure.
- "round 36 seats hit `429` rate limits" — true but small: two seats
  (`ScribeLog`, `RevQ206`) on `provider.rate_limit: 429`
  (`corpus/lessons/round-36.md` / `LOG.md:2201`, `round-37` report). The bulk of r36's
  53 dead were 403-quota (18) and the **L1's own seat bound** (29 killed at the 480 s
  bound, 6 at the 900 s bound). A yield line must therefore name a lane-side cause
  class (local seat-bound kill) alongside provider ones, or it will attribute the
  lane's own timeout policy to the provider.
- Also: "round 36's first attempt died" and the r39 double-dispatch (66 attempts for
  33 names) show a yield line must separate *seats launched* from *task calls*, or
  r39's true yield reads as 32/66 rather than 32/33.

Why defer rather than adopt now:
- C2 (operability) already owns the wave-evidence axis this round and is measured
  `met=True` at the tip; a second operability claim on wave evidence is not causally
  separable from C2 and would need its own frozen predicate + base control.
- The yield accounting is produced by the fleet's wave tooling and printed in the
  fleet round report; a lane-side copy is a mirror that drifts (the parked-worktree
  and stale-mirror defect class the round-40 lesson already logs).
- The daily cadence again needs an operator-side runner (KQ5 forbids installing timers).

Cheapest in-round move: this round's own wave already produced the inputs — the
r40 registry (64 members) and 62 landed seat reports under
