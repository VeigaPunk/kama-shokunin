## Risks / contradictions

- **Product/version semantics differ:** a vLLM release tag is a proxy for a versioned docs line, not proof that a particular docs page was published in or changed at that release. S476 itself says it does not establish docs-site versions. Proposed rows report repository-tag chronology, not documentation correctness or whether the cited behavior changed.
- **Do not overstate “behind”:** 39/23/18/9 is the count of higher tags matched by the frozen pattern, not a distance in releases to the cited docs page, and not a finding that each source claim is false. For vLLM v0.9.0, S363 documents a change at v0.11 to the prefix-cache hashing default; that specific S347 wording is historically superseded for v0.11+ use, but remains relevant to older deployments. Other older-version claims require page/behavior rechecks before asserting supersession.
- **S022 contradiction:** a v0.25.0 row is useful only if the queued item becomes a sourced row used by admitted knowledge. A SOURCES mention alone does not satisfy the C2 sourced leg; do not quietly treat queued as mined.
- **Tag versus docs mismatch:** S476 found latest matching release tag v0.32.0, while the watcher cannot prove the docs site’s version mapping; report both facts separately.
- **Commit pins:** S035-S037 and many later llama.cpp evidence rows are commit-pinned to 704366d76, with S038 tying that commit to b11755. Release-tag watching detects a new bN tag but does not verify source changes at that newer commit. Existing entry explicitly leaves b11887 behavior unchecked. Preserve this distinction.
- **Census limitation:** this was a targeted cross-source review of the engine/version families and citations evidenced in the round cache, not a semantically perfect parser over every numeric string in 479-line SOURCES.md and every knowledge document. Unrelated software versions, format/API version values, hashes, and incidentally mentioned versions are not release pins.
