Regimes, as written:

- **Pin is authority.** `fetch_model()` refuses with `model-fetch-no-pin` unless `--model-sha256`
  is exactly 64 hex. A URL alone never downloads anything (the CLI still requires `--model-sha256`
  at `:1346`).
- **Scheme allowlist.** `http`, `https`, `file` only (`model-fetch-scheme:<scheme>`); every
  redirect hop is re-checked (`model-fetch-redirect-scheme:<scheme>`), so an `https` download
  cannot be redirected into a scheme outside that set.
- **TMPDIR staging, verify, then publish.** The body streams into
  `tempfile.mkstemp(prefix='kama-model-fetch-')` (so `TMPDIR` decides where), is hashed while it
  lands, and only a matching digest is published with `os.replace`; a cross-filesystem staging
  dir (`EXDEV`) falls back to a sibling temp in the target directory plus rename, so the target
  path never holds unverified or partial bytes. Any failure unlinks the staging file and leaves
  the target absent.
- **No clobbering.** An existing target refuses (`model-fetch-target-exists`); a corrupt existing
  file still fails closed through the pre-existing `model-digest-mismatch` path — the URL never
  silently replaces operator data.
- **Receipt.** `model.url` (redacted), `model.fetched` (bool), `model.fetch`
  `{url, url_final, url_redacted, redirects, bytes, sha256}`. After a verified fetch,
  `model.path`/`model.sha256` are populated immediately, so a later setup error still leaves a
  receipt that names the file, its origin and its digest.
- **Redaction.** `redact_url()` drops userinfo, query and fragment: a signed S3/HF URL does not
  leak credentials into a receipt that lands in the repo; the bytes remain identified by the pin.

## 3. Why this closes D3

S485's receipts (`corpus/SOURCES.md:238`) pin the GGUF digest but not its origin, so once
`~/.cache` lost the file the run could not be repeated. From this patch a receipt carries
`model.url` (redacted) plus `model.fetched`/`model.fetch`, and the harness can rebuild the missing
file itself under the same pin. Rerun instructions become `--model-url <recorded> --model-sha256
<recorded>`; the verifier no longer depends on an undocumented cache location.

## 4. Not run, residual risks, observations

- **No live llama-server run.** This seat has no pinned `llama-server`/GGUF and the lane tool's
  full path needs both, so end-to-end evidence stops at "fetch → verified file → receipt" with a
  stub server, plus the loopback HTTP server inside the selftest. A real run after landing is the
  parent's post-integration gate step; `tests/llamacpp-live/controls.py` and
  `tests/llamacpp-live/check-receipt.py` should then be run against a fresh receipt.
- **Docs not updated, by scope.** `corpus/knowledge/llamacpp-loading-lifecycle.md:239` (the
  `kama-llamacpp-live/v3` section) enumerates receipt fields and will need a sentence for
  `model.url`/`model.fetched`/`model.fetch`; `corpus/SOURCES.md:238` (S485) cites the old tool
  digest `8c0dbb2b…`, which this change supersedes for future receipts. Both are lane files
  outside this seat's write set.
- **Redirect scheme guard** refuses non-`http(s)/file` hops. A CDN that redirects to a signed URL
  still works, but the signature is redacted — rerunning after expiry needs a fresh URL. That is
  intentional: the pin, not the URL, decides identity.
- **Pre-existing ordering** (not introduced here): the probe-existence check at `:1407` precedes
  `sha256_file()`, so a setup error there leaves `model.path`/`model.sha256` null for a *local*
  model file. The fetch branch now fills both immediately after verification; local files behave
  exactly as before. Moving the hash before the probe check would make receipts uniform — left
  alone to keep the diff minimal.
- **Pin validation is fetch-only.** The local path still compares `--model-sha256` as a string
  (historical behaviour); a malformed pin against an existing file reports
  `model-digest-mismatch`. Tightening that would change existing control outcomes, out of scope.
- **Disk cost.** A large GGUF is written once into TMPDIR and renamed when TMPDIR and the model
  directory share a filesystem; when they do not, it is copied once more to a sibling temp. With
  `TMPDIR=/fast/scratch` and a model under `~/.cache` (different filesystems) that is one extra
  copy of the model; acceptable for evidence durability, worth stating in the receipt docs.
- **No tool installs** were needed (python3 3.14.8 already present); nothing was installed or
  upgraded in this seat.
