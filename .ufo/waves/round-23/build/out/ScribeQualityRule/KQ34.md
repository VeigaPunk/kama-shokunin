## Anchors

- **KQ28 (landing audit completeness, exit 0 before the fleet commit).** KQ28's clean
  exit is the value that repo-local redirection can forge. Probe items (c) and (d)
  turn a missing or fabricated citation into a clean exit 0. KQ34 requires a fault case
  for each channel behind that exit 0, not only the existence of a clean run.
- **KQ32 (scope limit to trusted lane/fleet repositories).** KQ32 says the audit is
  limited until repo-local config/history and UTF-8/error hardening is demonstrated
  separately. KQ34 is the per-channel demonstration that KQ32 asks for. It does not lift
  the limit: a grid that passes for the named channels still scopes the claim to those
  channels, and KQ32's rejection of "scrubbing equals a security guarantee" still applies.
- **KQ33 (source-reference classification).** The committed `corpus/SOURCES.md` blob is
  itself an input. A UTF-8 or loading failure there must reach the could-not-evaluate
  exit, not a clean fallback that drops the source exemption. KQ34 treats that as one
  more named input channel with its own fault case.
- Related rules, not anchors: KQ30 (injection must reach its target), KQ20 (detector
  fails when the graded comparison is removed), KQ24/KQ17 (could-not-evaluate kept
  distinct from a failed observation).
