## Special-attention items (as assigned)

1. **"the served pool can be an operator override"** — SUPPORTED. `may_override_num_blocks` (1230–1236) replaces `num_blocks` with `cache_config.num_gpu_blocks_override` whenever the option is set, applied immediately after the memory derivation (1627→1628), with no clamp against `available_memory`. vLLM's own comment (2605–2608) states the allocated cache size is "decoupled from the profiled `available_memory`", and the override is logged at 2619–2623 (`"Overriding num_gpu_blocks=%d with num_gpu_blocks_override=%d"`). The entry could optionally cite that log line as the operator-visible trace of an override; it does not, which is omission, not error.
2. **"the min over device and host pool"** — SUPPORTED. 1221 seeds `limits` with the device-pool ratio; 1222–1226 append the host-pool ratio (`hisparse_host_num_blocks / host_blocks_per_request`) only when the request needs host blocks; 1227 returns `min(limits)`. The host pool exists only under hisparse, matching "when present". Note the host-pool budget itself (`get_hisparse_host_pool_bytes`, `get_hisparse_kv_cache_config`) is imported, not defined in this file — the entry's sentence covers the min correctly but the host budget's derivation is outside the read (gap below).
3. **"not a second independent measurement"** — SUPPORTED. The token figure is `int(max_concurrency · max_model_len)` (2308) where `max_concurrency` is itself `num_blocks/bpr` (1221) or the min with the host ratio (1227). Every input traces back to the pool and the declared length; there is no second measurement anywhere in the chain.

## Findings

**Finding 1 (minor, hedging defect) — entry line 15, "single place" is an unqualified engine-wide absolute.**
`corpus/knowledge/context-capacity-engine-sides.md:15`: "on vLLM the startup log is the single place where the declared per-request length and the served pool meet".
- The entry read one file; "on vLLM … the single place" claims knowledge of every vLLM surface (API listing, other modules' logs) the read cannot establish. The entry concedes exactly this class of uncertainty one sentence later for the HTTP listing ("not established here and is not claimed") but not here — inconsistent hedging.
- Even within the read file, startup emits other declared-length/pool pairings an operator may read as a "meeting": the insufficient-memory `ValueError` prints `max_model_len` beside available KV cache memory (`kv_cache_utils.py:1029-1039`, message body 1031–1034), and the auto-fit `info_once` messages do the same (`:2468-2473`, `:2477-2483`). Under the strict reading ("resolved served token capacity"), 2327–2334 is the only such place in the file — but the sentence carries no such qualifier.
- Command that shows it: `grep -n "max_model_len" .ufo/waves/round-42/c3/vllm-v0.32.0-kv_cache_utils.py` → hits at 1022, 1031–1036, 2377–2411, 2435–2438, 2468–2483 besides the cited 2304/2308/2323/2332.
- Proposed fix (entry line 15): scope the absolute, e.g. "within the read source, the startup log line (`kv_cache_utils.py:2327-2334`) is the only place the resolved served token capacity is printed beside the declared length; other startup messages pair the declared length with available KV cache memory (the `ValueError` at `:1029-1039`, the auto-fit logs at `:2468-2483`), and surfaces outside this file are unread." The table cell "one startup log line (:2328)" can stay with the same implication.

**Finding 2 (nuance, no fix required) — entry line 12, "the number of … requests whose blocks fit".** `get_max_concurrency_for_kv_cache_config` returns a float ratio (1195–1227), not a floored integer count; the integer count is its floor. The entry's own `int(…)` at 2308 is consistent, so the derivation is exact; only the prose phrase implies an integer. Optional rewording: "the (possibly fractional) number of `max_model_len`-long requests whose blocks fit".

**Finding 3 (nuance, no fix required) — entry line 13, "their ratio".** The printed `%.2fx` is the pre-truncation concurrency; `num_tokens/max_model_len` differs by <1/`max_model_len` after the `int()` at 2308. "Their ratio" is approximate. Optional: "their ratio up to token truncation".
