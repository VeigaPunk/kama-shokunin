## 4. Findings (outside the deletion scope; for the integration owner)

### 4.1 C2 `contract` leg survives a plausible tool mutant at the recorded seed

Mutant `oracle.diff` (`tools/digest-ledger.py:89` → `key = "external_ok"`, i.e. a ledger row pointing at an existing file with a different digest is no longer flagged `ledger_bad`):

```
selftest FAIL: external row whose file hashes differently is ledger_bad: got tokens=4 blob=1 external_ok=1 external_absent=0 unverifiable=1 wrong_flagged=1 ledger_bad=0 wrong_unflagged=0 unknown=0 exit 0
selftest pass=5 fail=1, exit 1
tool=1 contract=1 live=1 hygiene=1 capability=1 met=True seed=42   (counter exit 0)
```

The counter's `contract` leg did not see it: in `make_case` (`tools/round42-digest-audit.py:236-242`) the mismatching-`external` row needs `rng.random() < 0.7` **and** `rng.random() < 0.2` **and** the external file to still exist (`os.remove` at :221 fires at 0.3). Measured over the frozen 8-fixture set, using the counter's own `make_case`/`ref_dir`/`summary`/`exit_of` as reference:

```
python3 R42B20/sweep.py 100
seeds=100 caught=48 missed=52 miss_rate=0.520
missed seeds: [2, 8, 9, 13, 17, 20, 23, 26, 27, 29, 30, 31, 34, 40, 41, 42, 43, 44, …]
```

Seed 42 is among the 52 misses — the seed recorded in `.ufo/waves/round-42/c2/candidate.out`. So `contract=1` at the claim tip is a true reading of the frozen predicate but has no power against this defect class. The lane is not exposed today (the tool's own selftest catches it, and the shipped `classify` is correct), but the frozen `junk-c2-stub` control is the only tool mutant the fixture set was designed to kill.

Proposed fix for a future counter (not applied here — the prereg forbids changing the counter after a seat scores): make the mismatch deterministic, e.g. in `make_case` always emit one `external` row whose `path` is a file that exists and whose digest is `rand_hex(rng)`, or append a 9th fixed case. That keeps the frozen summary/exit comparison and makes `contract=0` for this mutant at every seed.

### 4.2 Method note: fixtures built with `git init` + `git archive | tar -x` + `git add -A` lose tracked-but-ignored paths

My first harness did exactly that and the *control* run read `live=0 … blob=79 … unknown=7` instead of `blob=86 … unknown=0`: `.gitignore` (`.ufo/interactive-sessions/`, `.ufo/state/`, `__pycache__/`) applies to a fresh index, so 7 blobs tracked at `3d9bd8d` never entered the fixture repo and 7 cited digests became `unknown`. `git clone --shared` + `checkout <tip>` (used for every run in this report) preserves the tracked tree and reproduces `met=True`. Any seat that sees `unknown=7` on a fixture repo should suspect its own harness before the tool.
