## Round 28 qualification -- KQ37

This append-only block supersedes the corresponding S136 wording in the KQ37 row and the inaccurate clause-(d) statement in round-27 qualification 1; it supplements the 3/17 boundary-cost disclosure and closes the round-26 defect-2 remainder. Earlier text is left in place.

1. **S139 escape wording.** Read the KQ37 row's S136 parenthetical as superseded: a BMP character can be escaped as a six-character `\uXXXX` sequence; a character outside the BMP is represented by a twelve-character UTF-16 surrogate pair. S139's SOURCES row, quoted exactly:

> | S139 | RFC 8259 — The JavaScript Object Notation (JSON) Data Interchange Format (Dec 2017; Internet Standard, STD 90 per the RFC Editor and IETF Datatracker indexes) — https://www.rfc-editor.org/rfc/rfc8259.txt | spec | A | which byte spellings encode one JSON string value; not how any one parser, server or log decodes, prints or echoes it | Section 7 "Strings", rfc8259.txt lines 433-440 (BMP six-character form) and 455-459 (surrogate pair) (fetched 2026-10-23; raw sha256 61a5378f4255c720beb2a4b4a63b29540147c140f36988bf086291989b4cd2d7) | supersedes S136 — any character of a JSON string may be escaped: a BMP character as a six-character \uXXXX sequence, a character outside the BMP as a twelve-character UTF-16 surrogate pair (S136 said six characters for any character, and named STD 90 although the RFC text itself does not). One decoded value has many raw byte spellings, so absence of a signature from raw request bytes does not rule out a decoded echo. | mined | 2026-10-23 | 180d | corpus/knowledge/echo-discriminating-counters.md, corpus/lessons/round-27.md |

2. **Corrected clause-(d) coverage.** Round-27 qualification 1's statement that clause (d) covers the one-literal part is too strong. The counter's `literal_texts` helper adds the concatenation of all extracted literals when there is more than one, and clause (d) tests membership in those candidates. It can therefore accept a signature found in the joined-literals candidate; it does not establish that the signature is contained in one individual literal (`.ufo/waves/round-27/count-c1.py:338-340,565`). This matches the entry's description that clause (d) allows a regex-extracted literal **or** the concatenation of all literals (`corpus/knowledge/echo-discriminating-counters.md:121-126`).

3. **Boundary-probe cost, scope, and open question.** Keep the 3/17 genuine-E26-row cost qualified by the probe's scope: it compared exact, case-sensitive strings in JSON-decoded request-body keys and string values at every depth, only where string length was `>= 4`; it did not inspect path, headers, or argv and applied no extra case or whitespace normalization (`.ufo/waves/round-27/residual/out/CriticBoundaryLegProbe/boundary-leg.receipt.json:10-14`; existing cost: `corpus/QUALITY.md:258-262`, entry: `corpus/knowledge/echo-discriminating-counters.md:127-132`). This is not a cost estimate for every possible KQ37 implementation or request. Separately, the offline probe exposes E26-14's lexical-coincidence refusal: the fixed server-owned diagnostic is refused by the overlap conjunct because the request key `prompt` occurs inside the signature. Whether that exact lexical coincidence alone should disqualify an otherwise server-owned signature is an open boundary-design question for the next signature counter, not a resolved rule or a newly observed live echo (`.ufo/waves/round-27/residual/advice/CriticBoundaryLegProbe.md:41-43`).

4. **Round-26 defect 2 remainder and round-28 claim boundary.** The round-27 signature-counter attempt is retired without data: round-27 C1 was withdrawn before data, no data seat was dispatched, and the A3 tip records `registered 0 counted 0 target 15 met False` (`corpus/lessons/round-27.md:15-25`; `.ufo/waves/round-27/a3/c1-tip.out:1-4`). No F3 file-content echo leg was built for that counter; the routed defect explicitly identifies that remainder (`corpus/lessons/round-27-verifier-spotcheck.md:263-265`). Accordingly, any future signature counter qualifying under KQ37 must include an F3 file/model-content echo leg and a non-author shortcut-control receipt for each named class before any data seat. This round's preregistered C1 is a request-field-outcomes claim, not a signature counter (`.ufo/waves/round-28/preregistration.json:10`). Its per-class control records are under `.ufo/waves/round-28/controls/`; the `HOLDS.md` index distinguishes receipts from classes without evidentiary receipts, so those records do not establish an F3 leg (`.ufo/waves/round-28/controls/HOLDS.md:3-20`).
