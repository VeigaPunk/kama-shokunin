## Listen port and slot-count setters (round 95 revision)

This section supersedes the round-94 "Listen port and slot-count setters" rows for `port` and
`n_parallel`. Two things change, both forced by the round-94 closure measurement (`SKILL.md`
§Round 94 correction c1-c3, `.ufo/waves/round-94/w1/SC01SetterSweep.md` F1/F2):

1. **The population admits the carriers that decide a value without naming the variable.**
   The pattern now includes the config.ini section-scoping lines (`COMMON_PRESET_DEFAULT_NAME`,
   `preset.name == "*"`), the `common_params` whole-struct copy that carries llama-cli's own
   `port`/`n_parallel` into its embedded server (`tools/cli/cli-server.h:43`), and the
   `params_base.n_parallel` realisation reads (`tools/server/server-context.cpp`,
   `tools/server/server-schema.cpp`). Round 94's pattern admitted none of them, which is why its
   decision rows were silent for `cli` and `router-child` while the values were being set.
2. **The decision model is per entry point.** Round 94 had one `R18` (port) and one `R19`
   (`n_parallel`) row for every entry together; each entry now has its own `R20`/`R21` row, and
   the row carries the precedence source that entry actually obeys. A caller reads the row for
   the program it is starting, not a summary that silently omits its entry.

**Effect vocabulary.** `default` = a member initializer or an auto-resolution a later setter may
replace; `overrides` = the line replaces a value another row already set; `copies` = the line
moves a value between structures without choosing it; `declares` = registers an option or
declares a function/member and sets nothing; `realises` = consumes the value (iterates, logs,
clamps) and chooses nothing; `unrelated` = text, tracing, URL parsing or a readback.
