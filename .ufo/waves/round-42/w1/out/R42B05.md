## 1. Findings

Severity: H = defeats the tool's stated purpose or corrupts the audited artifact; M = wrong/fragile verdicts or resource failure on realistic inputs; L = edge or divergence with no live instance found today.

### H1 (LIVE) — a cited 65-hex-char "sha256" is invisible to the tool; C2's "no cited digest unexplained" is overstated

- **Where:** `corpus/lessons/round-38.md:51` (scanned doc, present at base, born malformed in `54e2952` "round-38: claim work"):
  `Package bytes read at write time: SOURCES.append.md sha256 \`3ad0df68e8423a3b1b99d4e3b8d8c6271f7a4f4c96d3a5ad4e0a85a991ce234ff\`.`
  That string is **65** hex chars (`python3` length check on the line = 65), i.e. not a SHA-256 and it hashes nothing; the real staged-package digest `3ad0df68504e1f49…` (ledger row 3, `external`, verified external_ok at tip) is cited correctly elsewhere (`round-38.md:115`, `round-38-verifier-spotcheck.md:74`, `round-40.md:15`, `round-40-verifier-spotcheck.md:79`, `round-41.md:28`).
- **Why the tool misses it:** `tools/digest-ledger.py:52` — `TOKEN = re.compile(r"(?<![0-9a-f])[0-9a-f]{64}(?![0-9a-f])")` matches only exactly-64 runs; a 65-char run yields no token, so the citation is neither counted, classified, nor flagged. Tool tokens on that line: `[]` (direct check). Tip scan says `unknown=0`, exit 0.
- **Reproducer** (`repro.py case_overlength`): doc citing a 65-hex value as a sha256 → `tokens=0 … unknown=0`, **exit 0** (all clear).
- **Why it matters:** this is the exact disease the tool exists to catch — the docstring's round-38 S472 precedent is "cited a SHA-256 … that shared its first eight characters with the real digest and hashed nothing"; that one was 64 chars so the tool flags it (`wrong_unflagged`/`wrong_flagged`). The same class of bad citation with a corrupted *length* sails through, and the C2 predicate's spirit ("so that no cited digest is unexplained") is not met even though its letter ("every full SHA-256") is.
- **Fix (route to L1/closure; contract change):** (a) correct the `round-38.md:51` citation — the then-package bytes are not recoverable (shokuknow's committed `merge/kama/SOURCES.append.md` history stops at round-12 states; the current 196,639-byte version is uncommitted), so either cite the current real digest with a "read at round-40 state" note or reclassify the row `unverifiable` with a why-note; (b) extend the tool with a bounded-hex-run check (runs of 33–63 or 65+ hex chars bounded by non-hex → new class, e.g. `malformed`, counted into the failing exit) and amend the docstring token definition accordingly.

### H2 — partial-clone scan mutates the scanned repo (read-only violation); offline it dies

`tools/digest-ledger.py:143` runs `git cat-file --batch` over every oid from `rev-list --objects`; on a promisor (partial) clone that **lazily fetches missing blobs, writing objects into the repo under audit**, contradicting the docstring "Read-only: it reads git objects and files and writes nothing."

- **Reproducer** (`repro.py case_partial_clone`; origin gets `uploadpack.allowFilter=true`, clone `--filter=blob:none --no-checkout --no-local`, partiality asserted via `git cat-file -e <blob>` rc=128):
  - `count-objects -v` before: `in-pack: 4, packs: 1` → run `scan --repo <partial> --rev HEAD` → exit 0 → after: `in-pack: 7, packs: 4, size-pack: 5`. **The scan wrote 3 objects into the scanned repo.**
  - Same clone with the promisor remote removed (offline): `scan` → **exit 2**, stderr `digest-ledger: git rev-list --objects <rev>: fatal: missing blob object '823d0c22…'` — the tool cannot evaluate a partial clone at all.
- **Live impact today:** none — the measurement root is a full clone. Latent: any blobless/shallow-partial checkout of the lane remote (CI-style) either gets mutated mid-audit or bricks the counter.
- **Fix:** detect a promisor clone (`git config --get-regexp '^remote\..*\.promisor$'` or `extensions.partialClone`) and refuse with exit 2 and a clear message ("partial clone: blob set would be incomplete or would be fetched"), or parse `missing` batch headers and skip them plus `rev-list --missing=allow-promisor` — never fetch. Refusing is the honest choice for an audit tool.

### M1 — whole-repo payload held in memory (git mode ~4×, dir mode ~2× blob size)

- `tools/digest-ledger.py:143` captures the **entire** `cat-file --batch` output (every reachable blob's decompressed bytes) in one `p.stdout`; `:153` then slices a second full copy per blob; `:121` (dir mode) and `:88` (external hash) `f.read()` whole files.
- **Reproducer** (`repro.py case_memory`, peak child RSS via `getrusage(RUSAGE_CHILDREN)`): repo with a 256 MiB zeros blob → git mode **peak 1,069,320 KiB (~1.04 GiB)** vs small-repo baseline 19,512 KiB; dir mode over the same 256 MiB file **541,484 KiB (~529 MiB)**.
- **Live impact today:** none (lane repo is small). Risk: any future large blob (model fixtures, retained archives) OOMs the counter.
- **Fix:** stream-hash — dir/external: read in 1 MiB chunks into `hashlib.update()`; git mode: stream `cat-file --batch` with an incremental parser (or per-blob `cat-file blob <oid>` piped through a chunked hasher).

### M2 — duplicate ledger digests: last row wins; a bad row is silently masked and the verdict is order-dependent

- `tools/digest-ledger.py:69` — `rows[c[0]] = …` overwrites; nothing flags duplicates.
- **Reproducer** (`repro.py case_ledger_duplicates`), same two contradictory rows for one digest, only order differs:
  - bad row first (`wrong` with a `correct` not in the blob set → would be `ledger_bad`), good `unverifiable` row second → `unverifiable=1 … ledger_bad=0`, **exit 0** — the defective row is dropped.
  - reversed → `ledger_bad=1`, exit 1.
- **Live impact today:** none (ledger has no duplicates — checked). Fix: treat a duplicate digest key as `ledger_bad` (contradictory rows are a ledger defect under any reading), or at minimum document last-wins in the docstring.

### M3 — the C2 counter's `contract` leg is a mirror of the tool and cannot falsify it; its `live` reference also crashes where the tool exits 2

- `tools/round42-digest-audit.py:52` (`TOKEN`), `:98` (`parse_ledger`), `:109` (`classify`), `:149` (`ref_dir`), `:167` (`ref_git`) restate the tool's logic — same regex, same parser. `make_case` (`:204`) generates only clean ASCII fixtures: no uppercase, no symlinks, no encodings, no big blobs, no duplicate/CRLF ledger rows, no non-UTF-8 paths, no gitlinks, no partial clones. So `contract=1` certifies tool≡mirror, not tool≡contract.
- **Reproducer** (`repro.py case_counter_blindness`): the counter's own `ref_dir` on the H2/L2 adjacency fixture returns `tokens=3 blob=1 … unknown=2 exit=1` — byte-identical to the tool's defective output; the contract leg would pass.
- Additionally the counter's `git()` (`:89`) strict-decodes (`p.stdout.decode()`), so on a repo with a non-UTF-8 tracked path `ref_git` raises an **uncaught** `UnicodeDecodeError` (demonstrated: wrapper caught `UnicodeDecodeError 'utf-8' codec can't decode byte 0xe9 in position 178`, exit 9 in the harness) → the counter dies with a traceback (observed exit 1 semantics) where the tool at least exits 2. The `live` leg would abort, not gracefully fail.
- **Fix:** implement the counter's reference independently (e.g. manual scanner instead of the same regex), decode with `errors="replace"`, catch `UnicodeDecodeError` → exit 2, and add adversarial fixture classes to `make_case` (the ones in this report).

### L1 — uppercase cited digests are entirely invisible; uppercase ledger rows are dead

- `:52` token class is lowercase-only; `classify` looks up lowercase tokens only.
- **Reproducer** (`repro.py case_uppercase_cite`): blob exists; doc cites its digest in uppercase; ledger carries the same uppercase digest as `unverifiable` with a note → `tokens=0 … unknown=0`, **exit 0**. A full SHA-256 cite (docstring purpose: "every full SHA-256 the lane's documents cite") is unexplained yet the tool reports all-clear; the ledger row can never match anything.
- **Live impact:** none (corrected probe `[A-F][0-9a-f]{64}|[0-9a-f]{64}[A-F]` and `[0-9A-F]{64}` over all 130 scanned docs at tip: 0 hits). Fix: case-insensitive token match + lowercase-normalized ledger keys, or document the lowercase-only scope next to the purpose sentence.

### L2 — mixed-case adjacency carves false tokens out of longer hex runs (docstring violation)

- Docstring: "A token is a 64-character lower-case hex run **not adjacent to another hex character**." `:52` lookarounds only exclude `[0-9a-f]` — uppercase hex neighbors pass.
- **Reproducer** (`repro.py case_adjacency`): doc containing `'A'*64 + <digest>` (128-char mixed run), `<digest2> + 'F'` (65-char run), a pure-lowercase 128-char run (control), and a plain token → tool: `tokens=3 … unknown=2` (both mixed-case runs leak tokens); the docstring-correct regex `(?<![0-9a-fA-F])[0-9a-f]{64}(?![0-9a-fA-F])` yields exactly the plain token. Pure-lowercase long runs are correctly rejected by both (control holds).
- **Live impact:** 0 hits at tip (corrected probe). Fix: widen both lookarounds to `[0-9a-fA-F]`.

### L3 — symlink handling diverges between modes; a symlinked ledger is dead in both

- Dir mode skips symlinks (`:118`); git mode's `ls-tree -r` (`:156`) lists symlink blobs and `:162` scans a `.md` symlink's **link text** as document content.
- **Reproducer** (`repro.py case_symlink`): `link.md → ../outside/<unk>.bin` (target outside the repo):
  - git mode: `tokens=1 … unknown=1`, exit 1 — **phantom token read out of the link path string** (false positive);
  - dir mode: `tokens=0`, exit 0 — same tree, opposite verdict.
  - Symlinked `registry/digest-ledger.tsv → real-ledger.tsv`: git mode `cat-file -p` of the symlink returns the link text, so the ledger parses to a dead row; dir mode skips the symlinked ledger and — because `is_doc` only excludes the exact LEDGER path — scans `registry/real-ledger.tsv` as a **document**, leaking its digest column in as a token. Both modes: cited digest falls to `unknown`, exit 1, ledger not honored.
- **Live impact:** none — the lane's 8 symlinks all live under `.ufo/` (excluded), and the ledger is a regular file. Fix: in git mode filter `ls-tree` to blob modes (100644/100755) so symlinks/gitlinks are neither docs nor doc-content, and resolve a symlinked ledger to its target (or refuse loudly).

### L4 — line-boundary hex: a hard-wrapped 64-hex digest is missed; a wrapped 128-hex value becomes two phantom digests

- **Reproducer** (`repro.py case_split_and_wrapped`): doc with `<digest>` split 32/32 across two lines, a 128-hex value split 64/64, and an intact control → `tokens=3 … unknown=3`: the wrapped digest is never counted (missed cite — same family as H1), and the two halves of the 128-hex value are each reported as an independent SHA-256 (phantoms; per the token definition this is "correct", which is itself the problem).
- **Live impact:** 0 bounded 32/32 splits in the scanned doc set at tip. Fix: same bounded-run census as H1 catches the miss; the phantom case is a docstring-definition limitation worth a sentence, not code.

### L5 — non-UTF-8 *encodings*: UTF-16 docs are invisible; binary docs are fine (control)

- `:124`/`:162` decode with `errors="replace"` — a UTF-16 `.md` has every ASCII char NUL-interleaved, so no hex run survives.
- **Reproducer** (`repro.py case_encoding`): UTF-16 `.md` citing a digest of a present blob → `tokens=0`, exit 0 (silent miss). Binary `.md` with the ASCII digest intact → `tokens=1 blob=1`, exit 0, no crash (OK).
- **Live impact:** 0 (all 130 docs decode as UTF-8; no BOMs). Fix: none needed beyond documenting the UTF-8/ASCII assumption; a BOM/high-byte heuristic could warn.

### L6 — a non-UTF-8 tracked *path* bricks git mode (exit 2) while dir mode works

- `:142`/`:156` strict-decode `rev-list --objects` / `ls-tree -z` output; `UnicodeDecodeError` is a `ValueError`, caught at `:255` → exit 2 "usage or git error".
- **Reproducer** (`repro.py case_nonutf8_path`): tracked file named `caf\xe9.md` → git mode exit 2, stderr `digest-ledger: 'utf-8' codec can't decode byte 0xe9 in position 178`; the same tree via `--dir` → `tokens=1 blob=1`, exit 0. (Also feeds M3's counter crash.)
- **Live impact:** 0 non-UTF-8 tracked paths at tip. Fix: decode with `errors="replace"` (paths are only compared for `.ufo/`/LEDGER/suffix predicates) or work in bytes.

### L7 — a tracked gitlink whose path ends `.md` bricks git mode (exit 2)

- `:156` lists gitlink paths; `is_doc` accepts them; `:160`/`:162` `cat-file -p <rev>:<gitlink>` fails.
- **Reproducer** (`repro.py case_gitlink`): `git update-index --add --cacheinfo 160000,<sha>,notes.md` + commit → exit 2, stderr `digest-ledger: git cat-file -p <rev>:notes.md: fatal: Not a valid object name …`.
- **Live impact:** 0 gitlinks in the lane. Fix: same mode filter as L3 (blobs only).

### L8 — CRLF ledger edge: the last column silently gains `\r`; well-formed CRLF rows are fine (control)

- `parse_ledger` (`:65-70`) splits on `"\n"`, leaving `\r` on the final column.
- **Reproducer** (`repro.py case_ledger_crlf_blank`):
  - well-formed 7-column CRLF rows + 3 trailing blank lines → identical to the LF equivalent (`unverifiable=1`, exit 0) — control, OK;
  - digest-only row with CRLF → key `"<digest>\r"` never matches → `unknown=1` (LF: `ledger_bad`) — class changes with line ending;
  - truncated 4-column row with an absolute path last, CRLF → path `"<abs>\r"` → `isfile` fails → `external_absent`; the identical row with LF → `external_ok`. Only the line ending differs.
- **Live impact:** none (ledger is LF, 7 columns). Fix: `text.splitlines()` (or strip `\r`) in `parse_ledger`.

### L9 — `external` paths resolve against the process CWD, not the repo/dir

- `:86` `os.path.isfile(p)` on the raw ledger cell.
- **Reproducer** (`repro.py case_external_cwd`): ledger row `external` with relative path `evidence.bin`, file outside the scanned dir: run with CWD where the file is → `external_ok=1`, exit 0; same bytes, CWD one directory up → `external_absent=1`. The class flips with the caller's directory (the exit stays 0 either way — `external_absent` is deliberately not failing, per docstring and the preregistration's host-dependence note).
- **Live impact:** none — all four ledger `path` cells are absolute. Fix: resolve relative paths against the scanned repo/dir root and say so in the docstring.
