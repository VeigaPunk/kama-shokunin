## 3. Still unimplemented — six proposals and what one round would need

Each sketch names the instrument, the counter's legs, the fixtures that can fail, and the frozen surface it touches. None of them requires a new capability in the SCORECARD sense; all six are read-only over data the lane already commits.

**3.1 Proposal 3 — between-round drift watch for registered instruments** (`considerthese/2026-10-22.md:24`). What one round needs: a `tools/anchor-drift-watch.py` that (a) reads every `SKILL.md` registry row (`.ufo/waves/round-49/w1/out/S9Skill/skill.md` shows the row shape) and every `SCORECARD.md` capability row, (b) derives the anchor paths from the row's command (`--pins registry/engine-pins.tsv`, `--receipt …`, `--files …`), (c) finds the last commit that has a receipt for that instrument under `.ufo/waves/round-*/measured/` or `*/c2/`, and (d) exits 1 if any anchor path was touched by a commit after that receipt. Counter legs: `anchors=N drifted=D` with `--check 0`; fixtures: a synthetic repo with a receipt at rev A and an anchor edit at rev B (must exit 1), the same repo with a re-run receipt at B (must exit 0), and a row whose command names no path (must be reported, not silently skipped — the KQ36 lesson on stale instruments). Frozen surface: a new tool + gate row; KQ36 stays as the landing-time rule. Round-49 evidence that this pays: `W:S9Scorecard/SCORECARD.round49.draft.md:2866` records round-41 `mismatches=1` and round-43 `spot=1` at the build, i.e. two registered instruments had drifted by the time anyone ran them.

**3.2 Proposal 4 — split infrastructure friction from lane learning** (`considerthese/2026-10-22.md:26`). What one round needs: the lane cannot write the daily file (`.ufo/waves/round-49/w1/build_spec.py:42`), so the split must live in the round record. Concretely: a criterion that a round report and lesson carry an **owner column** on every routed defect and Mistakes row (`lane` / `orchestrator` / `operator`), and a checker that (a) classifies each row from the closure's own "**R4 (orchestrator/operator, …)**" prefix (`corpus/lessons/round-48-verifier-spotcheck.md:113`), (b) fails when an `orchestrator`/`operator` defect sits under `## Mistakes`, and (c) counts `lane`-owned rows per round so the trend is readable. Fixtures: one report with an operator defect under Mistakes (exit 1), one with it under a separate `## Operator-side events` heading (exit 0), one with an unlabelled row (exit 1). **3.3 Proposal 5 — shortcut-class ledger across rounds** (`considerthese/2026-10-23.md:29`). ## 4. Findings

**F1 — round 49's preregistration drops the proposal pointer that rounds 46-48 all carry.** `.ufo/waves/round-49/preregistration.json` has no `frontier` key (keys printed in `commands.txt`), while `.ufo/waves/round-46/preregistration.json:150`, `round-47:56` and `round-48:55` each carry `frontier.considerthese` naming the proposal the round mines. Command that shows it: `for r in 46 47 48 49; do python3 -c "…print(r, list(d.keys()), (d.get('frontier') or {}).get('considerthese'))"; done` → `49 … None`. Consequence: the lane's only machine-readable proposal record is gone for the round that also has no lesson line and no LOG line (§0), so this seat's table is the only place round 49's (zero) uptake exists. The integrated round-49 SCORECARD section does not fill the gap either: `awk '/^## Round 49/{f=1} f' SCORECARD.md \| grep -cE 'considerthese|proposal'` → `0` (`SCORECARD.md:2813` onward, working tree). Proposed fix: restore `"frontier": {"considerthese": "none this round (C1/C2 mine the round-48 closure R1/R5); the tracker is seat S8Considerthese"}` — a declared "none" is a record; an absent field is not.

**F2 — rounds 48 and 49 break the lesson-level proposal line that rounds 41-47 kept.** `grep -cE 'considerthese|proposal' corpus/lessons/round-48.md` → `0` and `…/round-49.md` → `0` (exit 1 each), against `corpus/lessons/round-47.md:37`, `round-46.md:11`, `round-45.md:21`, `round-44.md:41`, `round-43.md:62`, `round-42.md:42`, `round-41.md:123`. The lesson is the durable record (wave dirs are pruned); the round-48 table's F6 predicted this and it happened again. Proposed fix: one line at the end of `## Claims` in every lesson: `considerthese: <day> proposal N → <artifact>; taken up by seat <id>` or `considerthese: none (reason)`.

**F3 — the proposal-19 running count stopped at round 47.** `tools/shortcut-tally.py:895` sets `--rounds` default `"40-47"`; the round-49 measured set calls it with no range (`W:measured/measure.sh:36`), so the receipt prints `rounds=40-47` (`W:measured/tally-build.out:2`) and its table ends at round `47` (`:5-20`). The round-49 SCORECARD draft then writes the limitation into the record as if it were the count: "`shortcut-tally.py` exit 0 over rounds 40–47" (`W:S9Scorecard/SCORECARD.round49.draft.md:2866`). So the proposal that asked "is counter design getting harder to fool, round over round" now cannot answer for the two rounds after its own promotion, and the round-48 shortcut tally (a 69-seat wave with 34 attack seats) is never tallied. Proposed fix: derive the default range from the highest `## Round N` heading present in `SCORECARD.md`/`.ufo/waves/round-*` instead of hardcoding it, keep `--rounds` for the selftest, and pass `--rounds 40-<N>` explicitly in `measure.sh`. Note the tool already fails closed on unreadable rounds (`:954`), so widening the range cannot silently pass.

**F4 — the proposal-16 instrument left the per-round regression set in round 48 and is absent from round 49's measured set.** `grep -c 'seat-yield' W:measured/measure.sh` → `0`; round 48's set has `.ufo/waves/round-48/measured/seat-yield-w1.out` (`wave=w1 seats=69 … reports=69 missing=0`). The SCORECARD regression sentences carry it in rounds 46 and 47 (`SCORECARD.md:2674`, `:2721`) and not in round 48 (`:2807`) or round 49 (`W:S9Scorecard/SCORECARD.round49.draft.md:2866`). KQ62 asks a *report* to use the tool (`corpus/QUALITY.md:377`), which is why it survives at report time, but nothing checks the tool against the wave directory in the measured set. Proposed fix: add `run yield python3 tools/seat-yield.py .ufo/waves/round-49/w1 --expect-reports 71` to `measure.sh`, or state in the SCORECARD section why it is excluded this round. Round 49's own wave directory is exactly the case the tool was built for (71 seats, and at the snapshot `W:w1/out/` had 51 seat directories for 71 seats).

**F5 — no closure has ever ruled this tracker or its products.** The round-47 closure admits the round (`corpus/lessons/round-47-verifier-spotcheck.md:12`) and the round-48 closure admits round 48 (`round-48-verifier-spotcheck.md:7`), but `grep -nE 'S8Considerthese|S8Proposals|X9Tally|considerthese|proposal|tally'` on the round-48 closure → exit 1, 0 hits, and the round-48 table's own F5 recorded the same for round 47. Consequence: rows 18-20 of this table can never leave "no verdict", so the tracker cannot calibrate itself — the one thing proposal 2 of 2026-10-26 (`considerthese/2026-10-26.md:31`) asks for. The mechanism exists in the round-46 closure, which did rule a proposal product (`corpus/lessons/round-46-verifier-spotcheck.md:13`). Proposed fix: each closure's routed list gains one line per frontier artifact it does not rule, in the form `F1 (frontier, not ruled): <artifact> — <why>` — the round-48 closure already writes `(orchestrator/operator, …)` labels, so the label vocabulary is in use.

**F6 — an orchestrator-owned defect is booked as a lane mistake in round 49.** `corpus/lessons/round-49.md:35` (Mistakes row 3) records the stale prompt route map, which the closure files as "**(orchestrator/operator, prompt route map)**" (`corpus/lessons/round-48-verifier-spotcheck.md:113`). The row is honest, but it makes the round's mistake count non-comparable with earlier rounds and hides the operator-side item from whoever tracks the fleet. This is proposal 4's cost, observed: rows `:33` (R2) and `:34` (R3) are lane-owned, `:35` is not, and nothing in the row says so.

**F7 — instruments are lost by prose, because nothing pins which instruments the measured set must run.** F3 and F4 are two instances of one defect: the lane's "in continuous use" claims for instrument-bearing proposals (rows 9, 13, 14, 15, 16, 19) live in SCORECARD prose, and `measure.sh` is hand-written per round, so a tool can drop out (seat-yield, rounds 48-49) or keep a frozen population (tally, rounds 48-49) without any check failing. Proposed fix: `registry/per-round-instruments.tsv` (`instrument`, `script`, `command`, `required_since_round`) and one leg in `gate-registry-check.py` that fails when a required instrument has no `run` line in the current round's `measure.sh`. Round 49 is the round to add it: its measured script has 19 runs and the gate already reads the registry (`W:measured/gate-build.out` → `registered 42 unregistered 2 defective 0`).

**F8 — the pin instrument watches a pin the round's own capability does not use.** Round 49's C1 replays and its witness all rest on llama.cpp **b11909**, but `registry/engine-pins.tsv:4` pins `llama.cpp … b11755 S038`; seat U2Pins recorded the consequence in the round-49 artifact: "**b11909 appears in no pin row**, so pin-watch cannot say anything about the dependency the witness replays rest on" (`W:w1/out/U2Pins.md:13`). Two smaller facts make the `behind` signal useless even for b11755: 135 tags sort above it and upstream publishes ~22-26 b-tags/day, so `status=behind` is permanent and `exit 1` cannot distinguish "docs drifted" from "replay inputs gone" (`U2Pins.md:14`). This is the first time a round's own claim creates a pin the pin table does not carry — a freshness defect introduced by an operability gain, and it is exactly what proposal 14's instrument exists to prevent. Proposed fix (U2Pins's own, `U2Pins.md:37`): add a distinct `llama.cpp-replay … b11909` row so the replay binary's `behind` count is measured separately, and wire the seat's `replay-inputs-probe.py` beside pin-watch so the signal is "replay inputs missing" rather than "newer tags exist".
