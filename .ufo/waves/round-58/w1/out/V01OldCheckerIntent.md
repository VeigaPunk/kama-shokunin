## LIMITS (out-of-set survivors; report only, no C1 credit, no predicate change)
1. **L1 harness-env guard.** N05 (`if os.environ.get("KAMA_R56_RUN_BATTERY") == "1":`) dies only because the harness does not set that name — the harness *does* set `PYTHONDONTWRITEBYTECODE=1`. The same no-op with flipped polarity (`!= "1" → return 0`) prints `met=True` exit 0, while a normal run (variable unset) skips the whole body. So C1's premise "a no-op harness cannot satisfy the counter" holds only for guards disagreeing with the harness env; the checker never neutralises its own environment.
2. **L2 verdict discarded.** `return 0 if all(results) else 1` → `return 0` still gives `met=True` exit 0: legs run, the battery can never fail. The checker grades leg invocation, not that the gate can go red. Not a regression (round-56/57 graded identically; round-56 `limits`: "C2 grades roster fidelity, not mutant quality"), but it bounds "executed": the harness returns canned `ld_audit=detected` for every subprocess, so leg outcomes are unobservable by construction.
3. **L3 rename false-reject.** A pure `run`→`leg` rename (behaviour identical; diff in `limit-diffs.out`) is rejected: `executed=0 legs=0/3 met=False` exit 1. The "3/3 behaviour-preserving rewrites" set is bounded to rewrites keeping the leg function named `run` — shared with the round-57 checker, hence pre-existing.
