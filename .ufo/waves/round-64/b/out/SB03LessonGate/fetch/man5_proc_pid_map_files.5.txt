7: NAME top
8: /proc/pid/map_files/ - memory-mapped files
9: DESCRIPTION top
10: /proc/pid/map_files/ (since Linux 3.3)
11: This subdirectory contains entries corresponding to memory-
12: mapped files (see mmap(2)). Entries are named by memory
13: region start and end address pair (expressed as hexadecimal
14: numbers), and are symbolic links to the mapped files
15: themselves. Here is an example, with the output wrapped
16: and reformatted to fit on an 80-column display:
17: # ls -l /proc/self/map_files/
18: lr-------- 1 root root 64 Apr 16 21:31
19: 3252e00000-3252e20000 -> /usr/lib64/ld-2.15.so
20: ...
21: Although these entries are present for memory regions that
22: were mapped with the MAP_FILE flag, the way anonymous
23: shared memory (regions created with the MAP_ANON |
24: MAP_SHARED flags) is implemented in Linux means that such
25: regions also appear on this directory. Here is an example
26: where the target file is the deleted /dev/zero one:
27: lrw------- 1 root root 64 Apr 16 21:33
28: 7fc075d2f000-7fc075e6f000 -> /dev/zero (deleted)
29: Permission to access this file is governed by a ptrace
30: access mode PTRACE_MODE_READ_FSCREDS check; see ptrace(2).
31: Until Linux 4.3, this directory appeared only if the
32: CONFIG_CHECKPOINT_RESTORE kernel configuration option was
33: enabled.
34: Capabilities are required to read the contents of the
35: symbolic links in this directory: before Linux 5.9, the
36: reading process requires CAP_SYS_ADMIN in the initial user
37: namespace; since Linux 5.9, the reading process must have
38: either CAP_SYS_ADMIN or CAP_CHECKPOINT_RESTORE in the
39: initial (i.e., root) user namespace.
