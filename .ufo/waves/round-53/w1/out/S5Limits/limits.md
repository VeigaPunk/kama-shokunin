# S5Limits — carried-limits table: round-50..52 C1 limits vs the round-53 build

Seat S5Limits, lane kama round 53 (w1). Claims frozen at `d01b2b6d48a54ffe0e475000737d3e302c62e28e`; build `c22602bd8d83ab26349d1087e916ca537ee4f9d1`; base `4229ea1b9a789148dded1f159c20967d9a01373f`.

Verdict: of the 13 distinct C1 limits carried in the round-50..52 SCORECARD "What `met=True` does not show" sections and the round-52 outside-closure spotcheck R2, the round-53 build **closes 6** (libraries-by-path, btrfs dev mismatch, recorded-URL freshness, and the three round-51/52 image-binding limits held closed), **narrows 2** (host-install memfd / unobserved download — now byte-verified everywhere but provenance still unobserved; model-by-path — libraries closed, model still path-bound), and **leaves 5** (vm.memfd_noexec=2, probe PATH execution, model-bytes-rewritten-after-mapping, kills during download/readiness, pid-join edges, prerelease cliff).

## Sources of the limits

- **Round 50** (`SCORECARD.md:2891`): the heading "### What `met=True` does not show (round-50 wave attacks)" is **empty** — round 50 filed no wave-attack C1 limits of its own. Its carried C1 limits sit in "Planned (round 51)" item 2 (`SCORECARD.md:2893`): pid-join edges, mapped-file rewrite-after-load indistinguishability, btrfs dev mismatch fail-closed, record-time fetching of the recorded URLs, the prerelease cliff. The round-50 verifier spotcheck (`corpus/lessons/round-50-verifier-spotcheck.md:119`, R6) adds: decoy in-place exec of the host binary (J4Decoy), probe PATH execution (Sen1Env), model bytes rewritten in place after mapping, counter `--out` parent creation.
- **Round 51** (`SCORECARD.md:2917-2921`): copy decoy at the member path meets (K1Cheat3, J3CopyDecoy); hardlink at the member path meets, replay refuses, frozen counter does not check (J4Hardlink); the download is not observed; separate dev/inode snapshots, counter stats the path rather than a held descriptor (K1Design3). Its "Planned (round 52)" (`SCORECARD.md:2924`) re-carries probe PATH execution, model rewrite-after-mapping, kills during download or readiness.
- **Round 52** (`SCORECARD.md:3013-3017`): the memfd's bytes are not observed to come from the downloaded archive — host byte-identical install meets (J5HostMemfd), and so would `--server`/foreign-passed memfd (K1Cheat, argued not run); the launcher is 17,864 B, the code lives in `libllama-server-impl.so` (7.9 MB) and `libggml*`, loading by path (K2Design); `vm.memfd_noexec=2` hosts cannot run the replay.
- **Round-52 outside closure R2** (`corpus/lessons/round-52-verifier-spotcheck.md:139-141`): memfd-from-host ("the next reference is a counter-owned extraction"); libraries and model load by path; download not observed; `vm.memfd_noexec=2`; plus round-50 carried: probe PATH execution, model bytes rewritten after mapping, kills during download or readiness.

## New round-53 limits that replace the closed ones (from the preregistration, for the next frontier)

- **L0** — bytes, not provenance: a host byte-identical install still meets (row 3).
- **L1** — host libraries (libc, libstdc++, libssl, ...) are only classed root-owned/not-writable; their bytes are compared with no reference (`:431-441`).
- **L2** — only executable mappings are compared; relocated data mappings and the model mapping are not (rows 1-2).
- **L3** — one memory read while the server is held; a rewrite after the read is not observed (row 6).
- Environmental: the counter now requires Yama `ptrace_scope` 0/1 for its own descendants (S507); `map_files` stays rejected (S508, EPERM without `CAP_SYS_ADMIN`/`CAP_CHECKPOINT_RESTORE`).

## Observations (not limit dispositions)

- Two preregistered C1 controls have **no committed counter-run receipt** in the wave output as of this writing: J5Preload (LD_PRELOAD of a user-owned `libggml-rpc.so` copy — each seat directory holds only `control.patch`) and J6HostMemfd (host-filled memfd probe — only `probe.patch`). The counter would reject the LD_PRELOAD mapping (a user-owned executable mapping outside the unpacked tree fails the root-owned test, `:431-441`), and L0 already concedes the host-memfd case, but the ablation receipts that would demonstrate both at the build are not in `.ufo/waves/round-53/{w1/out,measured,controls}/`. Seats may still land them; this is a point-in-time observation.
- J1SwapChecked's receipt reads `bind=0` (the swapped tree was refused by the replay itself, "replay exit 1 match False"), so it is not a clean counter-side kill; J2SwapUnchecked (lying `verify_code`) is the run that exercises the counter's own memory read, and it does: `code: mapped bytes ... of llama-b11909/libggml-rpc.so differ from the archive member`.
