## 5. Answer to the question as posed

"v4 keeps the JSON schema string, so the round-48 counter should still meet" — **that inference does not hold.** The round-48 counter never reads a definition marker; it compares the tool's numbers field-by-field against its own frozen v3 recomputation (`graded`, `ungraded`, `restored_max`, `held_at_to`, `summary.ungraded_lines`). Keeping `"schema": "append-only-audit/v3"` and adding `"definition": "v4"` leaves an unknown key that the counter silently ignores, so the only way a v4 tip can keep that leg green is to keep v3's grading on the lane — the exact opposite of the C2 claim ("v4 grades 7 more lines; ungraded 72→65"). **The round-48 lane leg and the round-49 C2 claim are mutually exclusive by construction.** Nothing to fix in the frozen counter or in v4; the honest record is a supersession note.

Suggested integration action (for L1 / the scribe; not applied by me, and it needs no lane-file edit beyond the round-49 lesson/LOG text that integration already writes): in the round-49 lesson or LOG entry, state that the round-48 C1 counter's `lane` leg is superseded at v4 tips — naming the event, the four fields and the seven-origin cause, citing `verdict.json` here — so a later reader does not treat `met=False` at a v4 tip as a live loss. If instead a prior-counter-green gate is mandatory, the only other admissible path is to stop calling the round-48 counter's `lane` leg an assertion (it is a frozen recomputation of a superseded definition) — a decision for L1/operator, not a counter edit.
