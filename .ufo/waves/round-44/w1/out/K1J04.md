## The counterexample I built and rejected (S036)

The obvious false-comfort target is the release's *new route class*: b11889 adds `ctx_http.ws("/v1/realtime", …)` (`tools/server/server.cpp:189`, commit `1242be66f server: add realtime transcription API (#30636)`), and the vendored httplib routes upgrades through `routing(req, res, strm, is_upgrade)` — pre-routing **skipped** when `is_upgrade` (`vendor/cpp-httplib/httplib.cpp:10459`, `:9799`). If that were the whole path, S036's "every non-frontend path … answers 503" would have been falsified by a WebSocket route that never met `middleware_server_state`.

It is not. The same release's httplib runs the pre-routing handler *before* matching websocket handlers:

```
vendor/cpp-httplib/httplib.cpp:10350-10364
10351  // Run pre_routing_handler_ and pre_request_handler_ before upgrading so
10352  // that authentication and other middleware can reject the request with an
10358  auto is_upgrade = detail::is_websocket_upgrade(req);
10359  if (is_upgrade) {
10360    if (pre_routing_handler_ &&
10361        pre_routing_handler_(req, res) == HandlerResponse::Handled) {
10362      if (res.status == -1) { res.status = StatusCode::OK_200; }
10363      return write_response_with_content(strm, close_after_response, req, res);
```

`skip_pre_routing = is_upgrade` at 10459/10462 only avoids a *second* invocation. Middlewares are installed per listener (`server-http.cpp:139-148` → `init_listener`), and `ws()` broadcasts to all of them (`server-http.cpp:793-795`), so no listener is left ungated. A `/v1/realtime` upgrade while `is_ready == false` therefore gets the 503 body, before the API-key check. S036 holds; the near-miss is recorded here so the lane does not have to re-derive it.
