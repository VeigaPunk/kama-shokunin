### F2 (receipt format) — `tip=` cannot identify a tree

8 of the 9 committed sets record fixture commit SHAs that no replay can reproduce (no pinned committer date), and none of those objects survive in the lane clone:

```
$ git -C "$S/clone" cat-file -t b92ad324b52e251e41cea0c3449c3e24028c6119
fatal: git cat-file: could not get object info      (same for 2541e226…, 279ed0d3…)
```

So a replayer comparing only the receipt cannot distinguish "same tree" from "different tree" — the one field that would prove it is unusable. This seat had to establish tree identity out of band (`R42D06/trees.tsv`: 8/8 trees equal across two runs).

**Proposed fix:** pin the fixture clock, e.g. `ID = ["-c","user.name=r42-control","-c","user.email=r42-control@fixture.invalid","-c","gc.auto=0"]` plus `env GIT_AUTHOR_DATE=GIT_COMMITTER_DATE=2026-10-25T00:00:00+0000` around the commit call (`build_controls.py:20`, `:24-27`), which makes every stand-in SHA stable and the `tip=` line checkable. Alternative, if the frozen receipt format must not change: print `tree=<sha>` alongside `tip=` in a future round.

### F3 (nondeterminism) — the c2 `hygiene` detail line can never replay byte-exactly

Nine of nine `c2` receipts differ across replays in exactly that line (`build_controls.py` §2.1 diff). The leg value and count are stable; the names are `mkdtemp` suffixes from the round-41 counters (`tools/round41-scorecard-reconcile.py:184`, `tools/round41-pinwatch-audit.py`). **Proposed fix:** report the count and the prefixes only (`['r41c1-*', 'r41c2-*']`) or omit the names from the receipt and keep them in the counter's stdout.

### F4 (operability, in the builder) — 259 MB leaked per `c1` invocation into the ambient TMPDIR

After the two full replays my private `TMPDIR` held 19 export directories totalling 4.8 GB:

```
$ du -sh "$S/tmp" ; du -sh "$S/tmp"/* | head -3
4.8G	/fast/scratch/kama-r42/seats/R42D06/tmp
259M	/fast/scratch/kama-r42/seats/R42D06/tmp/r41c1-2zpngxk7
259M	…/r41c1-79bjo5nl
$ ls -A "$S/tmp" | sed 's/-.*//' | sort | uniq -c
     19 r41c1
```

Cause: `score()` (`build_controls.py:36-46`) runs the counters with the caller's environment, and the `c1` counter imports the **base/freeze** `tools/round41-scorecard-reconcile.py` unchanged (`tools/round42-selfdesc-reconcile.py:130-131,157`), whose export is `tempfile.mkdtemp(prefix="r41c1-")` with no removal (`tools/round41-scorecard-reconcile.py:184`). That is the defect round 42 repairs — so reproducing it is correct — but the builder does not contain it. The rate is exactly one export per `c1` invocation, measured in isolation:

```
$ rm -rf "$S/tmp3" && mkdir -p "$S/tmp3"
$ TMPDIR="$S/tmp3" python3 tools/round42-selfdesc-reconcile.py --repo "$S/clone" \
      --tip 0b606b03… --out "$S/tmp3/one.out"
$ ls -A "$S/tmp3"; du -sh "$S/tmp3"/r41c1-*
log  one.out  r41c1-f1_aig7p
259M	/fast/scratch/kama-r42/seats/R42D06/tmp3/r41c1-f1_aig7p
```

19 directories remain, which is exactly the count of leak-producing `c1` runs: 18 from the two builder replays (9 sets × 2) plus the one direct `c1` run I made at the real freeze commit. The `c1` run at the claim tip leaks nothing, because the round-41 counter there removes its export — `tools/round41-scorecard-reconcile.py:187` (`atexit.register(shutil.rmtree, export, True)`, present at `3d9bd8d`, absent at `0bfd47a`), which is the repair C2 claims. Full log: `R42D06/hygiene-leak.txt`.

This is the same `/tmp`-exhaustion hazard `corpus/lessons/round-42.md:49` (KQ51) names, and `build_controls.py` is the tool most likely to be re-run by later seats. **Proposed fix:** in `score()`, create `<D>/tmp` and pass `env=dict(os.environ, TMPDIR=os.path.join(D,"tmp"))`, then `shutil.rmtree` it with the sandbox; and state in the docstring that the builder owns its temp root.

### F5 (control coverage) — the `hygiene` leg is never positive inside this builder

All nine sets score `hygiene=0`; a counter hard-coding `hygiene=0` would pass every control in this family. The positive instance is only the claim receipt (`.ufo/waves/round-42/c2/candidate.out`, `hygiene=1`), which I reproduced independently (§4b), so the leg is two-sided across the round's evidence — but not inside the frozen control set. **Proposed fix (next round):** add a control that drops the two fixed round-41 counters into the freeze stand-in and shows `hygiene` flips 0 → 1 while `met` stays False.

### F6 (latent, code-read — not exercised) — receipts are opened in append mode

`build_controls.py:45` opens the receipt with `"a"`. A replay into an out dir that already holds receipts appends a second summary and a second `exit=` line instead of failing, producing a receipt that still parses; and a counter that dies before writing `--out` leaves a file containing only `exit=`. I did not exercise this (both replays used fresh out dirs) — it is a reading of the code, offered as `[INFERENCE]`. **Proposed fix:** open `"w"`, and after each run assert the receipt's first line starts with `tip=`.

### F7 (naming, no fix needed for this round) — `freeze.*.out` scores a stand-in, not `0bfd47a`

The `freeze` fixture tree is base + three counters (`bee18df6…`); the frozen commit's tree is `79e5365b…` and carries 32 further evidence files. The preregistration's `do_nothing_control` names `freeze.*.out` without saying so. §4a shows the numbers are identical at the real commit, so the control stands; a one-line note in the preregistration or a rename to `freeze-standin.*` would keep a reader from assuming otherwise.

- No tool was installed or upgraded; `pacman` was not run (host-wide pause respected). Python is the host `python3` (3.14); the counters need no third-party package.
