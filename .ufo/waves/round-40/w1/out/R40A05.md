## 3. Finding F1 (defect candidate, pre-mutation): counter reads the status column, not teaches

`registry_rows` stores `cell[1:]` (id at index 0), so teaches is index **6** and status
is index **7**; the code does `teaches = s474[7]` — the status cell. Discriminating runs:

```
pristine × FX-contract : s474_row=0 amend_corrected=1 r36d2c_fixed=1 false_corrections=0 met=False  exit=1
pristine × FX-counter  : s474_row=1 amend_corrected=1 r36d2c_fixed=1 false_corrections=0 met=True   exit=0
```

A fix authored per the table schema (supersedes text + digest in teaches) never flips
`s474_row`, so per the kill rule ("met flips False -> True") the frozen counting
command cannot certify a genuine, schema-faithful C1 fix. Same off-by-one applies to
the `false_corrections` row loop (`row[7]`): a fake "supersedes S472" planted in a
teaches cell would not be counted. Grounded in code read + the two runs above;
integrator's call (frozen counter, not mine to edit).
