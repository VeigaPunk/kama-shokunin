## Findings

**F1 (provenance, frozen evidence).** The base and freeze receipts record
`tip=4dc17978e184d5474f6b0ff3f3d9af608e06aac3`, which the lane remote does not contain
(E5); by construction it is the throwaway clone commit deleted by
`.ufo/waves/round-43/controls/build_controls.py` (`fresh()` → `commit(d)` → `shutil.rmtree(d)`).
The claim's kill rule ("At base mismatches=42 (controls/base.c1.out)") therefore rests on a
tip nobody can resolve, and because the commit timestamp is not pinned the hash cannot be
reproduced by re-running the builder either.
*Proposed fix:* have `build_controls.py` copy the created tip into a durable branch
(e.g. `refs/heads/control-r43-base`) inside the lane clone, or record `--base` + the control
recipe in the receipt so the scorer can rebuild and compare the summary line rather than the hash.

**F2 (portability, counter code).** `tools/round43-health-audit.py:88` hardcodes
`CENSUS = "/home/vgpnk/Projects/shokunin/scripts/sources-census.sh"`, an absolute fleet-root
path, and at `:279-286` a missing script only yields `census=0` plus a detail line instead of
exiting 2. So C3's sixth leg grades the host's layout, and on a host without that file the
counter reports a claim miss (`met=False`) rather than "could not evaluate".
*Proposed fix:* add `--census PATH` (default: `$SHOKUNIN_ROOT/scripts/sources-census.sh` or a
repo-relative copy) and return 2 when the script is absent.

**F3 (C1 baseline, outside this slice).** At the freeze tree the C1 facts that other seats own
are still failing: `unreg=16` (round-35..42 counters unregistered), `selftest=1`
(SKILL.md:1325 documents `GATE_SELFTEST pass=6 fail=0`, the gate run prints
`pass=5 fail=1`), `dc=1` (no correction line after the round-42 search-log entry),
`spot=1` (SCORECARD states 28, tree holds 29), `hidden=2` (README names neither `.gitignore`
nor `.ufo`). Reported, not touched.

**F4 (constraint for everyone writing SKILL.md rows this round).** SKILL.md is a root `.md`
inside the hexrun census population (`.ufo/` excluded), so any 32–127-hex run written into a
registry row — in particular an `--out` receipt's `tip=` hash or a full git oid — becomes an
unexplained census token and would break C2's `live` leg (`unknown=0`). My rows carry only
12-hex sha256 prefixes for that reason (E9).
