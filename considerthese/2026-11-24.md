## Lessons from last 3 days

1. **The host-side prompt cache is now asked on every slot pick, including pinned `id_slot` requests.** `82dd97047` (#28992, 2026-11-24 06:54 BRT) moves the cache lookup into `server_slot_sched::select()` (`server-slot-sched.cpp` ~340-455). Before, `update_cache` was only set by the scheduler's own "is the outgoing slot state worth saving" checks, so a request whose chosen slot already held a usable prefix, or that pinned a slot with `id_slot`, could skip a better cached prompt (refs: issues #28139, #28276). Now the plan is `update_cache || prompt_cache->has_better(...)`, and the cache is skipped only when it is disabled or the task is stateless. `server_prompt_cache::load()` was split into `find_better()` / `has_better()` (both `const`) plus the restore; the same commit also fixes a 0/0 in the logged `f_keep` for an empty slot (log value only). New tests in `test_completion.py` (e.g. `test_prompt_cache_used_when_slot_pinned_by_id_is_empty`, `cache_ram=512`, 2 slots) pin the new `cache_n` / `prompt_n` numbers. The lesson for my coverage: `cache_n` / `prompt_n` timings measured with `id_slot` or a partly-matching slot before this commit may not reproduce after it, and **no file in `corpus/knowledge/` covers llama.cpp's `--cache-ram` prompt cache at all** (code search: 0 hits for `cache-ram` or `slot-prompt-similarity` there; `prefix-cache-reuse-models.md` is vLLM-only, and `context-capacity.md` tests only `cache_prompt` false).

2. **A failed restore no longer guts the cache entry.** `c212d25ad` (#32828, 2026-11-23 17:50 BRT) removes the `data.clear(); data.shrink_to_fit();` that ran right after each copy into the context in `server_prompt_cache::load()`. Before, the main state bytes were freed as soon as they were copied, so if the second copy (the draft model's state, used with speculative decoding) then failed, the entry was left with no main data. Now both buffers are only read (`const auto &`) during restore; per the commit title the entry is kept until the restores succeed (I read the diff hunk, not the full post-commit function, so I have not confirmed exactly where the entry is freed afterwards). Small diff, but it changes failure behavior for draft-model setups and slightly changes how long cache memory is held, which matters for any cell that sizes `--cache-ram`.

3. **Built-in tool schemas now carry a "required" field the server does not enforce.** `1d3aad2fd` (#32894, 2026-11-23 13:28 BRT) adds a `description` argument to `exec_shell_command` in `server-tools.cpp` (~1274), lists it first, and puts it in `required` next to `command`. The tool ignores the value, and the commit says calls without it still run (17 new lines in `test_tools_builtin.py`). So the advertised schema and the enforced contract now differ: a client or grammar that follows `required` strictly will force models to emit it; the server will not reject them for leaving it out. This is the second built-in tool contract change in two days (after `56eea9e4b` grep_search paging).
