## Review boundary

Author and parent-dispatched advisor agreement are not an outside spot-check.
`lessons/round-5.md` records the missing non-author admit/reject review; no
criterion or local gate pass certifies promotion, native judgment, or a
completed training round.

## Criteria added — round 13 (2026-10-20; outside review: `lessons/round-12-verifier-spotcheck.md` D1 routed defect 1)

KQ16 supersedes only KQ15's two inaccurate formulations (exit-class and
capture/comparison) and preserves every other KQ15 clause, including KQ14's
semantic-human boundary and the boundaries listed below. This row adds no
admission method; it corrects how the existing method is named and how its
failure classes are reported.

| ID | Admit only when | Reject or limit when | Motivating lesson |
|---|---|---|---|
| KQ16 | The capture of a frozen historical copy is author-recorded provenance (S032), declared as `git show <pinned-commit>:<source-path>`; the committed comparison code corroborates only the independent comparison — a separate byte-identity read of the same pinned blob through `git cat-file blob <pinned-commit>:<source-path>`, checked against the code-pinned revision, path, OID and digest rather than treated as a second source or separate provenance authority — not which command created the frozen file: `capture: git show; comparison: git cat-file blob`. Source correspondence is reported separately from SHA-256 digest integrity against a pinned manifest naming the snapshot hash, source commit and source path, and the clean verdict requires both. Finding IDs are stable and distinct even when exit classes are shared; the exit is that of the selected primary finding under the code's `PRIORITY` order: `source_mismatch=1; snapshot_tampered=2; source_unavailable=2`. Thus `source_mismatch` yields exit 1 only when it is the selected primary finding and no higher-precedence could-not-evaluate finding is present; `snapshot_tampered` and `source_unavailable` share exit 2 and are distinguished by ID, the other declared could-not-evaluate findings (`snapshot_unavailable`, `manifest_invalid`, `unpinned`, `internal_error`) also exit 2, and a listed lower-precedence ID does not by itself imply that ID's exit. A byte mismatch that co-occurs with a higher-precedence finding exits 2, while the correspondence count still records the mismatch only when the pinned anchor is verified; an unavailable anchor counts zero mismatches. An overridden snapshot without its manifest can never authorize a pass: a byte mismatch is exposed as `source_mismatch`, while a matching unpinned snapshot remains a could-not-evaluate finding with exit 2, not clean. Corrections land as a new dated snapshot plus its own manifest, leaving the old frozen receipt byte-intact and appending an erratum that names it. | A matching digest against a shipped expected file, a green `--selftest`, a size/line count, or a pager/artifact-rendered copy (for example a truncated tail carrying an `artifact://` marker) is offered as correspondence with git history; a correction rewrites the old frozen bytes or manifest so the mismatch is only restated; the declared `git show` capture is offered as its own independent comparison, as command-verified provenance, or as reproducible from the committed comparison code, a same-repository read is offered as independent provenance authority, `snapshot_tampered` and `source_unavailable` are collapsed into one finding, or distinct IDs are treated as requiring different exit codes. The quoted audit phrases are documentation anchors, not semantic proof, and a textual gate does not establish semantic admission; KQ14 still governs, and no correspondence or digest result alone proves the historical claim's content. | `lessons/round-12-verifier-spotcheck.md` §Routed defects item 1 (D1: finding IDs versus exit classes; capture versus comparison); `lessons/round-12.md` capture/comparison wording; `lessons/round-13.md` Mistakes; method sources `SOURCES.md` S032 (`git show` capture) and S033 (`git cat-file` comparison), which establish neither independence nor a measured outcome. |
