## Answer
At llama.cpp commit `704366d76f8748cf9ad3df62a464bfcc8d1ae6ad` (release b11755), single-model `GET /props` sets `default_generation_settings.n_ctx` from `meta.slot_n_ctx`; `total_slots` is `params.n_parallel` (`tools/server/server-context.cpp:5229-5245`). `slot_n_ctx()` returns the sequence context, limited by positive `--kv-unified-per-slot` if supplied, and then by `llama_model_n_ctx_train(model_tgt)` (`server-context.cpp:4654-4663`). Thus `/props` is **per-slot effective context**, not the training context and not an unconditional `--ctx-size / --parallel` quotient.

The sequence context depends on KV layout (`src/llama-context.cpp:219,377-393`): `n_ctx` starts from explicit context size, or training context when zero, then rounds up to 256. Unified KV makes `n_ctx_seq = n_ctx`; split KV uses `GGML_PAD(n_ctx / n_seq_max, 256)` (and adjusts total `n_ctx` if needed). `server.cpp:169-174` resolves server auto parallel to four slots and `kv_unified=true`; `common/arg.cpp:1405-1406` sets the server default to auto. Under that default, 4 slots each report the unified context (bounded as above), not one quarter of it. Split mode can also round a small quotient up: `-c 256 --parallel 4` without unified KV yields slot context 256, not 64. The receipt's 256 alone therefore does not prove the KV layout; its absent `--parallel` plus the source default resolves the launch as auto/unified.

Training context is a separate `/v1/models` field: `data[0].meta.n_ctx_train` is populated from `meta.model_n_ctx_train`; the same `meta` object also has `n_ctx = meta.slot_n_ctx` (`server-context.cpp:4847-4849,5183-5188`, route registrations at `server.cpp:281-284`). The loaded training value is read from GGUF `LLM_KV_CONTEXT_LENGTH` (`src/llama-model.cpp:1382`; arch key format `%s.context_length`, `src/llama-arch.cpp:203`). It can reflect load-time override or custom YaRN adjustment rather than untouched GGUF metadata (`src/llama-model-loader.cpp:421-427`; `src/llama-context.cpp:4114-4117`). `/props` does not expose `n_ctx_train`.
