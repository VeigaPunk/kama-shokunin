## Findings

### F1 — S047: `holds` over ranges that are line-number coincidences in another file (major, false provenance)

The anchor cell cites `server.cpp` `signal_handler` 29-38 (statics 26-27), handler install 529-534,
`start_loop` call 575-576 and `return 0;` 590, while the population path is
`tools/server/server-queue.cpp`. The draft satisfies the counter's cited-line rule with queue.cpp
ranges chosen for their *numbers*, not their content:

```
# pin server-queue.cpp
26: }                    27: (blank)            28: int server_queue::post(server_task && task, bool front) {
29: std::unique_lock<std::mutex> lock(mutex_tasks);   <-- NOT signal_handler
...
529: size_t index = 0;      <-- loop inside server_response_reader::post_tasks, NOT sigaction
530: for (auto & task : tasks) {
...
575: }   576: (blank)   577: // should not reach here    <-- NOT the start_loop() call
```

Command: `git -C $U show 704366d76:tools/server/server-queue.cpp | sed -n '24,38p;525,540p;573,580p'`
(receipt: `w1/out/K1J08/evidence.txt` §"S047 EVIDENCE DEFECT", lines 130-201). The parser confirms
the coercion: `cited()` yields `STRONG={26,27,29..38,132..136,141..143,278..280,529..534,575,576}`
and `WEAK={590}`, and `cited()` never associates a number with the filename token preceding it.

The statement itself is still true at b11889 — I verified it out of band:
`signal_handler`/`is_terminating` byte-identical (`server.cpp:26-38`), the same sigaction block now in
`server_install_signal_handlers()` (`318-332`), called at `651-653` *after* `shutdown_handler` is set
(`645-649`) and *before* `ctx_server.start_loop()` (`671`), with `return 0` at `684`; the queue still
clears `running` in `terminate()` (`132-136`), sets it in `start_loop()` (`278-280`) and bails in
`process_new_tasks()` (`141-143`), so a SIGTERM inside 652..671 is still lost and a second one exits 1
(`server.cpp:34`). Also note the file's only b11889 change, `recv_with_timeout` at `448-467`
(`git diff 704366d76 d854d98b -- tools/server/server-queue.cpp`), intersects none of the row's ranges:
`changed=1` is caused by code the row never cites.

- Smallest safe correction **this round** (the row is VALID and its statement is true, so do not
  change the verdict): make the round-44 SOURCES-section note for S047 say that the ledger evidence
  is queue-side only and that the `server.cpp` window was verified out of band at release
  `645-653`/`670-684`, so no later reader treats `529-534`/`575-577` as signal-path evidence.
- Next round (counter and registry are frozen; a finding, not an edit): in `cited()`, capture the
  file qualifier before a number or range (`<name>.<ext>`), and drop numbers whose qualifier is not
  the row's `path`; then a cross-file row cannot reach `holds` on unrelated bytes and must be
  `holds-reworded` with the support file and lines in the note. Alternatively give the ledger an
  optional `support_path`/`support_lines` pair, or split S047 into a `server.cpp` row.
- If instead someone keeps the row as-is **and** claims its ranges prove the race window, that is a
  false-provenance defect, not a tradeoff: the cited queue lines are unreachable from the claim.

### F2 — S117/S125: the guard is cited only in the teaches cell, which the counter never parses (medium)

`cited()` builds its text from `c[1] + " " + c[5]` (title/source + anchor), not from `c[4]`
(teaches). For S117 the guard `server-context.cpp:5452-5454` and for S125 `5651-5657` appear only in
the teaches cell, so `STRONG` collapses to `{5453}` and `{5655}` and a one-line row passes
(`w1/out/K1J08/cited-decomposition.txt`). A seat could therefore delete the guard at the release and
the row would still be `holds` — exactly the "guard changed around unchanged text" hole this claim

### F3 — new transcription entry point at b11889 not covered by S125 (minor, observation)

`server.cpp:189` adds `ctx_http.ws("/v1/realtime", routes.ws_realtime)` (commit `1242be66f`), and its
guard is different: `if (!meta->has_audio_stream)` → "The current model does not support realtime
transcription." (`server-context.cpp:6021-6025`). This does not falsify S125, whose `teaches` is
scoped to the HTTP transcription handler, but the lane's E26-12 signature now has a second entry
point with a different guard and message; `SKILL.md`/`registry/error-signatures-r26.json` should say
so or say explicitly that they cover only `/v1/audio/transcriptions`.

### F4 — no drift found in the four `schema.cpp` rows, and that is not an accident

`git diff 704366d76 d854d98b -- tools/server/server-schema.cpp` is additions only (an `#include`
that shifts every line by +2, the `dry_sequence_breakers` dedupe, the TTS schema), so the `n_keep`,
`xtc_probability`, `mirostat` and `lora` rows survive a release bump whose headline features are two
new endpoints. That is a property of this release, not of the claim: the rows' protection comes from
`field_num::eval` (603-622) and `to_json` (server-task.cpp), which the rows do not cite. Worth noting
for the next bump, since `+2` uniform shifts are the archetype of a `holds` that carries no
information.
