# W1R02 — do-nothing-control attack on C2 and C3 (round 43, wave 1)

**Verdict:** both frozen counters accept a do-nothing shell. C2 prints `met=True` for a 78-line tool that never opens a document and never reads a ledger (the contract leg is answered by fixture *directory name*, the live leg by importing the counter's own `own_census`), and C3 prints `met=True` for a keyword-shell entry backed by 95-byte and 64-byte stub "API copies" — anchors hash the stubs themselves — with two Gate quotes that are true and live but say nothing about the claim. Neither shortcut is covered by either preregistered `out_of_counter_limit` note. Both are fixable in the counters without touching the frozen claims.

Counters scored: `tools/round43-hexrun-audit.py` sha256 `a455ba55…bd37b8` and `tools/round43-health-audit.py` sha256 `aa293a25…d0423b`, byte-identical at freeze `895793e0b4c56bdcb939277b8ff0251b26306d4d` (`git show 895793e:tools/… | sha256sum`; the shared clone's HEAD has since moved to `1af8d516` by another seat, but `git diff 895793e HEAD --stat` shows only the three C3 copy files, and the two counters hash the same as at freeze).

## 1. C2 — the cheapest tool that passes all twelve fixtures and the live leg

Sandbox `c2` = freeze + `tools/hexrun-census.py` (deliverable `cheat-hexrun-census.py`) + a round-43 canonical capabilities table (the round-42 rows verbatim plus one `hexrun-census` row). No `registry/hexrun-ledger.tsv` is created: `git -C c2 ls-tree -r --name-only HEAD | grep -c hexrun-ledger` → `0`. Diff: 2 files, 92 insertions (`sandbox-diffs.patch`).

Seed 7, same result (`attack-c2-seed7.out`): the contract expectations are constants of the fixture construction, so seed randomisation is irrelevant to the cheat.

How it passes without classifying:

- **contract (12/12).** `evaluate()` builds each dir fixture as `mk(f"case-{name}-", export)` (`round43-hexrun-audit.py:335`) and the git fixture as `mk("r43c2-git-")` (`:288`), then runs the tool with `cwd=export` (`:174-175`). The tool's contract branch is 10 lines: match the basename against the eleven frozen names and print the frozen line (`cheat-hexrun-census.py:28,56`). Direct proof that no content is read — a directory of that name containing only `random.txt`:

```
$ mkdir demo/case-md5-blob-ZZZZ; printf 'nothing here\n' > demo/case-md5-blob-ZZZZ/random.txt
$ python3 c2/tools/hexrun-census.py scan --dir $PWD/demo/case-md5-blob-ZZZZ

exit=0
$ python3 c2/tools/hexrun-census.py scan --dir $PWD/demo/case-duplicate-token-counts-once-QQQQ   # empty dir
tokens=2 distinct=1 lane_oid=0 md5_blob=0 upstream_ok=0 unverifiable=0 wrong_flagged=0 ledger_bad=0 unknown=1
exit=1
```

- **live.** `evaluate()` extracts the whole tip into `export` (`:326`), which contains the counter itself, and runs the tool from there (`:355`). The tool imports `tools/round43-hexrun-audit.py` and calls `own_census(repo, rev)` (`cheat-hexrun-census.py:66,69`), then reports `upstream_ok = distinct − lane_oid − md5_blob` (73) with `unknown=0, ledger_bad=0`. The live leg's only assertions are aggregate equality plus `upstream_ok>=40` and `unverifiable+wrong_flagged<=25` (`:353-362`) — exactly the numbers the import returns.
- **capability.** A byte-for-byte copy of the round-42 canonical table (so `observed ⊆ listed` for `capability-repertoire-audit.py`) plus the `hexrun-census` row satisfies `:381-383`. The frozen `junk-c2-stub` control failed `capability` only because it appended a one-row round-43 table, which makes every earlier capability "missing".

So the contract leg is a *shape* test, and the shape is handed to the tool. The stub's failure is one `if base.startswith(...)` away from success.

The other shortcut named in my brief — an `upstream` ledger row whose evidence is a copy of the citing document — is even cheaper than what I ran: the frozen semantics define `upstream_ok` only as "`evidence` is a path of a blob at REV … whose bytes contain the token and the `repo` cell text" (`round43-hexrun-audit.py:27-29`), so a document that cites the token and names the repo is its own valid evidence; and the live leg never opens the ledger at all. My sandbox proves the stronger version: **no ledger file exists anywhere in the tree and `live=1`.** The preregistration's C2 note concedes only that the counter "cannot prove the evidence files were fetched from the stated upstream"; it does not concede that `upstream_ok` need not come from a ledger, nor that fixture identity is visible.

## 3. C3 — the do-nothing shell that the counter accepts

Sandbox `c3` = freeze + entry + two registry rows + two stub copies + lesson + scratch/guard + one README line (11 files, 28 insertions; `sandbox-diffs.patch`).

```
$ TMPDIR=…/tmp python3 /fast/scratch/kama-r43/clone/tools/round43-health-audit.py \
    --repo …/c3 --tip 72c9a5efc3844bc63647947c2dba4a272ecfe07f \
    --base 6897ead55c24ba08c9ac0b09466d4fbfe005a459 --out ev/attack-c3.out
tip=72c9a5efc3844bc63647947c2dba4a272ecfe07f
entry=1 rows=1 coverage=1 gate=1 refetch=1 census=1 met=True
exit=0
```

The four substitutions that make it a shell:

1. **Entry asserts nothing.** First three non-blank lines are `source: S480, S481` / `verified-at: 2026-10-25` / `recheck: on-release`; the body is the keyword list itself: "weight cache daemon, vllm preload, #58552, starting, ready, failed, S004, different process". The entry leg is a substring test over eight keywords (`round43-health-audit.py:200`) plus the provenance trio (the source line must name both ids) — nothing checks a statement. This is the preregistered, declared limit ("entry's prose is checked by keyword, not read"), shown here at its full extent.
2. **Two rows whose anchors hash stubs.** `.ufo/waves/round-43/c3/vllm-v0.31.0-release.json` is 95 bytes and `.ufo/…/vllm-pr-58552.json` is 64 bytes; neither contains `health`, `58552`, `daemon`, `weight cache` or `preload` (`live-quote-check.txt`; real live bodies are 60,454 and 25,514 bytes). The rows pass `rows=1` because the anchor check is `sha256(committed bytes) in anchor cell` (`:182-183`) — a self-hash of whatever the claimant committed, while the docstring calls the file "a committed API copy" (`:131`) and the predicate says "the SHA-256 of a committed API copy". Nothing compares the copy's `tag_name`/`number`/`html_url` to the upstream object, so a stub is indistinguishable from a fetch.
3. **Gate quotes that are true but irrelevant.** `gate` accepts any `"…"` span of ≤25 words that norm-occurs in the *copy* (`:233-238`); `refetch` only requires the accepted quotes and the frozen quotes to occur live (`:270-272`). I used `"This release features 717 commits from 307 contributors (96 new)!"` (10 words, live release body) and `"Will rebase once #58370 is merged."` (6 words, live PR body) — both verified against the `gh api` objects (`live-quote-check.txt`). `gate=1 refetch=1` while the lesson's Gate lines carry zero claim-bearing text.
4. **Scratch scaffolding is presence-only.** `quarantine-slice` is one sentence, `collisions` empty, `guard/proof` is `guard placeholder`.

## 6. Limits of this attack

- I scored the frozen counters only; no counter, preregistration or control was edited. Everything else lives in my sandboxes (removed after this report) and the deliverable directory.
- The live legs depend on `gh api` (2 requests, read-only): `repos/vllm-project/vllm/releases/tags/v0.31.0` and `…/pulls/58552`, both exit 0 at 2026-10-25; bodies saved only as the quote-containment receipt, not re-hosted.
- A tool may still game D1 by content-shape detection after the naming fix; that costs roughly the same as implementing the classification, which is the intended bar. No installs were needed (no pacman, uv, npx or cargo), so there is no tool-version entry to record.
