- Added `build/out/GgufReconcile/gguf_receipt_reconcile.py` (10,156 B); no lane source/index/git state changed.
- `reconcile_receipt(gguf_metadata, file_sha256, receipt)` accepts the flat decoded GGUF metadata mapping plus the caller's hash of the exact opened file. It requires the exact `kama-llamacpp-live/v3` schema and binds identity only by `model_sha256_post`; an unequal valid digest returns `status: identity-mismatch`, exit 1. It never substitutes the receipt's pre-launch `model.sha256` or alias for this binding.
- Returns context facts separately: `<architecture>.context_length`, props `default_generation_settings.n_ctx`, receipt `ctx`, and props `total_slots`. Classification is based on served `n_ctx` versus training context (`<=` → `within`; `>` → `exceeds-train`). The latter carries a warning and still exits 0; neither `ctx` nor `total_slots` is multiplied/divided into that comparison.
- Reports captured `model_alias` against GGUF `general.name` as `equal`/`different`/`unavailable`; `comparison_is_verdict` is always false. Alias differences cannot change exit status.
- `run_receipt_reconciliation(..., receipt_path)` handles receipt loading/JSON output. Exit map: 0 reconciled (warning allowed), 1 identity mismatch, 2 unreadable/invalid/non-v3 receipt or unusable required fields. `run_selftest()` contains eight in-memory v3 receipt cases: pre/post hash counterpair, alias mismatch, within/exceeds/boundary contexts, slot multiply/divide counterpairs, non-v3 schema, and missing served n_ctx.
