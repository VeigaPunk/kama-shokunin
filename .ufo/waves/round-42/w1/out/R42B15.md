# R42B15 — C2 novelty and overlap attack: `digest-ledger.py` vs the four existing citation tools

**Verdict: no duplication, but not a superset — `tools/digest-ledger.py` duplicates none of the four in population, catches four defect classes none of them catch, and leaves five measured gaps of its own (two code-level); C2's predicate still holds (`met=True`), so this is a scope/novelty finding, not a falsification.**

Axes named (godspeed): **novelty** (marginal coverage against the four), **correctness** (what a `blob` verdict actually proves), **operability** (instrument registration and ledger mutability). Every number below was measured read-only on a fresh seat clone of `/fast/scratch/kama-r42/clone` at the claim tip `3d9bd8d72366e281fab291874524130428ee423d` (HEAD of my clone); nothing in the lane or fleet was written.

Root causes, with the exact line:

- **F1 — attribution is not checked.** `digest-ledger.py:79` classifies by membership in a blob set built from `git rev-list --objects <rev>` (`:142`), i.e. *every blob in the measured revision's history, at any path*. A digest is therefore proven to **exist somewhere**, never to be **the bytes of the file the prose names**. Real weight at the tip: **7 of the 86 `blob` verdicts are history-only** and 30 of 96 tokens are `SOURCES` anchors whose path is never consulted. fx3 (same tree, wrong file) is the minimal counterexample: exit 0 vs `mismatch`.
- **F2 — `.ufo/` is excluded** (`is_doc`, `:59-61`): every wave report and receipt is unscanned (fx5 `tokens=0`). That is the surface the round-41 temp-export leak (`R41A10-10`) lived on.
- **F3 — only `.md`/`.tsv` are documents**: fx13 (`receipts/candidate.json`, `.ufo/…/candidate.out`) → `tokens=0` exit 0. The round-42 receipts themselves are `.out`.
- **F4 — no revision-ancestry notion**: there is no `off-ref` analogue; any object reachable from the measured rev is accepted (fx4).

## 5. Gaps *between* the four (no tool owns these)

- **F5 — the ledger is a new mutable authority with no append-only guard.** fx6: commit 1 writes `5585f60…→wrong` (exit 0, `wrong_flagged=1`); commit 2 rewrites the same row to `unverifiable` with a note → **exit 0, `unverifiable=1`, no diagnostic**. `sources-append-only` cannot cover it (its contract is the 11-column `corpus/SOURCES.md` table; fx6 → exit 2), and no other tool reads the file. A `wrong` classification is therefore reversible by editing one cell.
- **F6 — duplicate ledger rows silently launder a classification.** `parse_ledger` (`digest-ledger.py:63-70`) keys `rows[c[0]]` with last-wins. Measured on a private fixture:
  ```
  single wrong row:                             wrong_flagged=1                       exit 0
  wrong row + unverifiable row (same digest):   unverifiable=1  wrong_flagged=0      exit 0
  unverifiable row + wrong row (same digest):   wrong_flagged=1                      exit 0
  ```
  Two rows for one digest are accepted with no `ledger_bad`; whichever sorts last wins. `round42-digest-audit.py:98-107` replicates the same `parse_ledger`, so the contract leg cannot see it.
- **F7 — the new instrument is unregistered.** `grep -n "digest-ledger" SKILL.md` → rc 1 (**0 matches**); `SKILL.md` has no round-42 section at all (`grep -c round42 SKILL.md` → 0). `gate-registry-check` cannot catch it by construction: `COUNTER_RE` (`tools/gate-registry-check.py:69-71`) only matches `tools/round<NN>-*`, so a non-round tool is outside its population. Meanwhile the gate is **red at the claim tip** — `registered 12 unregistered 16` (base `12/13`; freeze `12/16`) — and `tools/round42-digest-audit.py`, C2's own counter, is one of the three additions. The lane's round-34 C2 made this gate `registered 12 unregistered 0` (SCORECARD.md:1976); it has been red since.

## 6. The C2 `contract` leg's oracle is a copy of the tool

`tools/round42-digest-audit.py` reimplements `digest-ledger.py`'s classification verbatim (`parse_ledger:98`, `classify:109`, `ref_dir:149`, `ref_git:167` — same first-match order, same `rev-list --objects` blob set), and its 8 randomized fixtures (`make_case:204-262`) write digests as **bare hex lists** in `corpus/a.md`/`b.tsv` with **no path binding anywhere**. Consequence: `contract=1` is a determinism/IO differential against the same design, not an independent oracle — it cannot fail on F1, F2, F4 or F6. The capability's measured strength rests on the `live` leg (base 10 unexplained → tip 0), which is genuine, plus §3, which no other tool covers.

## 8. Impacted axes

- **operability (C2, 8→8):** predicate met, so the score is not falsified. The findings are about the *claim's* scope: the capability row says it classifies "every full SHA-256 the lane's documents cite", but it classifies every full SHA-256 outside `.ufo/` in `.md`/`.tsv` only, by existence and not by attribution. F5/F6 matter most because they let a `wrong` digest stop being `wrong` without any counter changing colour, and the ledger is the only place a reader learns what a digest names.
- **calibration (C1, 7→7):** untouched; the capability rows C1 reconciles are the same rows F2/F7 propose to reword, so any wording change lands under C1's `capabilities` section, not C2's tool.
- **coverage (C3, 9→9):** untouched; the new entry's 2 digests are both tip-tree blobs (measured: `context-capacity-engine-sides.md in_tree=2`).

No axis is harmed by applying F1/F2/F3/F7 as wording + one counter, and F6/F5 close the two laundering routes.
