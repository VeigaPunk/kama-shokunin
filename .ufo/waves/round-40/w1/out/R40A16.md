## 2. Authenticity of the blob (it is a real `git ls-remote --tags` capture)

The blob is not a plausible-looking forgery — it reproduces git's exact output
algorithm:

- Every line is `<40-hex sha>\t<ref>` (tab-separated, 190/190 lines).
- 190 lines = 166 base refs + 24 peeled `^{}` entries.
- The 166 base refs are in strict `strcmp` order of the ref name.
- All 24 peeled `^{}` entries appear **immediately after** their base tag, and in
  every case the peeled commit sha differs from the tag-object sha (annotated
  tags). Reconstructing the file as "sorted base refs, each followed by its peeled
  entry" reproduces the file byte-for-byte (0 inversions, 0 anomalies).
- Anchor quoted by S472 is present at line 160 with a real tab:
  `35ce313293052f8362e0829e7512bc9bc3d336c9\trefs/tags/v0.5.22`, peeled at line 161
  to `baa9befa381511cd4d56f83980951e5a45fffc6d` — exactly the tag object / peeled
  commit pair the S472 row and the amendment assert.
- The amendment's own two recheck commands, re-run verbatim against the blob,
  reproduce their stated expectations: the version-ordered highest tag is
  `v0.5.22`, and `grep -c 'refs/tags/v0.5.22$'` → `1`.
- No `refs/tags/v0.5.23` / `v0.5.24` anywhere; the highest release v-tag by
  version order is `v0.5.22` (72 plain release v-tags; the 10 `rc` tags sort
  below).

Content counts also confirm the amendment's arithmetic: "190 ref lines (166 tag
names)" is exactly right (190 lines, 166 distinct base names). **The amendment's
counts are correct; only the digest on that line is wrong.**

## 4. BLOCKING FINDING — C1's `s474_row` leg and census validity are mutually exclusive

This is the load-bearing result of my work and it is a hard contradiction, not a
tuning preference.

### 4.1 The counter reads the wrong column

`registry_rows()` (counter line 44) does `line.split("|")` then keeps `cell[1:]`,
so the stored list is `[id, source, kind, tier, scope, anchor, teaches, status,
opened, recheck, used-by, ""]` — **`teaches` is index 6 and `status` is index 7**.
The counter's line 63 reads `teaches = s474[7]`, i.e. the **status** column, and
line 81 scans `row[7]` for false corrections. I confirmed the indexing directly
by importing the frozen module and feeding it a row with one distinct marker per
column: `row[6] = 'teaches-x'`, `row[7] = 'status-x'`.

The predicate sentence (`preregistration.json:15`) says "whose **teaches** cell
starts with 'supersedes S472'". So the frozen code does not implement the
predicate sentence it claims to implement. This is independently confirmed by
peers R40A04, R40A07, R40A23 and R40E06/R40E13.

### 4.2 The census mandates the marker in the very cell the counter ignores

`sources-census.sh` (fleet repo, read-only) parses rows with `gawk -F'|'` and
maps cell 7 → `teaches`, cell 8 → `status`. Its duplicate-URL rule (line 648) is:

    if (u!="" && (scope_key in url_scopes) && status!="rejected" &&
        url_scope_nonrejected[scope_key] &&
        teaches !~ /supersedes S[0-9]{3}/)
        printf "... E04 ... duplicate url ... within scope ..."

So when a new row repeats a source URL **and** scope with an existing live row,
the census *requires* `supersedes S<n>` to appear in the **teaches** cell —
index 6 — exactly the cell the counter ignores. That is also the lane's
house convention: all 25 existing supersession rows in `corpus/SOURCES.md`
(S031, S040, S047, S056, S065, S078–S088, S096, S099, S100, S105, S131–S135,
S138, S139, S194) carry `supersedes` in column index 6 (`teaches`). No row in the
lane has ever used the status column for a supersession marker.

### 4.3 Formal impossibility under census validity

Census validity requires `NF == 13` (11 data cells; anything else → E01) and
`status ∈ {queued|mined|rejected}` (else E07). Therefore, for **every**
census-valid row, `row[7]` is one of `queued`/`mined`/`rejected` and can never
start with `"supersedes S472"`. Hence:

> **No census-valid S474 row can make `s474_row` become 1.**
> The C1 `s474_row` leg is unsatisfiable jointly with registry validity.

- `false_corrections` at base is **1**, sourced from the amendment's wrong digest
  (the rule at counter line 84 fires because `amend_corrected == 0`), not from any
  registry row. The frozen `preregistration.json` kill-rule prose claims
  "false_corrections == 0" at base; the measured control
  `.ufo/waves/round-40/controls/c1-base.out` says `false_corrections=1`. The
  kill-rule's *conclusion* (met False at base) holds; only that prose detail is
  inaccurate. I reproduced the base control **byte-exactly** by running the frozen
  counter against base `efe25f96…` in the evidence clone.
- Docstring/behavior drift: the docstring says the wrong digest *outside* the
  correction section counts as false, but line 84 only counts it when the

  wrong digest on amendment line 9 is tolerated (verified: `amend_corrected=1`,
  `false_corrections=0` while the wrong digest remains twice in the file). The
  round-40 report must not claim the stricter semantics.

1. **Do not** chase a row shape that satisfies the frozen counter. Every such
   shape breaks `sources-census.sh validate` (E01/E04/E07) and would introduce a
   registry regression to buy one counter leg.
2. **Ship the semantically correct S474 row**: 11 columns, `teaches` (index 6)
   starting with `supersedes S472` and containing
   `5585f6027df2dbc4dbafd4979b61c218ffd94e8af99936733218e0ae989e50f2`, `status`
   `mined`, `kind` `own-work`, `tier` `A`, and a source cell that names the
   local evidence artifact. If the source cell repeats
   `https://github.com/sgl-project/sglang.git` **and** repeats S472's scope
   verbatim, census E04 fires unless the teaches marker is present — the teaches
   marker is present in this design, so E04 is satisfied; but to keep the W04
   duplicate-URL count at baseline, an own-work source label **without** the
   remote URL is the lower-risk choice (consistent with peer R40E13/R40A23).
3. **Disclose the counter defect** rather than hide it: record the frozen
   counter's raw output at the landed tip (`s474_row=0 … met=False` for the
   census-valid row) alongside an explicit statement that the predicate sentence
   names the `teaches` cell while `tools/round40-calibration-audit.py:63` reads
   `row[7]` = `status`, and that the census's own E04 rule requires the marker in
   `teaches` — i.e. the frozen leg and registry validity cannot both hold. This
   is the same disclosure precedent the fleet established in chousa r38 Errata
   1–13 and kama r39 attempt 1.
4. If the L1 instead wants the counter leg to flip, that is a **counter change**,
   which round 40's freeze forbids (`preregistration.json` notes: "The frozen

   a row-shape search.
