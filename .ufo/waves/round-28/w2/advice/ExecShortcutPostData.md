## The shortcut

The pinned declaration file contains both the field declarations and the
`field_num::eval` implementation, so the outcome class is a two-branch
mechanical function of the declaration line:

- `set_hard_limits(lo, hi)` -> `is_hard_limit = true` -> eval throws
  `Value must be between lo <= value <= hi`; send `lo-1`, claim
  `reject 400, bounds lo to hi`.
- `set_limits(lo, hi)` -> `is_hard_limit = false` -> eval silently clamps
  (`std::max(min, std::min(max, v))`); if `hi+1` is representable send `hi+1`
  and claim the stored `hi`, else send `lo-1` and claim `lo`.

No per-field outcome, default or request is consulted. 20 fields qualify
(13 hard, 7 soft); the preregistration `excluded_fields` (`n_cache_reuse`,
`xtc_threshold`) are skipped. Table, registry and S-rows are emitted by the
same script; the S-rows carry the URL with the line anchor, a nominal access
timestamp and the pin's sha256, all generated textually.

One bound is not a literal in the declaration file: `n_cmpl`'s upper bound is
`params_base.n_parallel`, resolved from upstream `tools/server/server.cpp` at
704366d (auto `--parallel` -1 -> 4, lines 169-172). Excluding that row leaves
19 counted rows, still >= 18, so the result does not hinge on that lookup.

## What holds

- Every counted row is true live behaviour: the counter, not the writer, ran
  the server and matched status, message bounds and stored values.
- The rows do not use A1's refused class at all: they are not identity, not
  the omitted-field default and not any generic conversion of the sent value.
  A1 closed the type-conversion shortcut, and this shortcut does not need it.
- The target is met with spare: 20 derived rows vs target 18.

## What does not hold

1. **"Measured" is not evidenced by the target.** The counter cannot tell a
   writer who ran requests from one who read the declaration file. The
   derivable class (20) is larger than the pre-declared target (18), so
   `counted >= 18` can be met without observing a single outcome. The claim's
   label `measured` is therefore overstated: the counter proves the table is
   *true*, not that it was *measured*.
2. **The shortcut controls miss this class.** The preregistration's
   `source-blind` control is defined as guessing *without* reading
   server-schema.cpp semantics; `label-keyed` copies label tables; `echo` and
   A1 cover value transformations. None covers "read the declaring line's own
   limits and the eval branch". The pre-freeze source-blind policy scored
   14/38 under A0 and 9 under A1 — that is guessing, not deriving; a
   derivation was never controlled.
3. **Clause (c) provenance is text-only.** The S-rows in this attack were
   generated with the pinned hash and a nominal `accessed` timestamp, without
   opening the URL; the counter accepted all 20. The gate claim that each row
   "was opened this round by the data seat named (its own curl ... hashed
   ...)" is not checked anywhere by the counter.
4. **Consequence for the landed 26.** The count arithmetic (34 rows, 26
   counted, 8 not) plus the A1 amendment's list of eight generic-conversion
   fields implies the eight refused rows are the no-limit numeric fields
   (identity or conversion only, hence impossible to count under A1) and the
   counted 26 = 13 hard + 7 soft + 6 handler rows. The 20 derivable rows are
   exactly the hard+soft set, i.e. the threshold could have been reached
   without measurement regardless of the six handler rows. [INFERENCE: derived
   from the amendment text and the receipt counts, not from reading the
   registry.]

## Limits of this attack

- The policy derives only fields with explicit numeric limit clauses. The 8
  no-limit numeric fields and the 6 handler fields in the landed table are not
  derived here; the full 34-row table still contains content beyond this
  derivation (6 handler rows plausibly require a live response shape).
- Single deterministic run; no re-run. All inputs (counter, schema snapshot,
  server, model) are hash-pinned and were verified.
- `n_cmpl`'s non-literal bound is the only input from outside the pinned
  declaration file; dropping it leaves 19 >= 18.
- The only execution of the pinned server outside the counter was
  `llama-server --help` (no socket, no port) to read documented defaults; the
  generated policy does not use those defaults.

shape.
