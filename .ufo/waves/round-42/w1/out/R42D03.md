### Root Cause of the Separability Defect
In commit `2793eb5`, C1's `SCORECARD.md` head `## Axes` table carried raw counts:
- Freshness: `recheck=[...] -> 220` (counting all rechecks in `corpus/SOURCES.md`, including S478 and S479 added by C3).
- Coverage: `len(glob.glob('corpus/knowledge/*.md')) -> 35` (counting all knowledge files, including `context-capacity-engine-sides.md` added by C3).

When `build_separability.py` constructed the `sep-c1-only` fixture (which reverts `corpus/SOURCES.md` and removes C3's knowledge entry), rechecks fell from 220 to 218 and knowledge files fell from 35 to 34. This triggered `r41=2 mismatches=2 met=False`, saved as `sep-c1-only.c1.out` (and `before-filter.out`).

In commit `c8c92db`, the author decoupled those facts in `SCORECARD.md` by restricting the queries:
- Freshness: `... and int(l.split(chr(124))[1].strip()[1:])<=477 -> 218`.
- Coverage: `... if 'engine-sides' not in f -> 34`.

In commit `595b65f`, `corpus/lessons/round-42.md` §Mistakes line 49 and `corpus/QUALITY.md` KQ53 recorded that:
> *"The two count facts were restricted to what exists without C3 (registry rows S001–S477, knowledge entries other than the round-42 entry); the regenerated `controls/sep-c1-only.c1.out` reads `met=True`; KQ53."*

**However, `controls/sep-c1-only.c1.out` was NEVER regenerated in the tree.** The repository retained the stale failure receipt from before the filter (`exit 1`, `met=False`). Re-executing `build_separability.py` at tip `3d9bd8d7` proves `sep-c1-only.c1` evaluates cleanly to `mismatches=0 met=True` (exit 0) (rebuilt receipt saved at `out/R42D03/sep-c1-rebuilt.c1.out`).

## 3. Dependence Analysis: Real Coupling vs. Shared File

### 1. `SCORECARD.md`: Real Logical Coupling + Second-Order Parsing Shadow
- **Shared Surface:** C1 writes head sections (banner through Axes); C2 writes the canonical capability table.
- **Real Logical Coupling:** C1's §Retired asserts `"6 axes and 8 capabilities remain active"`; §Saturation asserts `"first-working rounds 10, 14, 16, 20, 25, 30, 41, 42"`; §Capabilities mirrors the 8 capabilities. If C2's acquisition of `digest-ledger` does not land, C1 fails Retired (7 != 8), Saturation (missing 42), and Caps head (7 != 8). A self-description claim by nature reconciles the post-round capability state.
- **Second-Order Parsing Defect (The Shadowed Canonical Table):**
  In `SCORECARD.md` line 117 (written by C1):
  ```markdown
  Mirror of the highest canonical list (`**Capabilities — canonical list as of round 42**` in §Round 42).
  ```
  Both `tools/round42-selfdesc-reconcile.py:124` (`canon()`) and `tools/round42-digest-audit.py:274` (`highest_canonical()`) search for:
  ```python
  re.search(r"canonical list as of round\s+(\d+)\*\*", l, re.I)
  ```
  Because line 117 matches this pattern for round 42 before the actual canonical table at line 2256, and both functions check `if int(m.group(1)) > best:`, **the parser binds to line 117 and parses C1's head table as the canonical list**. The actual canonical table in §Round 42 at line 2256 is completely ignored!
  This creates an unintended dependency: C1's head table alone satisfies C2's `capability=1` check (evidenced in `sep-c1-only.c2.out` where `capability=1` even when C2 files are absent), while any edit or defect in the canonical list at line 2256 is shadowed and undetected by the counters.

### 2. `README.md` vs. `corpus/README.md`: Shared File Conflation, No Real Coupling
- Preregistration line 53 stated `"at tip README names the entry (coverage=1)"`.
- In reality, C1 edits root `README.md` (listing all 14 top-level entries to clear `readme` mismatches).
- C3 edits `corpus/README.md` (adding the coverage row for `context-capacity-engine-sides.md`).
- `tools/round42-capacity-audit.py:185` checks `corpus/README.md`.
- These are distinct files in different directories. There is zero code coupling; only a minor wording ambiguity in `preregistration.json:53`.

### 3. `PROVINCE.md`: Contract Coupling
- C1 checks that for every capability in `crows` citing `tools/` or `registry/`, `PROVINCE.md` contains that token (`round42-selfdesc-reconcile.py:258–263`).
- Because C2 added `digest-ledger` citing `tools/digest-ledger.py; registry/digest-ledger.tsv`, C1 was required to add both tokens to `PROVINCE.md`.
- In `sep-c2-only.c1.out`, C1 fails with `province=2` because base `PROVINCE.md` lacked C2's tools. This is a legitimate contract coupling: the lane's boundary document must cover all active capabilities.

### 4. `corpus/SOURCES.md`: Shared File with Clean Decoupling
- C3 appends rows S478 and S479.
- C1's freshness RUN fact counts rechecks. Decoupled by scoping to `int(...) <= 477`.
- C1's `caps` head check: census counts (`opened`, `mined`, etc.) were removed from the head prose (`"Registry counts are not restated here..."`), eliminating what would otherwise have been a mismatch on `cen["mined"]` (199 vs 201).
- This is a shared file without operational coupling.

### 5. Whole-Repo Document Scanning in C2: Universal Hygiene Invariant
- `tools/digest-ledger.py` scans all `.md` and `.tsv` files in the repository for SHA-256 tokens.
- C3's rows S478 and S479 in `corpus/SOURCES.md` cite the SHA-256 digests of committed copies in `.ufo/waves/round-42/c3/`. Because they exist as git blobs, `ref_git` classifies them as `blob` (`blob` increased from 84 to 86; `unknown=0`).
- This is an invariant enforcement (KQ50), not a functional inter-claim dependency.

## 4. Proposed Connector Move

### Evidence
1. `.ufo/waves/round-42/controls/sep-c1-only.c1.out` is stale and records `met=False` (`mismatches=2`, exit 1), contradicting `corpus/lessons/round-42.md` line 49 and `corpus/QUALITY.md` KQ53 which state the regenerated control reads `met=True`.
2. In `SCORECARD.md` line 117, the prose string `(`**Capabilities — canonical list as of round 42**` in §Round 42).` matches the regex in both `round42-selfdesc-reconcile.py:124` and `round42-digest-audit.py:274`, causing both counters to read the head table and shadow the actual canonical list at line 2256.

### Affected Axes
- **`calibration`** (Primary): Reconciles the contradictory separability evidence in the controls directory; ensures the calibration counter verifies the genuine canonical capability table rather than its own mirror.
- **`operability`**: Ensures the capability acquisition audit binds authoritatively to the round's capability table in §Round 42.
- **`coverage`**: Unaffected.

### Proposed Move
1. **Unshadow the Canonical Capability Table:** In `SCORECARD.md` line 117, adjust the prose styling to avoid matching the regex without changing semantic meaning, e.g.:
   ```markdown
   Mirror of the highest canonical list in §Round 42 (`Capabilities — canonical list as of round 42`).
   ```
   This prevents line 117 from triggering `canonical list as of round\s+(\d+)\*\*`, allowing both `canon()` and `highest_canonical()` to bind cleanly to the authoritative table at line 2256.
2. **Regenerate and Commit the Stale Separability Receipt:** Regenerate `.ufo/waves/round-42/controls/sep-c1-only.c1.out` from the claim tip so it contains the true measured result (`mismatches=0 met=True exit 0`), fulfilling KQ53 and resolving the evidence conflict in the round controls.

### Risks
- Zero risk to claim validity: at the claim tip, line 117 and line 2256 contain the identical 8 rows. Unshadowing line 2256 preserves `capability=1` in C2 and `caps=0` in C1 while eliminating silent masking of future canonical table edits.
- Zero risk to frozen counter scripts: fixing line 117 prose in `SCORECARD.md` operates entirely within the lane's editable documentation surfaces without modifying frozen tools.
