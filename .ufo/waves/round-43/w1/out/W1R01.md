## 3. Frozen defects (findings only — nothing changed in place)

**D1 — the do-nothing control names a tip that does not exist.** `controls/base.c1.out:1` and `controls/freeze.c1.out:1` both record `tip=4dc17978e184d5474f6b0ff3f3d9af608e06aac3`; `git -C /fast/scratch/kama-r43/clone cat-file -e 4dc17978…` → `fatal: could not get object info` (`rc=128`). It is neither the base (`6897ead5`) nor the freeze commit. The same holds for every C1 shortcut receipt (`b12e890c…`, `ca02a0d2…`, `314b126c…`, `41799b45…` — all ABSENT; `W1R01/control-provenance.txt`). Cause: `build_controls.py:184-187` (`fresh()` at `:29`, `commit()` at `:39`) commits in a throwaway copy and records that copy's HEAD. The numbers are still base numbers (see D3), so the defect is provenance, not arithmetic.
*Fix (closure, not in place):* record the lane commit measured in the report and keep the throwaway hash as a control id only; the counter's `tip=` field should not be the sole anchor.

**D2 — `freeze.c1.out` is a duplicate, not a freeze measurement.** `sha256sum` of `base.c1.out` and `freeze.c1.out` are equal (`7c0847ce…`) and `diff` is empty. `build_controls.py:184` (`d = fresh(a.clone, a.base)`) checks out the same `--base` for *every* control, so the control named "freeze" cannot differ from "base" unless it was run with `--base 895793e0` — which it was not (else `pop` would be 31, not 28). The prereg's `do_nothing_control` therefore asserts a freeze-time control that does not exist.
*Fix:* re-run with `--base 895793e0b4c56bdcb939277b8ff0251b26306d4d`, or rename the pair and drop the freeze claim.

**D3 — the round's real starting point is 45, not 42.** At the named base `6897ead5` the counter reproduces the receipt exactly (`unreg=16 … pop=28 mismatches=42`). At the freeze commit `895793e0` it reads `unreg=19 … pop=31 mismatches=45` (`W1R01/receipts/base-freeze-tree.c1.out`), because this round's own three counters are themselves unregistered. A seat that registers the 16 paths named by `base.c1.out` still reads `unreg=3`.
*Fix:* the round report and the closure must state 45/19/31 for the measured tip; the kill rule still holds (45 → 0), so this is a bookkeeping correction, not a claim change.

**D4 — the described measurement root is one commit stale.** `/fast/scratch/kama-r43/clone` HEAD is `1af8d516` ("C3 API copies"), one commit past the freeze; `git log --oneline 895793e0..HEAD` touches only `.ufo/waves/round-43/c3/*.json`. C1 is unaffected (I measured at `895793e0` explicitly), but "the clone is at the freeze commit" is inexact; `prereg.claims[0].measured_commit` is `null` and no receipt names a checkable revision.

**D5 — the frozen shortcut family has a gap that the cheap attack walks through.** `junk-c1-fillerrows` fails only because its 16 rows name no flag (`flags=18`); `junk-c1-flagpaste` fails only because it pastes `--repo --tip --out` into every row, and several counters do not declare all three (`flags=11`), and it carries no pins (`pins=19`). No frozen control combines **one declared flag** (e.g. `--repo`, declared by all 19) **with correct pins** — the conjunction that reads `flags=0 pins=0` (A2). The controls falsify each clause alone and never the composition.
*Fix:* disclose A2 as a known shortcut shape in the closure; if a control is added next round, add exactly this conjunction.

## 4. Smallest safe correction (closure-side; the counter stays frozen)

1. **Grade the row, not its existence.** A registry row must name the invocation the counter actually needs (`--repo` plus the revision/output flags it declares), every exit code it can return including 2, one named digest, and the file it writes. A2 fails all four while passing the counter.
2. **Pin with the full 64 hex.** `SHA_RE` accepts 8; a 64-hex pin is unambiguous and sits outside the C2 hexrun token class (`tools/round43-hexrun-audit.py:17-18,82`: `32 ≤ L ≤ 127, L ≠ 64`) — an 8-hex or 40-hex prefix buys nothing and a 40-hex one would add a census token that must then be ledgered. Empirically, C2 on A is unchanged from base (`tool=0 … met=False`, all legs 0, because `tools/hexrun-census.py` does not exist yet, so the interaction is not yet observable); the token-window claim is a source read of the frozen counter, not a measured result.
3. **Do not let one row register many counters.** The `any(path in c for c in r)` match (`gate-registry-check.py:196`) plus `path in l` (`round43-registry-audit.py:133`) make a 19-path row a legal registry; the honest build must be 19 rows, one per instrument.
4. **Calibration figure from an append-only count.** `spot` compares a written number to a glob (`:206`); deleting a closure (G) or adding a decoy (B) both satisfy it. The lane already holds an independent detector: `tools/round42-selfdesc-reconcile.py` re-runs the cited glob and reported `no stdout line == '28'` on A2. Require that instrument's run in the closure.
5. **Search-log corrections must say what changed** (row id, wrong text, right text). The token check (`:196`) is a floor; a no-op "correction" passes it.
6. **README must list `.ufo/` and `.gitignore/` as tracked**, not merely name them: the check is `n not in rd` (`:217`), so asserting they are untracked passes.
