## Findings

1. **Install-tree digest may silently cover a subset while appearing complete (medium confidence).** `install_tree()` promises a digest for every regular file (`tools/kama-llamacpp-live.py:178-181`), but after a per-file `lstat` or `sha256_file` `OSError` it silently continues (`192-199`) and hashes the remaining entries as an ordinary combined digest (`200-202`). The gate recomputes the digest over only the recorded map and does not establish that the map contains every directory member (`tests/llamacpp-live/check-receipt.py:354-380`). Directory-list failure is visibly represented as `tree_sha=None`; per-file omission is not. Thus a transient/read-permission error can yield a plausible non-null but incomplete install identity. This is static analysis; no filesystem fault was injected.

2. **Receipt emission failures are silent in v3, unlike frozen v2.** On first-emit `BaseException`, v3 records an internal fault and retries once, but prints no diagnostic (`tools/kama-llamacpp-live.py:1550-1562, 1572-1588`). If `--out` cannot be written on both attempts, `emitted` remains false and the function returns 2 (`1590`) without a receipt or stderr explanation. Frozen v2 printed the OSError / emit-fault message to stderr (`frozen/tools_kama-llamacpp-live.py:1406-1413`). The exit code remains within the v3 table, but this removes the operator-visible reason for a common persistent write failure. This path was not dynamically fault-injected.

3. **First-emit `except Terminated` is unreachable in the normal shutdown path.** The finalizer installs `SIG_IGN` before teardown and before the first `_emit` (`tools/kama-llamacpp-live.py:1403-1408, 1550-1558`), restoring handlers only afterward (`1564-1570`). Therefore the first `_emit`’s `except Terminated` branch cannot receive one of the three handled signals in normal operation; only an earlier failure to install `SIG_IGN` could leave the raising handler active. The second-emit `except Terminated` is reachable because it runs after handler restoration (`1572-1585`). This is dead defensive code on the normal path, not a broken exit or teardown path.

4. **A later internal fault overwrites the first setup-error reason.** `_record_internal()` assigns both `internal_fault` and `setup_error` unconditionally (`tools/kama-llamacpp-live.py:888-891`). If a `SetupError` was already recorded (`1397-1398`) and finalization then hits an internal fault, the original setup token is lost. The gate requires `internal_fault == setup_error` (`check-receipt.py:279-286`), so the overwrite keeps the current receipt contract coherent, but the receipt cannot retain both causes. No compound-fault case was exercised.
