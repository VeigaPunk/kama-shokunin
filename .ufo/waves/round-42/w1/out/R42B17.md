## 2. Findings

### F1 — Medium (High if this tool is reused fleet-wide): a committed ledger row reads any host file, and the summary is an existence + content-match oracle

**Where.** `tools/digest-ledger.py:84-91`
```python
84:             if cls == "external":
85:                 p = r["path"]
86:                 if p and os.path.isfile(p):
87:                     with open(p, "rb") as f:
88:                         h = hashlib.sha256(f.read()).hexdigest()
89:                     key = "external_ok" if h == t else "ledger_bad"
```
mirrored at `tools/round42-digest-audit.py:118-121` (`hashlib.sha256(open(r["path"], "rb").read())`). `path` is column 4 of a committed TSV; there is no confinement, no allowlist, no symlink check, no size cap, and no base directory (see F4).

**Evidence.**
- Secret read, verifier's own environment: row `path=/proc/self/environ`, digest computed from the same env (`R42B17_CANARY=hunter2-canary`) → `tokens=1 blob=0 external_ok=1 …` exit 0 (`r5.log` §D); `os.path.isfile("/proc/self/environ")=True`.
- Secret read, SSH private key: row `path=/home/vgpnk/.ssh/id_ed25519` →
  `tokens=1 … ledger_bad=1 …`, `detail: ledger_bad 6666… class=external`, exit 1 (`r8.log`). `ledger_bad` means the file **was opened and hashed** and its digest differs from the cited token.
- Existence oracle, no content knowledge needed: same row with an absent path → `external_absent=1`, exit 0; with the path present → `ledger_bad=1`, exit 1 (`repro2.sh` §P3-3 vs §P3-2).
- Content-match oracle: `external_ok=1` iff the file's SHA-256 equals the attacker-chosen token (`repro2.sh` §P3-1).
- `--details` does **not** print the path (`r8.log`), so the leak is exactly the two bits above — but tokens are unbounded (one 64-hex run per row, unlimited rows per doc), so a hostile ledger can test one candidate file content per row per run: a practical confirmation oracle for low-entropy secrets, and an existence probe for arbitrary paths.

**Impact.** The ledger is *data*; reviewers audit code, not TSVs. Anyone who can commit a row — or copy a ledger between lanes/hosts, which is the intended reuse path — makes every verifier hash files of their choosing outside the repository, including keys and process environments, and learns existence and whole-file equality. Compare the tool's own `--ledger FILE` flag, which *is* guarded: `scan --dir R --ledger /etc/shadow` → `digest-ledger: [Errno 13] Permission denied` exit 2 (`r5.log` §A). The guard exists one call site away.

**Minimal fix** (keeps the frozen summary vocabulary, so the C2 contract and receipt stay valid):
1. One helper used by both `classify` implementations: `_hash_external(p, base)` → resolve `p` (absolute as-is, relative against `base` = repo root / `--dir` root, never the cwd), `os.path.realpath`, require containment under an allowlist (`--allow-root`, repeatable, default `os.path.expanduser("~")` plus the repo root — the four real rows are all under `/home/vgpnk`, so they keep working), then `fd = os.open(p, O_RDONLY|O_NOFOLLOW|O_NONBLOCK)`, `st = os.fstat(fd)`, require `stat.S_ISREG(st.st_mode)`, hash in 1 MiB chunks with a byte cap — the four real artifacts are 196 KB, 7.7 MB, 22 MB and the round-35 fetch, so the cap must sit above the largest (22 MB) rather than at the tree's 2.9 MB largest blob.
2. Any `OSError`, non-regular file, or oversize → `external_absent`, with the reason on a `detail:` line (details are not compared by the counter, so no contract change).
3. Mirror the helper in `round42-digest-audit.py` (it must stay an independent reference, not an import).

### F2 — Medium: a ledger row turns the tool's exit contract into a traceback (exit 1, no summary line)

**Where.** `tools/digest-ledger.py:87-88` is reached from `classify` at line **258**, which sits *outside* the guard at 253-257:
```python
253:     try:
254:         tok, blobs, led = scan_dir(a.dir, a.ledger) if a.dir else scan_git(a.repo, a.rev, a.ledger)
255:     except (RuntimeError, OSError, ValueError) as e:
256:         print(f"digest-ledger: {e}", file=sys.stderr)
257:         return 2
258:     n, detail = classify(tok, blobs, led)
```
The docstring at line 39 promises `Exit: 0 L+X+K == 0; 1 otherwise; 2 usage or git error`.

**Evidence.**
- `/etc/shadow` row (uid 1000): `PermissionError: [Errno 13] Permission denied: '/etc/shadow'` at `digest-ledger.py:87`, **stdout empty**, exit 1 (`R42B17/b.err`).
- `/proc/self/mem` row: `OSError: [Errno 5] Input/output error` at `digest-ledger.py:88` (the `open` at 87 succeeds; the read fails), **stdout empty**, exit 1 (`R42B17/r9.err`, `repro1.sh` §P8).
- 4 GiB sparse file row under `ulimit -v 1000000`: `MemoryError` at `digest-ledger.py:88`, stdout empty, exit 1 (`R42B17/memoryerror.err`).

**Impact.** Exit 1 is documented as "there is an unexplained digest". A crash that produces no summary line at all is indistinguishable from that verdict for any exit-code consumer — the C2 counter, the closure, a CI gate. Reachable without malice: run the tool as a different user, or on a host where a legitimate external artifact is unreadable or oversized — exactly the situation the `external` class exists to describe. `external_absent` is the honest answer there, not a traceback.

**Fix.** Move `classify` inside the `try` (or wrap the per-row read per F1(2)) and add `MemoryError` and `UnicodeError` to the caught tuple → exit 2.

### F3 — Medium: the C2 counter crashes on hostile or merely odd trees, and can print `met=True` while exiting 1 with no receipt

**Where.** `tools/round42-digest-audit.py:120` (same unguarded read), `:89` (`p.stdout.decode()` — strict UTF-8), `:364` (`except (RuntimeError, subprocess.CalledProcessError)`), `:373-376` (`--out` written *after* the summary is printed and *outside* the try).

**Evidence.**
- Hostile row `/etc/shadow` in a fixture repo → `PermissionError` at `round42-digest-audit.py:120` inside `ref_git`, **stdout empty**, exit 1 (`R42B17/f1.err`).
- Hostile row = 4 GiB file under a 1 GB cap → `MemoryError` at `:120`, stdout empty, exit 1 (`R42B17/f2.err`).
- Non-UTF-8 tracked doc (`corpus/latin1.md` = `caf\351 \377\376`) → `UnicodeDecodeError` at `:89`; the *tool* handles the same repo fine (`scan --repo … --rev HEAD` → `tokens=0 … exit=0`) (`r7.log`). The counter's reference is strictly less tolerant than the contract it claims to freeze.
- `--out /proc/nope/x.out` → summary `tool=1 contract=1 live=1 hygiene=1 capability=1 met=True seed=42` is printed, then `FileNotFoundError` from `os.makedirs` at `:374`, **counter_exit=1**, no receipt written (`r5.log` §F).

**Impact.** A lane commit can make the C2 counter un-runnable on a verifier's host — the attacker picks the failure. The `--out` case is the sharp one: `met=True` on stdout with exit 1 and no receipt, so an exit-code-only harness records a false negative and an evidence-only harness records a pass without a receipt. All three crash paths should have been `could-not-evaluate: …` + exit 2.

**Fix.** (a) apply F1's helper in `classify`; (b) `git()` decodes with `errors="replace"` (matching the tool's contract); (c) catch `OSError`, `MemoryError`, `UnicodeError` in `main` → `could-not-evaluate:` + exit 2; (d) move the `--out` write into the same `try`, or probe writability before printing the summary and return 2.

### F4 — Low-Medium (correctness): an `external` `path` has no defined base — the tool, the counter's reference and the counter's tool-run resolve it against three different cwds

**Where.** `digest-ledger.py:86-88` (caller cwd) vs `round42-digest-audit.py:119-120` (counter cwd) vs `round42-digest-audit.py:265` (`subprocess.run(..., cwd=export)`, the tar export). Nothing in either docstring says which.

**Evidence.**
- Same tree, same row `path=../ext/secret.bin`: cwd = tree root → `external_ok=1`; cwd = a deeper directory → `external_absent=1` (`repro3.sh` §P4-1/P4-2).
- Fixture repo `5a49326` with a relative row (`path=ext.bin`) and the artifact untracked beside the repo root: reference `external_ok=1`, tool `external_absent=1` → **`live=0` spuriously** (`R42B17/f3b.out`: `live-reference: … external_ok=1 … exit=0` vs `tool exit 0 '… external_absent=1 …'`).
- Why the claim survives today: all 4 real rows use absolute paths, and `make_case` only ever emits absolute `ext_file` paths (`round42-digest-audit.py:217`, used at `:238`/`:241`), so the contract leg never exercises a relative path.

**Impact.** The verdict of a frozen counter depends on the operator's cwd — a reproducibility hole that a single relative row in a future ledger turns into a false `live=0`. It is also the traversal half of F1 (`../..` escapes the scanned root: `repro1.sh` §P5 → `external_ok=1` for `../outside.bin`).

**Fix.** Define the base in the docstring and the counter's contract block (repo root for `--repo`, DIR for `--dir`), implement it in both `classify` implementations, and add one relative-path case to `make_case`.

### F5 — Low: dash-leading `--rev`/`--tip` values are only stopped by git's own error path

`--rev=--output=/tmp/r42b17-pwn` reaches `git rev-parse --verify --output=/tmp/r42b17-pwn^{commit}` and fails cleanly (exit 2, no file). The `^{commit}` suffix is the only thing defeating every option form I tried, which makes this git-version-dependent. Cheap hardening, verified on git 2.56.0 in the seat clone:
```
$ git rev-parse --verify --end-of-options 'HEAD^{commit}'        → 3d9bd8d… rc=0
$ git rev-parse --verify --end-of-options '--output=/tmp/x^{commit}' → fatal: Needed a single revision
```
(Note: `git rev-parse --verify -- <rev>` does **not** work — it errors with `Needed a single revision`.) Alternatively reject a leading `-` in an argparse `type=` for both `--rev` and `--tip`.

### F6 — Low (disclosure): the ledger commits host layout, and it is the first *machine-consumed* absolute path in the lane

`git show 3d9bd8d:registry/digest-ledger.tsv | cut -f4` → 4 absolute `/home/vgpnk/...` paths (release archive, installed `.so`, `shokuknow/merge/kama/SOURCES.append.md`, the parked worktree's round-35 fetch). `/home/vgpnk` already appears in 12+ tracked lane docs (`git grep -c '/home/vgpnk' 3d9bd8d -- '*.md' '*.tsv'`), so this is consistent with existing practice — but here the path is an executable input (F1), not prose. Fix: store `path` as `~/…` (expand at read time) or behind a `host:` column, keeping the four rows re-hashable while dropping the layout from a public repo.

### F7 — Info (already acknowledged, restated so the closure reads it): a row can silence the tool

`digest-ledger.py:93` accepts any token as `unverifiable` when `note` is non-empty, and the counter's `junk-c2-allunverifiable` control only requires `external_ok>=4`. So "no cited digest is unexplained" is really "…unexplained *or* declared unverifiable with a note". The preregistration's `out_of_counter_limit` says as much; the residual is that the 5 `unverifiable` notes are prose, not a re-check, and nothing distinguishes an honest note from a silencing one. Not a tool defect — a limit of the claim's wording.

## 3. Claim status

- **C2 (operability 8→8, `digest-ledger`): stands.** Independent run at `3d9bd8d`, seed 42: `tool=1 contract=1 live=1 hygiene=1 capability=1 met=True`, exit 0, `external_ok=4 ledger_bad=0 wrong_unflagged=0 unknown=0`, TMPDIR empty; 200 dir-mode seeds and 24 git-mode fixtures show no contract divergence; no shell/argument injection; no credential material in the tree.

F3(d) is the one case where the counter misreports in the *permissive* direction (`met=True` + exit 1 + no receipt).
- **Routing:** F1/F2 → `tools/digest-ledger.py` (one helper + one `try` move); F3 → `tools/round42-digest-audit.py` (decode, catch, receipt); F4 → both, plus one fixture case; F5/F6 → cheap hardening in the same edit; F7 → no change, closure text only. All are post-claim repairs: none requires re-scoring C1 or C3, and F1's fix must keep the four absolute rows working so `live` stays `external_ok=4`.
