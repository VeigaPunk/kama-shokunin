## 2. FINDING A (blocking, calibration) — the C1 counter reads the wrong column

`tools/round40-calibration-audit.py:63` reads

```python
teaches = s474[7]
if teaches.startswith("supersedes S472") and CORRECT_EVIDENCE in teaches:
```

but `registry_rows()` (same file, lines 44-48) builds each row as
`[c.strip() for c in cell[1:]]` where `cell = line.split("|")`. For the committed 11-column
registry the cell order is fixed by the header at `corpus/SOURCES.md:11`:

```
| id | source | kind | tier | scope | anchor | teaches | status | opened | recheck | used-by |
```

so `row[0]=id … row[6]=teaches`, `row[7]=**status**`, `row[8]=opened`. **Index 7 is the `status`
cell, not `teaches`.** The counter checks `row[7].startswith("supersedes S472")` — i.e. it demands
that the *status* column literally begin with the string `supersedes S472`.

Verified by index-dump at base (`git show efe25f9:corpus/SOURCES.md`, rows S472 and S473):
`row[6]` = the teaches prose, `row[7]` = `mined`.

### Empirical proof (three fixtures, all in `/tmp`, git-init'd, toplevel-verified)

| fixture | S474 shape | C1 counter | census validate |
|---|---|---|---|
| A | marker in the true `teaches` cell (col 7), `status=mined` | `s474_row=0` → **met=False** | exit 0, 0 E |
| C/D | marker in the `status` cell (col 8) | `s474_row=1` → **met=True** | **exit 1, E07** `status=supersedes S472 …` |
| E | 12 columns (pad inserted before teaches) | `s474_row=1` → met=True | **exit 1, E01** `fields=12` |

**Consequence: the C1 claim and the census contract are mutually exclusive as frozen.**
The only shapes that flip `met=True` are (i) `status=supersedes S472 …` → census **E07** status
enum violation, or (ii) a 12-column row → census **E01** malformed row. The census-clean shape
that a correct `row[6]` predicate would accept leaves `met=False`.

This also makes the frozen `false_corrections` guard inert: it counts rows where
`row[7].startswith("supersedes S472")` (`round40-calibration-audit.py:81`), i.e. the same wrong
column. Proof: fixture F = a met=True base **plus** a spurious `S475` row whose *teaches* cell
starts with `supersedes S472` (a textbook false correction) → counter still reports
`false_corrections=0 met=True`. The guard cannot fire on the defect it exists to catch.

**The L1 must not attempt to satisfy C1 by writing the marker into the status column.** That
trades a calibration receipt for a census-red registry — the census is the fleet-wide instrument
(`scripts/sources-census.sh`), and a red `SOURCES.md` harms the lane's operability axis. The
frozen counter cannot be edited by me (it is a frozen, pre-data instrument, and lane edits are
forbidden here). The correct fix is a one-character index change `s474[7]` → `s474[6]` in the
counter, which must be authorised as a counter defect fix with a fresh control receipt, or the
claim must be re-preregistered against the `teaches` column. Both routes are L1/operator calls.

Note: this makes item A02 ("code-review `round40-calibration-audit.py` against the frozen C1
predicate sentence") the decisive review of the round, not a formality.

## 3. FINDING B (blocking, operability) — the after-state census is only stable if S474 reuses S472's scope string

The census's duplicate-URL logic keys on the normalised URL **and** the scope string
(`scripts/sources-census.sh:641-650`):

- `E04` fires when the same URL recurs **within the same scope** and the row is not rejected and
  the teaches cell lacks `supersedes S[0-9]{3}` (line 648 — the exemption exists precisely for
  a superseding row).
- `W04` fires when the same URL recurs **across different scopes**.

Because S474 (same `github.com/sgl-project/sglang.git` URL) and S472 share a URL, the scope string
decides everything. Measured on the full-repository scratch mirror:

| S474 scope string | W04 | E findings |
|---|---|---|
| **identical to S472** | **93 (unchanged)** | 0 → validate exit 0 |
| differs from S472 (shortened) | **94 (+1)** | 0 → validate exit 0 |
| identical to S472 but teaches lacks the `supersedes S472` prefix | 93 | **E04** → exit 1 |

Both sibling drafts (R40S04, R40A03) already reuse S472's scope string verbatim, so the drafted
S474 yields W04 93 and 0 E findings. **This must be stated as a hard constraint in the report:
the scope cell of S474 is byte-identical to S472's, and the teaches cell must begin exactly
`supersedes S472`.** Any rewording of the scope text silently adds a W04 (93 → 94) and would make
the after-measurement look like a registry regression.

the preregistration's base-state sentence verbatim — the report must quote the **control receipt**

## 9. Method notes / evidence hygiene

- All fixtures were created in `/tmp` via `D=$(mktemp -d) && git -C "$D" init -q`, with
  `git -C "$D" rev-parse --show-toplevel` asserted equal to `$D` before the first commit. No git
  or jj mutation was performed in the lane, the fleet repo, or any sibling lane. The lane clone
  `/fast/scratch/hyaku/kama-r40` and the fleet repo were read only.
- Fixture lineage: `/tmp/F01-mirror-base` (base mirror, commit `0b843d1e`) → `/tmp/F01-after-clean`
  (census-clean S474, 215 rows) → `/tmp/F01-counterpass` (marker in status → met=True, E07 red) →
  `/tmp/F01-12col` (12-column S474 → met=True, E01 red) → `/tmp/F01-false-on-met` (met=True base
  + spurious S475 → `false_corrections=0`, guard inert). `/tmp/F01-fixB` is the census-clean
  fixture with full corrections (counter `met=False`). All `/tmp` fixtures were temporary and have
  been removed after measurement; the lineage above is reproducible from the recipes in §2/§3
  (base mirror → append row → commit → run both tools).
- The full-repository mirror was used for `validate` (not a bare `corpus/SOURCES.md` copy) because
  E11 (`used-by` path existence) is resolved relative to the lane root — a registry-only mirror
  produces ~90 spurious E11 findings, the same trap recorded in the round-39 lesson.
- No tool was installed or upgraded this seat (no pacman, no `uv tool install`, no release
  binary). Only pre-existing `bash`, `gawk`, `git` and `python3` were used.
- The `sources-census.sh` script was invoked with its documented CLI only; it writes stdout or
  `--out` and reads only the registry and the lane root. No file in the fleet repo was modified.
