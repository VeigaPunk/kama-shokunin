## 4. Defect D2 — C1's `caps` leg is tautological at the claim tip (a surviving mutant)

- **File/line:** `tools/round42-selfdesc-reconcile.py:124` — `m = re.search(r"canonical list as of round\s+(\d+)\*\*", l, re.I)` inside `canon()` (lines 120–126), consumed at `:178–180` for `names`/`firsts` and at `:221–228` (`caps`) and `:259` (`province`).
- **What happens:** the round-42 head prose at `SCORECARD.md:117` reads ``Mirror of the highest canonical list (`**Capabilities — canonical list as of round 42**` in §Round 42).`` The regex matches **that backticked reference** at line 117, and because `canon()` only replaces on strictly greater round numbers, the real list at line 2256 never wins. `table_rows(lines[118:])` then parses the head `## Capabilities` table. Probe (`R42A14/canon_probe.py`):

```
(117, '42', 'Mirror of the highest canonical list (`**Capabilities — canonical list as of round 42**` in §Round 42)…')
(2256, '42', '**Capabilities — canonical list as of round 42**')
== canon() chose round 42 with 8 rows: [sources-registry, …, digest-ledger]
== head ## Capabilities has 8 rows: [sources-registry, …, digest-ledger]
== canon rows identical to head rows: True
```

  So `hn` and `names` (`:223`, `:179`) are the same table: the comparison at `:224` cannot fail. The only other `caps` check, the stated-counts-vs-census loop at `:225–228`, performs zero checks at the tip because the head now says "Registry counts are not restated here" (`SCORECARD.md:117`) — at base it checked three counts (`base.c1.out`: "states 30 opened; census 218", etc.). Net: the `caps` leg checks nothing at the claim tip.
- **Mutant that survives (the predicate it cannot enforce):** rename the head table's first capability to one that exists in no canonical list, leave the canonical list untouched, run the frozen counter:

```
python3 canon_probe.py      # mutant: SCORECARD.md:121 '| ghost-registry | …' ; canonical list line 2262 still 'sources-registry'
== M1 tip=bf434bd8 exit=0
```

  (`R42A14/M1-head-ghost.c1.out`.) The frozen predicate says "the head Capabilities table names exactly the highest canonical table's capabilities"; the counter reports `met=True` for a tree where it does not. The reverse direction is equally blind: deleting the whole round-42 canonical block (C2's SCORECARD text) from the tip tree also scores `met=True` (`R42A14/B-tip-no-c2canon.c1.out`, case B of `coupling_exp.py`).
- **Proposed fix** (counter is frozen, so this is a routed defect for the L1/closure, not an in-wave edit): anchor the match to the block's own heading, e.g. `re.match(r"^\*\*Capabilities — canonical list as of round\s+(\d+)\*\*", l)`, or skip lines containing a backtick. ## 5. Defect D3 (control fidelity) — sep-c1-only is not C1-only at file or hunk level

- **File/line:** `.ufo/waves/round-42/controls/build_separability.py:34` — `C2_FILES = ["tools/digest-ledger.py", "registry/digest-ledger.tsv"]`. The preregistration's C2 write set (`preregistration.json:66`) is those two **plus** the two round-41 counters and the SCORECARD canonical list. The sep-c1-only sandbox starts from the tip and removes only the two files (`:43`), so it retains (a) C2's counter-hygiene fix and (b) C2's round-42 canonical row, and (c) with D2, the head/canonical comparison reads the head anyway.
- **Evidence:** `sep-c1-only.c2.out` in a tree with no `tools/digest-ledger.py` still scores `hygiene=1 capability=1` — both are C2 work present in a sandbox labelled "C1 only". `build_separability.py:54` copies the two round-41 counters only for sep-c2-only, which shows the author knew they are C2's, but sep-c1-only inherits them from the tip checkout.
- **Consequence:** "C1 needs neither C2 nor C3 to have landed" (`preregistration.json:66`) is verified only for C2's two data files and C3's file set. It is **not** verified for C2's SCORECARD text or C2's counter cleanup, and D2 means the counter could not detect the former even if the control removed it. The honest statement is: C1 and C2 co-write `SCORECARD.md`, so hunk-level separation is required and was not performed.
- **Minor:** the sep-c2-only fixture does not use C2's real hunk; it appends a hand-written one-row canonical list (`build_separability.py:56`). That is a fabricated fixture, adequate for the `capability=1` leg but not a replay of the claim's text.
- **Proposed fix:** in `build_separability.py`, add the two round-41 counters to `C2_FILES` and, for the C1-only sandbox, replace `SCORECARD.md` with the tip text minus the round-42 canonical block (the same edit as case B) — then the control actually tests the diagonal it claims. Re-score after fixing D2.
