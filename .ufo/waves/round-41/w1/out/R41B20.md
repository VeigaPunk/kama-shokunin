- `tool/contract/sourced/capability` never touch the network: they read the `git archive` export of tip (round41-pinwatch-audit.py:209,211,267-308) and run offline fixture cases via `--tags-dir` (pin-watch.py:92-98; counter :230-231). Seed 41 (same as the frozen controls) reproduces `contract=1`.
- `live` is decided solely by byte-equality between the tool and the counter's own reference at round41-pinwatch-audit.py:261 (`len(rows) >= 3 and got == want and gcode == wcode`). Both sides run `git ls-remote --tags <repo>` under the same dead-proxy environment (counter :252 ` tool :100-101). Both fail identically:

  - tool: `read_tags` returns None (`:99-105) → same per-engine `status=error`, same summary, same exit 2 (pin-watch.py:114-117,126-131).
  - Byte-equal, same exit → `live=1`, `met=True`, counter exit 0. The `live-reference:` detail line ( :265) records the all-error reference verbatim.

## Finding

- The C2 predicate's live sub-claim ("its live check of registry/engine-pins.tsv equals the counter's own ls-remote reference over >= 3 engines", preregistration.json:35) is met under total network outage: agreement is trivial when both clients fail the same way. The counter therefore does not certify that upstream remotes were reachable, only that tool and reference agreed at the same moment (the preregistration itself scopes the leg to "same-moment agreement … it does not certify upstream release policy", preregistration.json:45 — the same limitation extends to upstream reachability).
- `met=True` and counter exit 0 hold unchanged across network-on and network-off; the claim's score evidence cannot distinguish a working watch from a blacked-out one. The tool itself fails safe — `status=error` per pin + exit 2 (pin-watch.py:131) is the honest outage signal — but the counter consumes no error signal: the all-error reference still counts as a passing `live` leg, and `met` stays True.
- No claim flip: under the frozen counter code (round41-pinwatch-audit.py:41,309) C2 remains `met=True` at tip in both network states. The falsifiable extra claim — "the live leg demonstrates real upstream observability" — is falsified: it would need a non-degenerate criterion (e.g. requiring `error=0` on the live reference, or distinguishing empty vs non-empty tag streams) which the frozen code does not check.
