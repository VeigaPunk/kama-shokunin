## 5. Findings and proposed fixes (findings only — nothing edited in place)

1. **R41A10-10 is fixed for normal termination but not for signal termination.** All five temp-allocating counters leave a full tree extraction (≈27–34M) in TMPDIR when SIGTERM'd. Default `TMPDIR` (unset) is `/tmp`, so a killed counter run on the shared host still recreates the round-41 disk-exhaustion hazard at ~30M per kill (smaller than the old ~253M per run, but unbounded under repeated kills). Proposed fix (lane-side): replace `atexit.register(shutil.rmtree, export, True)` with a module-level SIGTERM/SIGHUP handler that runs the same rmtree (or wrap the allocation+cleanup in a `try/finally` inside a `term_handler`), or have each counter trap SIGTERM and perform cleanup before re-raising; at minimum document in `AGENTS.md` that killed counter runs must be manually cleaned (`rm -rf /tmp/r41c1-* /tmp/r41c2-* /tmp/r42c2-* /tmp/r42c3-*` — note the `r41c1-*` leak also comes from `round42-selfdesc-reconcile.py`).
2. **`round42-selfdesc-reconcile.py` silently inherits the round-41 counter's temp allocation** (line 130-134) — it is not self-contained w.r.t. temp. If the round-41 counter is ever removed or changes its scratch layout, this counter changes behavior invisibly. Proposed fix: give the round-42 selfdesc counter its own `TemporaryDirectory`-scoped export instead of letting the imported module allocate outside any context.
3. **digest-ledger scan** is the only tool with no temp surface at all (verified under normal exit, under `timeout 5`, and under a forced 0.2s kill) — no action needed.
