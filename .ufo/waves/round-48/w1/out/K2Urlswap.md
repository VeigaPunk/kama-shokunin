# Round 48, lane kama, seat K2Urlswap — C2 urlswap/tamper leg attack

**Verdict: the C2 urlswap and tamper legs are satisfiable without downloading any file.** A replay variant that refuses the four swapped/tampered receipts by comparing URL/digest against the frozen constants *before any fetch*, and serves the genuine replays from host bytes, meets the whole frozen counter — `receipts=1 recordcheck=1 replay=1 compare=1 tamper=1 urlswap=1 newrow=1 replayed=3/3 met=True` — even when the network is provably dead (`https_proxy=http://127.0.0.1:1`). A second variant that skips live execution entirely (synthesizes the rerun from the committed receipt + cached bytes) also meets, fully offline. Only the naive blind copy (no refusal at all) is caught by the urlswap leg. The counter therefore cannot enforce "really re-acquiring and really re-running" (C2 question); it can only reject an out-of-pair receipt.

## Defect analysis

1. **urlswap leg (`:520-543`) checks outcome, not cause.** It requires only exit 2 + `refused` starting with `digest-mismatch` + no rerun receipt. A refusal produced by comparing the receipt's URL/digest to the frozen constants before fetching is indistinguishable from a byte-verification refusal after downloading. `swap-asset`/`swap-model`/`tamper-asset` are all refused cheaply by V1/V2/V3; `tamper-model` is already refused free by provenance validation. The leg kills only the *blind copy* (V4), which produces a matching rerun instead of refusing.
2. **Replay leg (`:396-434`) hashes final files but cannot observe their origin.** The counter sets `HOME`/`XDG_CACHE_HOME`/`TMPDIR` inside its scratch but the replay can read any absolute host path; nothing forces a download, or any live execution. D1's "copies host-cache bytes without downloading" is therefore not closed in combination: refuse-by-name + serve-from-cache passes every leg.
3. **Zero-execution passes.** Every field the counter checks on the rerun (schema, outcome, `started_utc` ≥ counter start, model commit, server/model/archive paths under scratch with the right hashes, evaluated checks, stable projection) is derivable from the committed receipt plus cached bytes; V3 shows no server needs to run or even exist.

## Smallest safe corrections (proposals; counter is frozen, nothing changed in place)

- **urlswap/tamper positive control:** add a case whose provenance names a *genuine* non-frozen pair with its real digest (e.g. the b11906 asset with its own sha256). It must replay successfully (exit 0, match). Any name/constant-based refuser (V1/V2/V3) refuses it → leg fails; an honest replay downloads the swapped resource, byte-verifies, and passes. This separates "refused because not the frozen pair" from "refused because bytes did not verify".
- **Replay live-ness:** have the counter mint a per-run nonce and pass it through (env) to the replay, which forwards it to the live tool via a new flag; the live tool stamps it into a capture that belongs to the stable projection, and the counter compares. A synthesized rerun cannot know the nonce in advance. (Files the counter hashes would remain, per D1, but the nonce forces at least the live tool to run and record something fresh.)
