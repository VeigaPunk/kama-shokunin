# kama-shokunin operating rules

- Work only within this repo and its PROVINCE.md scope.
- Every change appends a LOG.md entry with the evidence that motivated it.
- Never fabricate domain knowledge: cite a file, a command output, or a source.
- VCS (round 17, 2026-10-20): this repo is jj-colocated (git stays the backend and the GitHub remote). Only `/home/vgpnk/Projects/shokunin/scripts/hyaku/jj-lane.sh commit <lane-dir> --as kama -m "round-N: …" -- <repo-relative paths>` writes history; cite only the hash it prints as `landed <hash>` (older helper: `pushed <hash>`), never a `committed <hash>` line, which a push-recovery rebase can rewrite. Exit 3 from `commit` (or from `push`) means the commit exists locally but is not on the remote: rerun `jj-lane.sh push <lane-dir>`, never force; `nothing to commit` lands nothing. Never `git add`/`commit`/`stash`/`checkout`/`switch`/`reset`/`restore`/`rebase`/`pull`/`push` here and never a mutating `jj` command by hand (jj resets the git index on every mutation). Git HEAD is detached after a helper commit: read the tip with `git rev-parse refs/heads/master` or `jj-lane.sh state <lane-dir>`; `git rev-parse @{u}` then fails (exit 128) and `git rev-parse --abbrev-ref HEAD` / `git branch --show-current` print `HEAD` / nothing with exit 0, so never use them; verifier ranges use `origin/master..master`. Gates that need git writes run in a `/tmp` clone. jj ignores git hooks and `.gitattributes` eol/filters: add neither expecting them to fire. Run the round-13 live gate only after the helper commit (an uncommitted QUALITY.md exits 4, could-not-evaluate, when every other check is clean; a content failure still exits 1; byte-identical mode-only changes are not detected).
