## Findings

### F1 (latent, severity low) — the external class resolves a relative `path` against two different cwds

`tools/round42-digest-audit.py:119` (reference, runs in the counter's process cwd):
`if r["path"] and os.path.isfile(r["path"]):`
`tools/digest-ledger.py:86` (tool, runs with `cwd=export` per `run_tool`, `round42-digest-audit.py:264-267`):
`if p and os.path.isfile(p):`

The contract text (`round42-digest-audit.py:22-25`) says only "if the file exists" — it never says *relative to what*. Command that shows it (fixture kept):

```
$ cd R42B01/fixtures/relative_external_path/export && python3 tools/digest-ledger.py scan --dir fixture
tokens=1 blob=0 external_ok=1 external_absent=0 unverifiable=0 wrong_flagged=0 ledger_bad=0 wrong_unflagged=0 unknown=0   exit=0
# reference in the harness process (cwd = seat dir), same fixture:
tokens=1 blob=0 external_ok=0 external_absent=1 unverifiable=0 wrong_flagged=0 ledger_bad=0 wrong_unflagged=0 unknown=0   exit=0
# reference with cwd = fixture dir: external_absent=1 as well
```

So a relative `path` yields `external_ok` vs `external_absent`: the summary lines differ and the counter would score `contract=0` — for a reason that is pure cwd, not ledger truth. It cannot fire today because `make_case` only emits absolute paths (`round42-digest-audit.py:217,238`: `ext_file = os.path.join(d, "outside.bin")`), and the live ledger's four external rows use absolute paths (`registry/digest-ledger.tsv` col 4 all start `/home/vgpnk/`), so `c2/candidate.out` `contract=1 live=1` is unaffected.

Proposed fix (not applied — leaf): pin the meaning in the frozen contract and in both implementations, e.g. resolve non-absolute `path` against the scanned root — reference `round42-digest-audit.py:119` → `p = r["path"] if os.path.isabs(r["path"]) else os.path.join(d, r["path"])` and tool `digest-ledger.py:85-86` → same with `root`; alternatively declare non-absolute paths `ledger_bad`. Because the counter and tool are frozen after scoring, this belongs to a future round's counter, not to round 42's C2.

### F2 (precision, severity low) — the contract leg cannot see an upper-case-accepting token regex

`mut-upper` (TOKEN regex widened to `[0-9a-fA-F]`) is a direct violation of the frozen contract line `round42-digest-audit.py:13` ("a 64-char **lower-case** hex run"), yet it produced **0 mismatches in 2,400 generated cases** (`fuzz-result-mut-upper.json`, 6.88 s) because `make_case` only ever writes lower-case hex. The same tool is caught instantly by hand fixture 1. So `contract=1` in `c2/candidate.out` proves agreement on the generator's alphabet, not on the contract's token rule.

Proposed fix (future counter, not round 42): add one fixed fixture to `make_case` — a document citing `digest.upper()` next to the real digest — or state in the preregistration that the lower-case rule is pinned only by the live leg plus reviewer reading. This does not weaken C2: the *real* tool does enforce the rule (fixture 1, `tokens=1`).

### Non-findings worth recording

- CRLF, non-UTF-8, symlinks, 65-hex runs, split tokens, empty ledger and header-less ledger all agree; the reference and tool share the same `errors="replace"` decode, the same `os.path.islink` skip, the same `(?<![0-9a-f])…(?![0-9a-f])` boundary rule and the same header-skip condition, so these cannot drift independently.
- The generator's `"`" + tokens[0] + "x`"` tail (`round42-digest-audit.py:246`) makes the first token uncitable in some cases; harmless for the contract leg (both sides read the same file), noted so nobody mistakes it for a divergence.
- Exit codes agreed on every case, including the `L+X+K>0 → 1` rule; `mut-exit` shows the leg does compare them.
