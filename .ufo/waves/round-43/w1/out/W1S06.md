## 4. Findings (frozen artifacts — reported, not edited)

**F1 — a frozen round-43 base receipt names a revision that resolves nowhere.**
`.ufo/waves/round-43/controls/base.c1.out:1` is `tip=4dc17978e184d5474f6b0ff3f3d9af608e06aac3`.
`git -C /fast/scratch/kama-r43/clone cat-file -t 4dc17978e184…` → `fatal: Not a valid object name`;
the same probe in `/home/vgpnk/Projects/shokunin/kama-shokunin` → `fatal: git cat-file: could not get object info`.
The counts are reproducible from the prereg's base, so the receipt's content is sound but its label is not
auditable: `python3 tools/round43-registry-audit.py --repo $S/clone --tip 6897ead55c24…` prints the identical
`… pop=28 registered=12 mismatches=42 met=False`. Proposed fix (next round, forward-only): regenerate
`controls/base.c1.out` against `6897ead5` so the base receipt names a resolvable revision.

**F2 — the frozen "base mismatches=42" is the base tree's count, not the freeze tree's.**
Same audit at the freeze prints `mismatches=45` with `unreg=19`: the three round-43 counters are in the gate
population and unregistered. A reader who treats `controls/base.c1.out` as the freeze tree's do-nothing
baseline understates it by 3. No committed round-43 receipt prints the gate/audit line at `895793e0`
(`.ufo/waves/round-43/gate-registry-base.out` also reads `registered 12 unregistered 16`, i.e. the base commit
`6897ead5`). Proposed fix (next round): add a freeze-revision receipt; do not rescore this round.

**F3 — the round-41 base receipts were produced by counters absent from their tip.**
`git -C /fast/scratch/kama-r43/clone cat-file -e 8893b894:tools/round41-pinwatch-audit.py` →
`fatal: path … exists on disk, but not in '8893b894'` (same for the scorecard counter). The base line describes
revision `8893b894`'s state, not a counter revision. My rows say "at tip 8893b894" and never claim the tool is
committed there; no fix proposed to frozen receipts.

**F4 — docstring write-scope drift in both counters (minor, lane code).**
`tools/round41-scorecard-reconcile.py:41` says "Read-only on `--repo`: git show / cat-file / archive only", but the
code issues `rev-parse --verify` (`:144`), `cat-file -p` (`:80`), `cat-file -e` (`:86`) and `archive` (`:190`) —
never `git show`. `tools/round41-pinwatch-audit.py:45` says "git rev-parse / archive / show" while the code uses
`rev-parse` (`:208`), `archive` (`:214`) and a network `git ls-remote` (`:257`). My rows list the commands actually
issued. Proposed fix (lane, next round): correct the two docstring lines and add the network read to pinwatch's
scope sentence.
