## Findings (by severity)

### F1 — BLOCKER: leg 1 reads the `status` column, not `teaches` (label/string mismatch)
`corpus/SOURCES.md` header is
`| id | source | kind | tier | scope | anchor | teaches | status | opened | recheck | used-by |`.
The script builds `row = line.split("|")[1:]` → `row[0]=id … row[6]=teaches, row[7]=status`,
then reads `teaches = s474[7]` — the **status** cell.
Mechanical proof on S473 at base: `row[6]` = "`The Unix timestamp (in seconds) when the model was
created.`" (teaches), `row[7]` = `mined` (status).
Mutation B (contract-faithful correction: marker+correct digest in the real teaches cell,
`status=mined`): `s474_row=0 … met=False`, exit 1. **The genuine correction cannot flip met; the
counter contradicts the predicate sentence it freezes.**

### F2 — CRITICAL: `met` flips without the real corrections (demonstrated)
Mutation A: S474 row with `supersedes S472 <correct digest>` in the **status** cell, teaches left
uncorrected; `## Correction — round 40` appended; **superseded digest still live at amendment
line 9** (`source: S472 …`). Result: `s474_row=1 amend_corrected=1 r36d2c_fixed=1
false_corrections=0 met=True`, exit 0. Two compounding defects:
- **F2a** = F1 (wrong column is the satisfied surface).
- **F2b**: the wrong-digest guard is dead code. `if WRONG_EVIDENCE in amend and not
  amend_corrected` can never fire when `amend_corrected == 1`, which `met` already requires — so
  the docstring rule "wrong full digest outside its correction section counts as false" is not
  implemented. Appending a correction section while the live body still teaches the wrong digest
  passes as fully corrected.

### F3 — MAJOR: leg 3 is not row-bound
`if CORRECT_PACKAGE in lesson and "R36-D2C" in lesson` accepts the two strings anywhere in
`corpus/lessons/round-40.md`; the predicate requires "a correction **row** naming R36-D2C and
giving the full package digest". Mutation C: R36-D2C on one line, package digest in an unrelated
line → `r36d2c_fixed=1`, `met=True`.

### F4 — MINOR: kill-rule sentence misstates the base state
kill_rule says "At base (efe25f96) every leg is 0 **and false_corrections == 0**". The frozen
control `c1-base.out` (reproduced byte-identically) shows `false_corrections=1` — the superseded
digest sits at amendment line 9 at base. Legs 0 / `met=False` are right and the False→True flip
direction is unaffected, but the frozen sentence is factually wrong.

### F5 — MINOR: receipt-label equivalence claim not satisfied
Preregistration note: "the label string in the receipt equals the predicate sentence above". The
receipt emits a compact leg summary (`s474_row=… amend_corrected=… r36d2c_fixed=…
false_corrections=… met=…`); the exact predicate sentence appears nowhere in the counter — the
docstring is a paraphrase (verified: sentence not a substring of the script).

### F6 — MINOR: robustness / precision
- `blob()` swallows git errors: an invalid `--tip`/`--repo` yields an all-zero receipt
  (observed), indistinguishable from "files absent". Fail-closed, but the receipt is blind to
  the cause.
- The false-S47x check reads `row[7]` (status) too, and applies to every S-id, not only S47x —
  broader than the docstring (stricter direction; also masks F1 on the reject side).
- Leg 2's "section" is everything after the first `## Correction — round 40` to EOF; digests in
  later unrelated sections would satisfy it.
- A decode error on a blob would crash to exit 1 — same code as a legitimate miss (fail-closed,
  receipt-less).
