## Findings — the 8 survivors (coverage gaps, not license to change the contract)

- **F1 (M05) — `rel != LEDGER` in `is_doc` (:60) is dead logic on all exercised paths.** Both `scan_dir` (:120-124) and `scan_git` (:145-149) test `rel == LEDGER` / `path == LEDGER` in a branch that runs *before* `is_doc`, so the conjunct can only matter under `--ledger`, which no leg ever passes. Removing it left selftest, all 8 contract cases, and the live scan byte-identical. Harmless defense-in-depth today; if you want it covered, one contract case must pass `--ledger`.
- **F2 (M10) — wrong-row prefix equality covered only from above.** `c[:7]==t[:7]` survives because every real/fixture wrong row's `correct` shares ≥8 chars. No case has a `correct` digest sharing exactly 7 (not 8) leading hex chars. Proposal: add a selftest case — wrong row whose `correct` matches the first 7 chars only → expect `ledger_bad`.
- **F3 (M12) — `c in blobs` membership uncovered.** No case has a `correct` digest sharing 8 chars with the cited digest while absent from the blob set (selftest case 3 uses a non-matching prefix, so the prefix conjunct masks it; the live wrong row's correct digest is a blob). Proposal: selftest case with `correct` = 8-prefix-matching digest not in the blob set → expect `ledger_bad`.
- **F4 (M13) — the `fullmatch` guard is logically dead, not just uncovered.** `c in blobs` already forces `c` to be a 64-lowercase-hex sha256 (set of hexdigests), so `fullmatch ∧ membership ∧ prefix ≡ membership ∧ prefix`. No behavioral gap exists; dropping the guard cannot change any output on any input. Optional cleanup only.
- **F5 (M19) — ledger rows with a class outside {external, unverifiable, wrong} never exercised**, so the `else → ledger_bad` routing (:99) is unobserved. Proposal: selftest case with a bogus class → expect `ledger_bad`.
- **F6 (M22/M26/M27) — selftest honesty is uncovered by the whole detector pair.** The audit never runs `digest-ledger.py selftest`, and even a run would not catch these: M22 makes selftest always exit 0, M26 makes it unable to count failures, M27 disables its `.ufo`/ledger scope check — all still print `pass=6 fail=0`, exit 0 on a passing tool. Proposal: extend `evaluate()` in `round42-digest-audit.py` to (a) run `selftest` on the exported tool and require exit 0, and (b) run a negative control — a copy with one corrupted expectation must exit 1 — so a selftest that cannot fail is itself detectable.
- **F7 (M15/M17 context) — contract-leg coverage of the unverifiable and external-rehash rows is seed-dependent.** At seed 42 no contract case contains a non-empty-note unverifiable row (both generated unv rows had empty notes → both mutant and reference say `ledger_bad`) and the only existing external file's digest is classified `blob` first (the file sits inside the scanned dir, so its digest is in the blob set). Both mutants were still caught — by selftest and live — but the contract leg alone would not catch them at this seed.
- **F8 (adjacent defect the mutants surfaced — lane content, exact file/line): `corpus/lessons/round-38.md:51` cites a 65-hex-character "sha256".** The backticked value for "SOURCES.append.md sha256" is `3ad0df68e8423a3b1b99d4e3b8d8c6271f7a4f4c96d3a5ad4e0a85a991ce234ff` — 65 chars (65th char `f`), hashes nothing, is in no blob (`cited-in-blobs: False`), and matches neither the verified ledger digest `3ad0df68504e1f49a0ab23e68b2034a9d6258345468fa03013737ced7ce234ff` (registry/digest-ledger.tsv row 3, external, staged `merge/kama/SOURCES.append.md`) nor any blob prefix. `digest-ledger.py` cannot see it by design: the hex-boundary lookarounds (:52) make a 65-run a non-token — which is exactly why M01/M02 die on the live leg (`tokens=97 blob=86 … unknown=1` vs reference `tokens=96 …`). This is the round-38 S472 phantom-digest failure class in miniature. Proposed fix (for the integration owner, not this seat): correct the round-38.md citation to the ledger-verified digest, and/or add a selftest case pinning the boundary contract (a 65-hex run adjacent to hex must not be counted as a token).
