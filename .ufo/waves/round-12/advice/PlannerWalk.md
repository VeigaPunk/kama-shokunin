## Design intent, blind spot, and general invariant

The source comments show the round-11 gate was designed to detect incomplete provenance supplements and mutations of original knowledge-file prefixes, and the runner was designed to preserve its fixtures and expected outcomes. **[INFERENCE]** The green reproduction therefore overfit the single captured SOURCES artifact to an integrity test: it answered “are these bytes still the bytes named by this expected-digest file?” but not “are these the bytes at the declared historical Git object?” The source revision field looked like provenance but supplied no enforced relation in the runner. The control set is valuable for the gate it tests; it is not a source-capture fidelity control.

The reusable gate invariant is two independent assertions, per frozen source input: (1) **digest integrity** — snapshot bytes match the digest in the trusted manifest; and (2) **source correspondence** — snapshot bytes exactly match the blob selected by the independently pinned commit and path. A matching self-reported digest alone cannot establish origin. The final clean verdict must require both assertions; a content mismatch must not be relabeled as manifest tampering, and an unavailable source must remain distinct. The round-12 interface appropriately names these separately (`source_mismatch`, `snapshot_tampered`, `source_unavailable`, `clean`) and fixes the source commit/path; the old capture is to remain immutable and be observed without a manifest when demonstrating its mismatch.
