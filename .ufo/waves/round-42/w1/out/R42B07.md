## 3. Can the ledger row be upgraded? Yes for both — measured, with three traps

Classification is `blob` first (`tools/digest-ledger.py:79`), and the blob set is *every blob reachable from the revision* (`tools/digest-ledger.py:17`), i.e. history included. So committing the fetched bytes once makes each digest a blob at that commit **and at every descendant**, permanently — the row is then redundant rather than merely re-argued.

Measured in a fixture clone of the lane at `3d9bd8d` (toplevel verified), copies placed under `.ufo/waves/round-42/c2/evidence/` (a `.ufo/` path is outside the document scan, so the copies add no tokens):

| fixture state | tool output | exit |
|---|---|---|
| base `3d9bd8d` | `tokens=96 blob=86 … unverifiable=5 … unknown=0` | 0 |
| **copies committed, rows untouched** | `tokens=96 blob=88 external_ok=4 external_absent=0 unverifiable=3 wrong_flagged=1 ledger_bad=0 wrong_unflagged=0 unknown=0` | 0 |
| rows dropped, **no** copies (trap 1) | `… blob=86 … unverifiable=3 … unknown=2` | **1** |
| rows → `external`, path absent (trap 2) | `… blob=86 … external_absent=2 unverifiable=3 … unknown=0` | **0** |

Read against the frozen legs (`tools/round42-digest-audit.py:320-321`: live requires equality with its own reference plus `ledger_bad=0 wrong_unflagged=0 unknown=0 external_ok>=4`; `exit_of` at `:145-147` fails only on `ledger_bad+wrong_unflagged+unknown`):

- **Row 1 (order).** Dropping the rows before the bytes land turns both tokens into `unknown`, which is a failing class: `unknown=2 exit=1` → the audit's live leg goes 0 and `met=False`. The bytes and the row change must land in **one** commit.
- **Row 2 (the counter cannot see a laundered row).** Reclassifying `unverifiable` → `external` with a path that does not exist yields `external_absent=2` and `exit=0`: `external_absent` is in no failure set, and the live leg only demands `external_ok>=4`. So a seat could claim an upgrade it never performed and the C2 counter would still read `met=True`. Proposed (round-43, not now — the counter is frozen): add a leg asserting that a digest classified `unverifiable` at base is `blob` at the tip unless its `external` path exists and re-hashes — that is host-independent and needs no network. Cheaper interim check for the closure: `grep -P '^\S+\texternal\t' registry/digest-ledger.tsv` and confirm each `path` exists on the measuring host.
- **Row 3 (jj's 1 MiB cap).** `stories260K.gguf` is 1185376 B = 1.13 MiB. A named *directory* is tracked like `git add <dir>`, and jj's `snapshot.max-new-file-size` silently refuses files over 1 MiB — the helper warns after the fact (`scripts/hyaku/jj-lane.sh:719-722`) and the round-25 lesson records exactly this ("One 1.4 MB log over the 1 MiB new-file limit was skipped by that directory commit and committed by name", `corpus/lessons/round-26.md:90`). A named *file* is tracked with `--include-ignored`, which admits files over that cap (`jj-lane.sh:655`), and only files over 10 MiB need `--allow-large` (`jj-lane.sh:638-639`). So the GGUF must be named explicitly in the commit or the upgrade half-lands: the bytes would be absent while the rows are gone → trap 1. `gguf.md` (43 KB) is unaffected.

Precedent that the lane already binds digests to committed bytes this way: C3's copies `.ufo/waves/round-42/c3/{vllm-v0.32.0-kv_cache_utils.py,llamacpp-704366d7-server-models.cpp}` (111612 and 117111 B) hash to `af4164bc…e57a` and `9c5a6f2c…8b4a`, which are exactly the digests carried in the S478/S479 anchor cells (`corpus/SOURCES.md:231-232`), and `tools/round42-capacity-audit.py:160-168` fails the row if the committed copy's sha256 is absent from the anchor.

**Licensing caveat for the GGUF (decision for the L1, not mine to take).** `ggml-org/models-moved` declares no license (`cardData.license` is `null`, no license tag), consistent with `corpus/SOURCES.md:51` "no license declared"; the ggml repo at `da8e2a54` is MIT (`LICENSE` fetched, `http=200`, 1078 B, sha256 `94f29bbe…010d`). Committing 1.13 MiB of unlicensed weights is a redistribution choice the lane has not made before; committing the 43 KB MIT doc is not. If the L1 declines the weights, the honest residue is a dated re-hash receipt (the one below) with the row left `unverifiable` and its note upgraded to name the URL, byte count, digest and date — but per the claim's own `out_of_counter_limit` a note does not make a digest true, so that option leaves the class unchanged.
