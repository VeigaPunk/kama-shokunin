## Findings by severity

### M1 — Crash: tag_regex group capturing non-digits → uncaught `ValueError`, exit 1 (input outside contract domain)
- Contract declares `tag_regex is a Python regex with >=1 capturing group of digits` (audit.py:10). The tool checks regex syntax (pin-watch.py:67–70) and group *count* (pin-watch.py:71–72) but cannot statically check digit-ness. At run time, any upstream tag that fullmatches with a non-digit capture crashes `release_tags` at pin-watch.py:87 (`tuple(int(g) for g in m.groups())`).
- Run (fixture regex `v(\w+)`, tags `valpha`,`v12`): stdout empty, stderr `ValueError: invalid literal for int() with base 10: 'alpha'` + traceback, **exit 1**. Exit 1 collides with the contract's `behind` code (audit.py:24) — a cron/human keying on exit code alone would misread a crash as "recheck the pinned sources".
- The reference crashes identically (`ValueError` at audit.py:113), and the counter's `main` catches only `EvalError` (audit.py:322–325) — read-established, not run: a poisoned registry regex would traceback the whole counter instead of emitting `exit 2 could not evaluate`. The frozen fixtures cannot produce it: `make_case` emits only digit-run groups (audit.py:142, 151).
- Not a contract violation (the input is out of domain), but the sharpest operational risk found. If ever hardened, tool *and* frozen reference must change together or the byte-equality leg breaks.

### M2 — Tool/reference divergence: whitespace-padded cells (tool strips, reference does not)
Tool strips all five cells (pin-watch.py:63 `(c.strip() for c in cells[:5])`); reference stores them raw (audit.py:83). The contract text is silent on padding; the reference is the byte-arbiter.
- `space_pin_cell` (pin cell `" v1.2.3 "`): tool exit **0** `status=current`; reference exit **2** `pin= v1.2.3  … status=missing`. Exit code and lines diverge.
- `space_regex_cell` (regex cell padded): tool exit 0 `current`; reference exit 2 `newest=- … missing` (padded regex never fullmatches a tag name).
- `space_engine_cell` (engine cell `" e "`): exits agree (0/0) but lines differ (`engine=e` vs `engine= e `) — byte inequality, which is what the contract leg compares.
- Impact today: none — registry cells are clean and fixtures are generated unpadded (`pins_text`, audit.py:180–183). Latent tripwire: if a human later pads a registry cell, the **live** leg fails on tool-vs-reference byte comparison (a correct failure, but with a confusing `detail:` line).

### L1 — Tool stricter than the frozen contract: duplicate engines refused
`pin-watch.py:64-65` raises `PinsError duplicate engine` → graceful stderr + exit 2 (pin-watch.py:209–210). The frozen contract (audit.py:8–26) never requires engine uniqueness — only the tool's own docstring does (pin-watch.py:7 "unique name"). Reference happily evaluates both rows (probe: 2 lines, exit 1 vs tool exit 2). Defensible (a duplicate row makes `DIR/<engine>.txt` lookup ambiguous), but it is an undocumented-in-contract refusal; worth one contract line next round.

### L2 — Reference laxer than the contract: zero-group regex accepted
Contract declares ">=1 capturing group" (audit.py:10). Tool enforces it (pin-watch.py:71–72, exit 2 `tag_regex needs a capturing group`); reference evaluates with empty-tuple keys (probe `v\d+\.\d+`: exit 0 `current`). Tool is the contract-correct side; fixtures always carry one group, so latent.

### L3 — Indented comment line: both refuse, differently
`" # x"` is not a comment for either parser (`startswith("#")` only — pin-watch.py:55, audit.py:76). Tool: `PinsError … :2: expected 5 tab-separated cells`, exit 2. Reference: `ValueError bad pins row: ' # x'` (would crash the harness leg if reachable — fixtures can't emit it). Safe direction (refuse, never misparse), different mechanism.

### Observations (agreeing, no divergence)
- Header/data rows with >5 columns are silently truncated to 5 by both (`split("\t")[:5]`, pin-watch.py:56/63, audit.py:77/83) — consistent with each other, outside the 5-column contract shape.
- A 3-field tag line `sha\trefs/tags/v1.2.3\tjunk` is ignored by both (reference `len(parts) != 2`, audit.py:91; tool's fullmatch fails on the tab-bearing name) — identical output under digit-group regexes.
