## 5. Defect found in the r41 claim commit (the reason the C1 counter flipped under me)

**The r41 counters leak a full 253 MB export of the repository into `/tmp` on every invocation and never delete it.**

`tools/round41-scorecard-reconcile.py:184-186` and `tools/round41-pinwatch-audit.py:208-210` each do `export = tempfile.mkdtemp(prefix="r41c1-"/"r41c2-")` then `tar -x` a `git archive` of the whole tip into it. Neither file contains `rmtree`, `shutil.rmtree`, or a `finally` block:

```
$ grep -n "rmtree\|finally" tools/round41-scorecard-reconcile.py tools/round41-pinwatch-audit.py
(no output)
```

Measured on this host: one C1 invocation leaves a **253 MB** directory behind (`du -sh /tmp/r41c1-c7ka8imk` → `253M`), and `/tmp` free space fell by **866 MB** across a single invocation. At the peak I observed **104** `/tmp/r41c1-*` and **170** `/tmp/r41c2-*` directories totalling ≈ **63 GB** (r41c1 ≈ 20.7 GB, r41c2 ≈ 43.3 GB), against a 128 GB `/tmp` filesystem. The committed tree itself is 234,905,600 bytes as a tar and 253 MB extracted — the export is the *entire* lane history, including `.ufo/waves/round-15/run-*.json` at 2.8 MB each.

**This is what made the C1 counter's verdict non-deterministic.** With `/tmp` at 100 % (35 MB free), the same counter, same tip, same command produced:

```
axes=6 facts=24 hash_bad=0 lines_bad=0 run_bad=1 dead=0 score_bad=0 hollow=0 mismatches=1 met=False
detail: operability run `python3 tools/report-landing-audit.py --selftest` no stdout line == 'selftest cases=79 failed=0' (exit 2)
exit=1
```

`report-landing-audit.py --selftest` failed with `[Errno 28] No space left on device` when I ran it directly at that moment; minutes later, after space was freed, it returned `selftest cases=79 failed=0` and the counter returned `met=True` again. So the counter's `met` value depends on host disk headroom, not only on the tree it measures. `report-landing-audit.py` writes a temp blob dir per selftest case (`/tmp/report-landing-selftest-*`), so the C1 counter inherits that dependency.

This matters for **calibration** (a frozen counter whose result moves with host state is not a measurement of the repository) and for **operability** (a counter that fills the disk will break other lanes' fixtures — and this host's `/tmp` reached 100 % during this round, with sibling lanes' temp dirs at 14.5 GB (`/tmp/r35audit13`) and 4 GB (`/tmp/tameshi-r45-ExecGtestMirror`)).

Two aggravating details: the write-cap failure mode is a **crash, not a clean exit 2**. Under `ulimit -f 100` the export step dies with `subprocess.CalledProcessError: … SIGXFSZ: 25` — an uncaught traceback, exit 1, where the counter's own contract (`tools/round41-scorecard-reconcile.py:38`) says exit 2 means "could not evaluate". And the sibling tool `tools/instrument-agreement.py` shows the fix shape the lane already knows: `shutil.rmtree(d, ignore_errors=True)` at lines 63 and 112. `tempfile.TemporaryDirectory()` would be the one-line equivalent.

## 7. Recommendation — the next round's candidate

**Recommended candidate for round 42: build the mechanism half of `considerthese/2026-10-25.md` proposal 1 — a tool that re-derives every digest a lesson or SOURCES row cites, and cross-checks every S-id named in lesson prose against the registry row it names — with a `TemporaryDirectory`-scoped export and a control that fails when the digest is wrong.**

Why this one, in order of weight:

1. **It is the only proposal in the entire 28 with a lane-internal falsification naming it as the top candidate.** `R40F05.md` §5 and `R40S09.md` both say so: *"The S-id cross-check is the strongest candidate for a future round, being the half of proposal 1 with no instrument at all."* Round 41 did not build it; round 42 can, at no extra source-finding cost.

A digest/S-id re-derivation tool is a *self-assessment vs observed state* instrument — exactly the calibration predicate shape of C1.

A daily driver is the only thing that removes that latency, and `R40F05.md` says C1 *"does not shorten it."*
4. **It is cheap and low-risk.** `tools/citation-provenance.py` already implements the token-parse + `git cat-file` + digest-compare mechanics; `corpus/SOURCES.md` currently holds **0** `cite(` tokens, so the extension is additive (`registry/required-citations.json` is a plain 17-row list). It needs no network, no runtime, no endpoint.
5. **It closes the r41 lesson's own overclaim** — if proposal 1's mechanism exists, the r41 sentence *"Proposal 1 was applied in round 40"* becomes true and needs no correction; if it does not, the sentence needs the append-only correction §3.9 recommends.

**Runner-up (proposal 4 of 10-24, "count attempts and restarts per round"):** also cheap and lane-owned, and it is the one 10-24/10-23 proposal with a criterion (KQ47) and a receipt already in place — only the consolidated per-round table is missing.
