## 1. Why a shortcut exists: what the counter derives from where

`tools/round42-selfdesc-reconcile.py` (frozen at `0bfd47a`) never compares the head to an independent registry. Every "observed" value it prints comes from **another author-written block of the same file**:

| Leg | Code | Derived from |
|---|---|---|
| banner | `:186-190` | four substring tests on the text before the first `## ` |
| planned | `:192-201` | first `## Planned` section body + a file-wide search for a `### Planned (round N+1)` line followed by a numbered item |
| retired | `:203-206` | `len(vector)` and `len(names)` — both from SCORECARD itself |
| saturation | `:209-221` | `vector` (`:169-176`, the §Axes table) and `firsts` (`:178-180`, the highest canonical list) |

| readme | `:254-257` | `git ls-tree` top-level names (the one genuinely tree-derived leg) |
| province | `:259-263` | `tools/`/`registry/` tokens inside the **canonical list's own evidence cells** |

Two mechanical consequences: (a) §Axes, §Saturation, §Retired, §Capabilities and the canonical list are all the *same* author-controlled data, so the head is checked against itself; (b) every count/fact leg is "must match **if stated**", so the cheapest satisfaction of a stale number is to delete it.

## 6. Defects found (file:line, command, proposed fix)

**D1 — the head is reconciled against itself, not against the tree.**
`tools/round42-selfdesc-reconcile.py:169` (`axes = m41.axes_table(sc)`), `:178-180` (`canon`, `names`, `firsts`), `:259-263` (`province` reads the canon's own evidence cells). Command: §3/§5 above (`R42A13/shortcut-S1b.c1.out`). Because the canonical list is author-written data *in the file under test*, a one-row round-42 canon makes caps/retired/saturation/province pass with no tree contact at all.
*Fix:* derive the capability set from an out-of-band, machine-checkable source — e.g. a `registry/capabilities.tsv` whose rows must each name an artifact that `git cat-file -e` finds at the tip — and require the head table to mirror **that**, not the file's own prose; require the canonical list's evidence cells to be non-empty and to name at least one existing path.

**D2 — the census-count leg is satisfied by omission.**
`tools/round42-selfdesc-reconcile.py:227-229` iterates `re.findall(r"\b(\d+) (opened|mined|queued|rejected)\b", cs)`; with no numbers present the loop body never runs, so the leg reports 0. Isolation (canon shrink in place, base numbers restored in the head row): `caps=3 mismatches=3 met=False` — `R42A13/isolation-deletable-counts.c1.out`; delete the numbers (S1b) and `caps=0`.
*Fix:* make presence a requirement — assert at least one match per category (or that the exact derived sentence `N opened, N mined, …` appears), so the leg cannot be satisfied by deleting the claim.

**D3 — the plan leg accepts a mention, and the numbered item need not be in the section.**
`:192-201`: `ph in pl` is satisfied by the string `### Planned (round 43)` appearing in backticks inside a superseded paragraph, and `idx = [i for i, l in enumerate(lines) …]` searches the **whole file** for the heading + numbered item. At base the heading `### Planned (round 42)` already exists at `SCORECARD.md:2184`, authored by round 41 — so the "live plan" the shortcut points at is the previous round's plan, untouched. Cost: 1 line.
*Fix:* require the numbered items to sit inside the `### Planned (round maxN+1)` block, require the block to live in the last round section, and require each item to name an axis and a counter path (`tools/round<N>-*.py`).

**D4 — the relevance needle and the r41 "strong" leg are both satisfiable by a self-referential fact.**
`:265-268` (needle is a substring of the command text) with `tools/round41-scorecard-reconcile.py:182-206` (any run fact counts as `strong`). My variant replaces every evidence cell with `run \`grep -c '<needle>' SCORECARD.md\` → \`N\``; `facts` drops 24 → 6 and both counters stay green. This extends, and does not replace, R42A05's finding (`R42A05.md` §4: `echo <needle>` satisfies `rel` on the *tip* tree): the same mechanism also licenses deleting the hash/line/path evidence, so `rel=0` can be bought with a *negative* net line change.
*Fix:* as R42A05 §4 (derive `OUT` in the counter) **plus** a floor on the fact base — require ≥2 hash-or-run facts per axis and reject run commands whose only input is `SCORECARD.md`/`README.md`.

**D5 — C1 is not separable from C2/C3, contrary to the frozen contract.**
`preregistration.json:66` states "C1's frozen rel needles name only files that exist at base … so C1 needs neither C2 nor C3 to have landed." The derived legs contradict this: `retired` needs `len(names) capabilities`, `saturation` needs `firsts`, `caps` needs the head to equal the highest canon — all of which C2 changes when it appends the `digest-ledger` row, and `province` then also gains `tools/digest-ledger.py` / `registry/digest-ledger.tsv`. Measured, on my own fixture, with **no C1 edit at all**: honest-minimal C1 `met=True` (`c3f40a5`) → add only C2's round-42 canon row → `mismatches=5 met=False`, exit 1 (`R42A13/separability-c2lands.c1.out`: `retired: does not state '8 capabilities'`, `saturation: does not state 'first-working rounds 10, 14, 16, 20, 25, 30, 41, 42'`, `caps: head names […] != canon (round 42) […]`, `province: PROVINCE.md lacks tools/digest-ledger.py`, `…registry/digest-ledger.tsv`). The real lineage shows the same class of coupling from the other direction: at `dd9f5dc` — the commit that first landed all three claims' work — C1 read `mismatches=1 met=False` (`r41=1`: adjacency fact said `14`, C3's `cross-lane-scope.md` edit made it `16`), and only `2793eb5` made it green.
*Fix:* either measure C1 at a commit where C2/C3 are absent (a C1-only tree), or drop the count-restating facts from C1's predicate and check them only at the measured tip under an explicit ordering rule.

## 7. Implication for C1's admissibility

1. `met=True` at `c8c92db` is **reproducible and necessary** — I re-ran the positive control and it matches `c1/candidate.out` exactly.
2. It is **not sufficient** for C1's stated type ("self-assessment vs observed state"). Four of the six head legs are comparisons against the same file, and every count/fact leg is a "if stated, must match" check whose cheapest satisfaction is deletion or self-reference. The only leg that is genuinely tree-derived and not dodgeable is `readme` (`:254-257`, `git ls-tree`), and it is satisfied by a one-line list — which is true, so it is harmless, but it carries no calibration signal either.
3. Concretely, the *admissible* reading of the measured receipt is: "the head no longer contradicts the tree in the six sampled respects, and the r41 fact base re-derives at the tip" — not "the self-assessment matches observed state". The closure should require a reviewer to confirm by hand the two things the counter cannot see: that the head's capability set equals the instruments that exist (7 at base, 8 at the tip), and that `PROVINCE.md` names them **in §Owns**, not in a footnote (the round-41 routed defect 2 is satisfied by the landed claim — `grep -c -F 'tools/pin-watch.py' PROVINCE.md` = 1 at `c8c92db` — but a footnote anywhere in the file also passes, as my honest-minimal variant shows).
4. Calibration consequence: the honest claim's `122` inserted lines are not evidence of rigour, and the shortcut's `15` are not evidence of haste. Line cost carries no signal here; only the *content* checks (capability set = instruments present, facts not deletable) do. The round-41 lesson already records that "the counter can be met by low-cost edits (`R41A06.md`)"; this round shows the low-cost edit can now also **remove** the evidence and shrink the capability list while both counters stay green, so the same finding has grown from "weak evidence" to "counter-rewarded retraction".
