## Findings
**B1 BLOCKER — probe identity is not owned: a doctored rev prints the predicate verbatim.**
The counter prints `probe_sha256` but never compares it to anything (`tools/round91-answer-time.py:267`); it runs
`git show <caller-rev>:tools/kama-probe.sh` (`:241-247`). A commit whose only change is "examine the last served
id" scores `cells=12 mismatches=0 positive_mismatches=0 probe=rev`, exit 0 (step 4). Every field of the frozen
line is satisfied; only the caller-supplied rev differs from M. Correction for a later round (predicate stays
frozen): refuse (exit 2) unless `probe_sha256 == 0aa43573…` (or equals `git show <frozen M>:tools/kama-probe.sh`).

**B2 BLOCKER — every large cell puts the expected id last, so "scan all served ids" is untested.**
T1/T3/T4 end with `good`, T2 has no `good`, T5 has exactly one id (`tools/round91-answer-time.py:203-208`).
g1 (`model_matches` and `router_match` read `tail -n 1` only) scores 12/12, exit 0. Held out, `good` first or in
the middle: M = `MODEL_OK matched`, g1 = `MODEL_MISMATCH served-id-mismatch` (`heldout.out`, H1/H2). The lane's
77-row harm matrix cannot see it either (77/77 for g1): its only 2-id rows put the match second
(`ReadyControls.second-data-id-match`). A router that lists `good` before other models gets a false
MODEL_MISMATCH from a probe that this counter calls green.

**B3 BLOCKER — the normalize rule is only ever tested on one-id answers.**
g3 replaces the rule for any served text > 1 MB with `grep -qF "$exp_n"` (no directory drop, no `.gguf` strip)
and scores 12/12, exit 0; the harm matrix also passes it 77/77. The rule itself is graded only by P2/P3/P5, each
a single id. So C1's "same rule at scale" is unverified by either gate.

**B4 BLOCKER for the counter, mitigated by K2 — `router_refine` is unobservable.**
g5 makes `router_refine` return immediately: 12/12, exit 0, T3 still `MODEL_OK matched`. T3's verdict comes from
`model_matches` (`probe-M.sh:944-955`); the only router status in any cell is `loaded`, which returns without
setting `RT_*` (`probe-M.sh:814,820-822`). The harm matrix does catch this (72/77, the 5 `RouterUnloaded.*`
rows), so the defect is in the counter, not in the overall gate.

**D1 DEFECT — count caps above 200 001 ids are invisible.** g2 caps at 210 000 ids and scores 12/12; a 250 000
cap passes the same way. The largest cell is 200 001 ids, while 4 MiB ÷ 16 B per minimal entry ≈ 262 144 and a
250 001-id body measures 4 000 042 B (computed) — under the cap. Every cap in 200 002…262 144 is therefore both
reachable and undetected. The claim says "no count cap"; nothing tests it.

**D2 DEFECT — `served_model` (the `paste -sd,` join) is never read.** The grader reads only verdict, reason and
seconds (`tools/round91-answer-time.py:195-199`). g6 truncates `C_SERVED` to 200 ids → 12/12, exit 0; held out,
M emits 200 001 ids, g6 emits 200 (`heldout.out`). Harm-matrix rows all have ≤2 ids, so g6 passes 77/77 too.

**D3 DEFECT — "linear time" is not owned, only a 20 s wall clock.** g4 sorts (n log n) before the scan → 12/12
at ≤1.67 s. g7 adds 17 s of dead time to the correct rule → T1 18.41, T2 17.77, T4 18.40 s pass; T5 fails at
20.02 s by 0.02 s (load 31). A probe up to ~8× M's time passes, and the boundary is load-dependent.

**D4 DEFECT — numeric-string coercion is untested.** g9 drops `return s ""` / the `BEGIN … ""` → 12/12, exit 0,
and 77/77 on the harm matrix. Held out, ids `1e3` vs `1000` and `010` vs `10`: g9 says `MODEL_OK matched`, M
says `MODEL_MISMATCH` (`heldout.out` N1/N2). M is right; nothing in the gate distinguishes the two.

**N1 NOTE — P5 is the one cell that owns the S592 sourcing choice.** g8 passes the expected id with `awk -v`:
P5 fails (`positive_mismatches=1`), because gawk turns `q"b\s` into `q"bs` (length 5 → 4). The ENVIRON
requirement is genuinely covered by exactly one cell.

**N2 NOTE — environment not pinned.** The counter passes the inherited environment (`:251`): `PATH` decides
`HAVE_PY`, and the probe's grep fallback, the python-free path, `models[]`/`name`/`model` keys, CRLF/NUL ids,
duplicate ids and wildcard-at-scale are never exercised (the last five are disclosed held-out in the claims).

**N3 NOTE — probe isolation.** The probe is copied alone into a temp dir and run from `work/probe-cwd`
(`:238-251`); `SELF_DIR`/`REPO_ROOT` (`probe-M.sh:93-94`) then point into the temp dir. Harmless today (unused),
but a probe that reads repo files would be silently mis-rooted rather than reported.

**N4 NOTE — grader surface.** `parse_row` takes `rows[0]` and the check ignores the probe's exit code, table
output and extra rows (`:181-199`). K3 (counter bytes frozen) holds by inspection — `5d0fe009…` at F and at
HEAD — but the counter does not self-check.

**N5 NOTE — load margin.** M's worst cell was 2.03 s at load 7.5-10 and 2.85 s at load 29-46, i.e. ≥7× headroom
under the 20 s budget; no false red for M was observed.
