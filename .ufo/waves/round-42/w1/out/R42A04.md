# R42A04 — C1 counter mutation study: 33 mutants, 24 killed by the frozen controls, 9 survive all of them

**Verdict: the frozen C1 controls are strong — 24 of 33 single-site mutants of `tools/round42-selfdesc-reconcile.py` change at least one committed control receipt — but 9 survive every committed control *and* the positive control: four disable the `receipts` leg (which never fires on any committed tree, including the claim tip — no control ever exercises a missing `.ufo/` citation) and five exploit checks that bind nothing today (`SAT_LINE` from above, first-vs-last integer, canon tie-break, substring headings, latest-round regex). Separate defect **F1**: the committed `controls/sep-c1-only.c1.out` is stale — it records the pre-decouple output (`r41=2 met=False`), the frozen counter reads `met=True` on the equivalent tree at the frozen tip, and `corpus/lessons/round-42.md:51` claims that file "reads `met=True`", which the committed bytes contradict.**

Scope: findings and drafts only; no lane, clone, or fleet file was edited. All writes were in `/fast/scratch/kama-r42/seats/R42A04/` (removed at the end) and this report + `R42A04/` artifacts dir.

## 2. F1 — committed `sep-c1-only.c1.out` is stale (control-bookkeeping defect)

- **Committed bytes** (`.ufo/waves/round-42/controls/sep-c1-only.c1.out`, sha256 `6939038ec488ee4cabf0a2e88489148b419f6d263de3baee56a1968cdd384cec`, committed in `c8c92db`; `sep-c1-only.c1.before-filter.out` is **byte-identical**, same sha): line 2 reads `r41=2 … mismatches=2 maxN=42 met=False`, exit=1, with details `no stdout line == '220'` and `no stdout line == '35'`.
- **Rebuild** (frozen recipe: claim tip minus C2/C3 files, `corpus/SOURCES.md`+`corpus/README.md` reverted to base — verified: 218 `| S` rows, 34 knowledge `.md`, no `tools/digest-ledger.py`) scored by the frozen counter: `r41=0 … mismatches=0 maxN=42 met=True`, exit 0 (retained: `R42A04/out/pristine/PRISTINE-freeze.sep-c1-only.c1.out`).
- **Why:** `c8c92db` ("decouple head-table count facts from C2/C3 files") changed the two run facts the sep tree trips on — `SCORECARD.md:15` freshness now expects `218` (`… and int(l.split(chr(124))[1].strip()[1:])<=477`) and `SCORECARD.md:17` coverage now expects `34` (`… if 'engine-sides' not in f`) — but the committed sep receipt still records the pre-decouple expectations `220`/`35`. The receipt was generated before the text it must accompany was finalized and never regenerated.
- **Contradiction:** `corpus/lessons/round-42.md:51` (Mistakes, row *scope*) states "the regenerated `controls/sep-c1-only.c1.out` reads `met=True`" — the committed file reads `met=False`. The lesson is not backed by the committed bytes.
- **Impact:** (a) a verifier replaying the controls at the frozen tip gets a spurious mismatch on this one receipt; (b) as committed it cannot serve as a mutation reference — my study used the rebuilt pristine receipt as the sep-c1-only reference and marks those kills `s:c1*` below; (c) it does **not** weaken C1: `met=True` on a C1-only tree is the expected separability direction (preregistration `separability`: "C1 needs neither C2 nor C3 to have landed"), and the other two sep receipts (c2-only, c3-only → `met=False` for C1) reproduce exactly.
- **Proposed fix (L1, receipts commit):** regenerate `controls/sep-c1-only.c1.out` at the frozen tip with the frozen counter (expect `r41=0 mismatches=0 met=True` exit=0) and delete or regenerate the `before-filter` copy, which today is a byte-identical duplicate of the stale file and documents nothing.

## 4. The 9 survivors — mutants no committed control kills

**F2 — the `receipts` leg is unprotected (M17, M19, M31, M18).** On every committed control tree *and at the claim tip*, `receipts=0`: every `.ufo/…` token cited in the round-40/41 sections resolves. So the entire existence check can be switched off — `exists()` → True (M17), all sections exempted as `record corrections` (M19), the missing-path loop → `pass` (M31) — or widened (M18: scan round-42 sections too; they cite only `preregistration.json`, `controls/base.c{1,2,3}.out`, `.ufo/waves/round-16/live/receipt.json`, all present) without any frozen receipt changing. This is the exact failure mode round 41 closed on (R41A10 §1: "the round-41 SCORECARD evidence row points at receipts that do not exist"), and the frozen evidence never exercises it. *Proposed round-43 control (counter is frozen):* `junk-c1-danglingreceipt` — from the freeze stand-in, append to a round-42 section a line citing `` `.ufo/waves/round-41/does-not-exist.out` ``; the true counter must read `receipts=1 mismatches=41 met=False` (kills M17/M19/M31 via a round-40/41-section variant, and M18 via the round-42-section variant — put the dangling token in a round-42 section to kill both classes with one tree, plus a second token in a round-41 section if M18 and M17 are to be killed by the *same* tree).

**F3 — checks that bind nothing today (M03, M12, M15, M24, M34).**
- *M03:* the base head contains no `Latest measured round:` line at all, and the only committed trees where the line exists (junk-c1-textonly head, claim tip) state the correct number — a regex accepting any number is invisible. Proposed control: a junk tree whose head says `Latest measured round: 40.` while `maxN=41` (true counter: banner+1; M03: silent).
- *M12:* `min(ASSIGNED)=7 < 8` today, so any `SAT_LINE ≥ 8` behaves identically; the threshold is pinned only from below (M13, `SAT_LINE=7`, is killed by everything). If both assigned axes ever reach 8, a `SAT_LINE=9` counter demands `nudge active` where the prereg rule says inactive. Proposed control: junk tree with axes `operability 8 … calibration 8` and Saturation saying `nudge inactive` (true counter: saturation+2; M12: silent).
- *M15, M24, M34:* equivalent-today mutants (score cells hold a single integer; no two canon tables share a round number; no heading contains another heading name). Recorded as slack, not defects; they become live if cells gain secondary integers, two same-numbered canon tables appear, or headings gain suffixes.

**Where the kills come from (context for the L1).** M16 (r41 stub) is invisible to base/freeze *and* the positive control (`r41=0` on all three) — only the two junk shortcut trees with `r41>0` (sidefilesonly 2, falserel 1) kill it: the shortcut controls are what make the r41 leg tamper-evident. M09 (derived-count corruption) is invisible to base/freeze because both `6 axes` and `7 axes` are absent there; junk-c1-textonly (which *states* the counts) and the positive control kill it. M20 (needle loosening) changes only detail text on base/freeze/junk — its decision-level kills are the rebuilt sep-c1-only tree and the positive control (at tip the needle is satisfied by the `glob.glob('corpus/lessons/*verifier-spotcheck.md')` command inside the calibration row, `SCORECARD.md:18`). M26 shows the `exit=` line is part of the frozen evidence and pins the exit contract. 13 of 33 mutants are false-*fail* mutants (they would read `met=False` at an honest tip: M02, M05, M06, M08, M09, M13, M14, M20, M25, M28, M30, M32, M33) — every one is caught by `candidate.out`.
