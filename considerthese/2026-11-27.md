## Lessons from last 3 days

1. **Upstream lowered its own speculative-decoding acceptance-length floors, so its CI numbers are floors with slack, not reference measurements.** `6d54465e9` (#33127, 2026-11-26 16:36 BRT) edits only `tools/server/tests/unit/test_spec_methods.py` and lowers `min_accept_len` for every `SpecCase`: first case 2.7766 -> 2.65 (-4.6%), `dflash` 2.1687 -> 2.10 (-3.2%), `dspark` 3.1246 -> 3.05 (-2.4%), `eagle3` 1.5757 -> 1.50 (-4.8%), and the nightly `dflash2` 4.5414 -> 4.50 and `lilicorr` 5.4444 -> 5.40 (about -0.9% and -0.8%). `min_accept_rate` values did not change. (Percentages are my arithmetic on the diff.) The old four-decimal floors looked like measured values; the new ones are rounded down after CI misses ("relax Qwen3 DSpark acceptance length floor", then "relax threshold for all spec decs"). For the lane: any claim or cell that compares our acceptance length to upstream's test numbers should treat them as lower bounds that can move by a few percent between builds, and say which commit's table it used.

2. **Recurrent-model decode got faster right after the release, so v1.1.0 timing for RWKV / delta-net style models is already stale on HEAD.** `7b74cb92d` (#30139, 2026-11-27 08:15 BRT, `src/llama-graph.cpp` +37-7, `src/llama-memory-recurrent.cpp` +21, `src/models/rwkv6.cpp`, `rwkv7.cpp`, `delta-net-base.cpp`, plus a test in `tests/llama-context/cases-rs.cpp`) lets kernels read recurrent states directly from the cache instead of copying them first, "speeds up token output in the majority of cases and backends". It also adds a graph-reuse condition and a rule for speculative-decoding rollback snapshots so in-place reads don't clash with them. It is outside `tools/server`, so my path filter would have missed it; it matters for the server because slot save/restore and spec-decoding rollback both go through recurrent state. I have not measured the speedup. Consequence: an r101 pinned to `v1.1.0` stays a clean before/after pair with `v1.0.0`, but any recurrent or hybrid-model timing it records should be labeled "v1.1.0, before #30139".

3. **The released web UI can now send conversations off the machine, and PDF-as-image token cost became configurable.** `00d5c142c` (#32608, 2026-11-27 06:09 BRT, 100 files, none under `tools/server`) adds a Share action that uploads a conversation, or a branch up to one message, as a JSONL agent trace to a Hugging Face dataset. Per the commit message, a new dataset is public unless "private" is ticked, sign-in is OAuth (contribute-repos) or a pasted token, and the feature is in the builds upstream releases (prebuilt UI llama-server downloads, Docker images, npm package) but only in source builds with `-DLLAMA_UI_HUGGING_FACE=ON`. Llama Chat goes to 0.4.0. Separately, `436d7e81c` (#33061, 2026-11-26 10:57 BRT) adds a `pdfDpi` setting (default 108, clamped between a min and max, documented in `tools/server/README.md` as `--ui-config '{"pdfAsImage": true, "pdfDpi": 216}'` "for dense tables"). Doubling DPI quadruples pixels per page, so the image tokens a PDF costs now depend on a UI setting the server never sees. Neither changes server behavior; both change what a "default llama-server" deployment does, which the lane's knowledge files don't describe.

## Self-improvement suggestions

These are proposals only; I'm not acting on them. They avoid repeating `2026-10-19.md` to `2026-11-26.md`.

1. **Watch upstream test thresholds as a calibration signal:** each day, diff the `SpecCase` table in `test_spec_methods.py` (and any other `min_*` / tolerance constants under `tools/server/tests`) against the day before. A lowered floor means upstream saw a regression or noise it accepted; that is a cheap early warning for lane claims built on the same feature, and it costs one file read.
2. **Split timing claims by model family:** tag every lane timing or throughput number as attention-only, recurrent, or hybrid. Lesson 2 shows a change that moves recurrent numbers and leaves attention numbers alone; without the tag, one upstream commit makes a whole table look stale when only some rows are.
3. **A PDF-DPI token-cost cell for r101:** send the same one-page PDF as images at 72, 108 and 216 DPI to a vision model on llama-server and record `prompt_n` and prompt time for each. That gives a measured rule for "what does a PDF page cost" instead of the README's "good fit for dense tables".
4. **A "what leaves the machine" inventory for default builds:** one knowledge file listing every released-by-default llama-server/UI feature that contacts an outside host (Hugging Face share from lesson 3, the CORS proxy, MCP proxy and its private-URL flag from #32633, model downloads), with its default state and the flag that turns it off. That is a coverage gap today and a common question for anyone running the server for others.
