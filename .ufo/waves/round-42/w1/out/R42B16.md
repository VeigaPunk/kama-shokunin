## 3. Contested Scope

The sibling scan reveals three major areas where kama's current C2 design conflicts with fleet-wide architectural standards:

### 1. Host-Dependent Absolute Paths vs Hermetic In-Tree Resolution
- **Kama defect (`registry/digest-ledger.tsv:2-5`):**
  Kama hardcodes host-absolute paths into `registry/digest-ledger.tsv`:
  - Line 2: `/home/vgpnk/.local/opt/llama-b11755-bin-ubuntu-x64.tar.gz`
  - Line 3: `/home/vgpnk/.local/opt/llama-b11755/libllama-server-impl.so`
  - Line 4: `/home/vgpnk/Projects/shokuknow/merge/kama/SOURCES.append.md`
  - Line 5: `/home/vgpnk/Projects/shokunin/kama-shokunin/.ufo/waves/round-35/w1/out/ScribeGate/fetch/dockerfile.html`
- **Falsification in `tools/round42-digest-audit.py:330`:**
  Kama's counter enforces `live = (live_ref["external_ok"] >= 4)`. Preregistration line 44 explicitly concedes: *"external_ok counts only host-local re-hashes on the measuring host, so the live leg is host-dependent by design."*
- **Sibling standard:**
  `mori-shokunin` (`mori-pin-check.py:29`) requires: *"digest paths stay inside the measured tree."*
  `tameshi-shokunin` (`registry-check.py:38`) flags any absolute path under the live fleet root as `non_hermetic_argv` (exit 1).
  `kaidoku-shokunin` (`corpus/lessons/round-24.md:58`, M24-3) specifically resolved external `/tmp` paths by replacing them with an in-tree `repro/inputs.json` manifest. Hardcoded `/home/vgpnk/...` paths fail completely in any containerized or non-vgpnk execution environment.

### 2. Unbounded Regex Scraping vs Grammatical Context Binding
- **Kama overreach (`tools/digest-ledger.py:52,126`):**
  Scans all 64-hex strings in documentation indiscriminately. Any random 64-hex hex sequence—such as a synthetic fixture key, nonce, or test matrix hash—is treated as a file content hash. If not present in git blobs or the external ledger, it triggers `unknown += 1`, causing an exit 1 failure.
- **Sibling standard:**
  `kake-shokunin` (`scripts/citation_lint.py`, selftest mutant G) proves that unconstrained hex scraping overreaches on plain hex.
  `kumitate-shokunin` (`scripts/cite-check.mjs:1116-1185`) requires a marker keyword (`sha256`, `pinned`, `rev`) and associates the hash with its preceding target path (`ownerAt(offset)`). Unowned hashes are classified as `PIN_UNTYPED` (informational note), never fatal errors.

### 3. Out-of-Band Waiver Table vs Append-Only Supersession
- **Kama design (`registry/digest-ledger.tsv:6,7-11`):**
  Kama maintains an out-of-band TSV table to classify defective digests:
  - Line 6 marks S472's corrupt hash (`5585f602...`) as `class=wrong`, letting the bad hash persist in `corpus/knowledge/` and `corpus/SOURCES.md`.
  - Lines 7–11 mark five hashes as `class=unverifiable`, including deterministically computed hashes (such as `5b38422c...` from `tests/llamacpp-live/install-io-grid.py`, as confirmed by seat R42B09).
- **Sibling standard:**
  `tameshi-shokunin` (`corpus/knowledge/r44-anchor-refresh-rule.md:7-15`): Under `CORPUS.md` rule 2, a corrupted or drifted anchor in `SOURCES.md` must be corrected via an **append-only supersede row** (`supersedes S0NN —`), keeping both historical accuracy and active verification intact without out-of-band waiver files.
  `kumitate-shokunin` (`scripts/cite-check.mjs:1205`): A wrong hash in documentation is a fatal `PIN_MISMATCH`, not an excusable waiver.

## 4. Portable Lessons (What Sibling Lanes Already Hold That Kama Should Cite)

1. **Kumitate (`kumitate-shokunin/scripts/cite-check.mjs:1116-1210`):**
   *Lesson:* Grammatically bind content pins to explicit file citations (`ownerAt(offset)`). This prevents false positives on synthetic tokens, nonces, and fixture matrices, and provides an actionable error message specifying both the expected hash and the cited file.
2. **Tameshi (`tameshi-shokunin/tools/pin-disposition.py:8-12` & `corpus/knowledge/r44-anchor-refresh-rule.md:7-15`):**
   *Lesson 1 (Epistemic Boundary):* A matching SHA-256 digest proves byte preservation only; it never transfers execution verdicts, test passes, or environmental validity (`result_reuse=not_established`).
   *Lesson 2 (Append-Only Supersession):* Corrupted or drifted source anchors must be superseded by an appended row in `SOURCES.md`, ensuring that verification remains self-contained in the canonical document rather than outsourced to a separate TSV waiver ledger.
3. **Chousa (`chousa-shokunin/corpus/knowledge/receipt-expectation-digests-r40.md:13-19`):**
   *Lesson:* A file digest binds the complete byte stream (formatting, comments, newlines), not merely the logical rows cited. Verification tools must check self-digests and counter digests across multiple surfaces to prevent decoupled drift.
4. **Mori (`mori-shokunin/tools/mori-pin-check.py:27-29`):**
   *Lesson:* Digest verification paths must be confined strictly within the measured repository tree (`digest paths stay inside the measured tree`). External dependencies must be resolved via in-tree fixtures or workspace-relative parameters.
5. **Kengaku (`kengaku-shokunin/corpus/knowledge/ledger-route-telemetry.md`):**
   *Lesson:* Explicitly distinguish between retained byte preimages and unavailable historical artifacts using standard metadata annotations (`source-status: historical-unavailable`, `retained-evidence: baseline sha256... no raw bytes retained in-corpus`) rather than an opaque `unverifiable` tag.
