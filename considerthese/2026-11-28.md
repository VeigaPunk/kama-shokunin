## Lessons from last 3 days

1. **Losing a tool call when the model never closes its reasoning block is a recurring bug, now fixed for a third model family.** `f16e79da8` (#32993, 2026-11-28 08:22 BRT, `common/parsers/k2-horizon.cpp` +7-2, `tests/test-chat.cpp` +16) fixes #32972. K2 Horizon can start its `<ifm|tool_calls>` section without ever writing `</ifm|think>`. The old parser waited for the end tag, so the tool call stayed inside `reasoning_content` and never ran. Now it ends reasoning where the tool-call tag starts. The new test covers `reasoning_effort` medium and high with `reasoning_format` auto. The commit message says this is "the same pattern as #32232 (Gemma4) and #32271 (Ministral-3)". For the lane: this happens in `common/`, outside my `tools/server` path filter, yet it decides what `/v1/chat/completions` returns in `tool_calls`. Any lane claim like "model X does tool calling on llama-server" depends on the build and on reasoning effort, and a missing tool call with thinking on should be checked as a parser problem before blaming the model.

2. **A CUDA/HIP kernel limit broke MoE expert-bias adds above 65535 tokens in one launch.** `3ab385146` (#33162, 2026-11-27 11:42 BRT, `ggml/src/ggml-cuda/add-id.cu` +14-12) says ADD_ID took its grid y-dimension straight from the token count. gridDim.y tops out at 65535 on NVIDIA and HIP, so bigger launches failed with "invalid configuration argument". The kernel now caps the grid and loops over the rest, and a 70000-token case was added to `test-backend-ops.cpp` (the old cases stopped at 129). I have not checked which models use ADD_ID or whether a normal llama-server prefill sends that many tokens in one launch; at the default micro-batch size it should not. Consequence: on CUDA/HIP, any r101 cell with a very large micro-batch (`-ub`) or a single huge batch on an MoE model should record whether the build includes `3ab385146`, because `v1.1.0` does not.

3. **Upstream keeps loosening test tolerances, now for backend math as well as spec-decoding floors.** `0c2209c88` (#33238, 2026-11-28 07:49 BRT) gives `test_loop_ctrl` in `tests/test-backend-ops.cpp` a `max_nmse_err()` of `5e-3`, which the title calls "the fused mul_mat tolerance". With yesterday's `6d54465e9` (spec-decoding `min_accept_len` floors lowered), that makes two tolerance loosenings in two days. Yesterday's idea to watch thresholds should therefore cover `tests/test-backend-ops.cpp` `max_nmse_err` overrides, not just `tools/server/tests`. Also: two UI commits landed. `8e23278c7` (#33205) stops chat titles that come from the message itself from containing the full `[name](file:///abs/path)` text of an @-mention; the LLM title prompt still gets the full link. `6d8a8886f` (#33195) restyles markdown tables. Neither changes server behavior.
