### Reading the running server's identity and the disclosure ledger (round 51)

- In a replay result, `own_server` {path, dev, inode} is the replay's own extracted member `<work>/server/<member>`; the rerun receipt's `server_exe` {opened, path, dev, inode, size, sha256} is the image the live tool opened through `/proc/<pid>/exe`. They match only when dev and inode are equal and the bytes hash to the receipt's server digest: a digest alone says which bytes run, not which file (round-50 closure R6, seat J4Decoy exec'd the host's own b11909 install and met the digest-only check). A mismatch is printed as `server-exe:<reason>` (or `server-exe:sha256:…`, `server-exe:not-own-member:…`) and the replay exits 1. Stated limit: a byte-identical copy that is placed at the member path itself matches — the check binds the running image to the extracted file, not to the archive the copy came from.
- `python3 tools/append-only-audit.py --repo . --to <rev>` grades every deletion at the default threshold 1 (v5: 20). Status `disclosed` means every graded line of that event that is gone at `<rev>` is named in `registry/append-only-disclosures.tsv`; `restored`/`partial` mean the file got its lines back; `--json` lists what a missing row would have to name, per event, under `undisclosed`.
- A bad disclosure is not a warning: a row naming no event, naming no deleted line that is still unheld, naming more of them than that, or naming the wrong class makes the audit exit 1 and prints `disclosure <commit12> <file> <key12> bad: <reason>`. The ledger is graded evidence, not a permission slip — write rows from the tool's `undisclosed` JSON (`.ufo/waves/round-51/c2/build_ledger.py`), never by hand.
- The ledger itself is not append-only. A disclosed line that is later restored by append is then held at `<rev>`, so its row names nothing unheld and becomes an over-count, which the tool grades as a bad disclosure: remove that row when the line comes back. Regenerating the whole file from the tool's JSON is the safe form.
- A new in-place edit of an append-only file still exits 1 until it is restored by append (preferred) or disclosed with its mechanical class; `--disclosures FILE` points the audit at a ledger outside `registry/` for experiments.
