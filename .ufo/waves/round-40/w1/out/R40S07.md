## Runbook (L1 executes)

### Phase 0 — Timing and prep

1. Run the sweep **after the last seat result has landed and before the L1 report is
   written/committed** (prompt: "before the report"). If the wave adds more seats later,
   re-run Phases 1–6 before the final report.
2. Run every command with explicit `-C`; never rely on a process cwd. The L1 shell starts at
   the fleet root, which is exactly why relative paths misroot.
3. Write nothing except: (a) the restored lane copies, (b) one sweep log under `/tmp`
   (e.g. `/tmp/kama-r40-misroot-sweep.log`) if a log file is wanted, (c) the report's
   `## Mistakes` rows. Never write at the fleet root.

### Phase 1 — Fleet-root scan (`git status --porcelain`)

```sh
git -C /home/vgpnk/Projects/shokunin status --porcelain
```

- Exit code must be 0. Record the full output verbatim in the sweep log.
- **No pathspec** (prompt). A pathspec would hide the very plain files that misroot.
- Untracked entries appear as `?? <path>` (directories appear as one `??` line unless
  `-uall` is used). To see every untracked *file* inside untracked directories use:
  ```sh
  git -C /home/vgpnk/Projects/shokunin status --porcelain -uall
  ```
- Separately capture ignored entries (never swept):
  ```sh
  git -C /home/vgpnk/Projects/shokunin status --porcelain --ignored
  ```
  Ignored entries print `!! <path>`; they are not candidates and are never deleted.
- Modified tracked files print ` M <path>` (e.g. `.ufo/watchdog.log`, `.ufo/state/*`,
  `.scratch/*`). They are **not** candidates; never restore, stage, or delete them.

### Phase 2 — Classify untracked candidates

For each `??` path `U`:

1. **Skip excluded prefixes** (never a candidate, never deleted, never moved):
   - `.ufo/state/` (driver baselines), `.ufo/watchdog.log`
   - `.scratch/` (orchestrator-owned run state; names many lanes/rounds by design)
   - `.ufo/waves/hyaku/`, `scripts/hyaku/` (hyaku orchestration)
   - `.ufo/waves/round-<N>/` for any N owned by another round/lane — ownership is not
     kama round 40 (observed live: `.ufo/waves/round-30/` is untracked at r40 start;
     leave untouched, flag to the fleet owner if it persists)
   - `*.shokunin/` lane roots (ignored), `.jj/`, `.tower/`, `xconnector-scratch/` /
     `xsentinel-scratch/` trees
2. **Ownership test** for remaining candidates: does the content name kama or round 40?
   ```sh
   grep -lE 'kama|round-40|R40' "/home/vgpnk/Projects/shokunin/$U"
   ```
   - Match → in scope (continue).
   - No match, or content names another lane/round → out of scope. Never touch it;
     it is another lane's file (or unknown). Do not even move it: cross-lane cleanup is
     the fleet owner's call.
3. For an in-scope candidate, the canonical destination is the same relative path under the
   lane: `/home/vgpnk/Projects/shokunin/kama-shokunin/$U`.
   - If that lane path already exists and is **byte-identical** → the fleet copy is a
     duplicate; skip straight to Phase 4's deletion check.
   - If it exists and **differs** → do NOT overwrite and do NOT delete. Preserve both
     (copy the fleet copy to a distinct lane path, e.g. append `.fleet-root-dup`), record
     the collision, and flag it; never destroy either byte stream.

### Phase 3 — cmp verification and restore

For each in-scope candidate `U` whose lane destination is absent or identical:

```sh
mkdir -p "$(dirname "/home/vgpnk/Projects/shokunin/kama-shokunin/$U")"
cp -p "/home/vgpnk/Projects/shokunin/$U" \
      "/home/vgpnk/Projects/shokunin/kama-shokunin/$U"
cmp -s "/home/vgpnk/Projects/shokunin/$U" \
      "/home/vgpnk/Projects/shokunin/kama-shokunin/$U"
echo "cmp_exit=$?"
sha256sum "/home/vgpnk/Projects/shokunin/$U" \
          "/home/vgpnk/Projects/shokunin/kama-shokunin/$U"
```

- `cmp_exit=0` = byte-identical. This is the verification gate: **copy first, verify
  second, delete third — never in any other order.**
- If cmp exits non-zero (should be impossible immediately after `cp`), stop on that path:
  no deletion, investigate, record.
- Record both sha256 values so the sweep evidence is reproducible (matches round-23/33
  recovery precedent, where the byte-exact move recorded hashes and `cmp` equality).

### Phase 4 — The one allowed deletion rule

The **only** fleet-root deletion permitted anywhere in the round is:

> Delete an untracked file at the fleet root only when ALL of:
> (a) the file is in scope (Phase 2 ownership test passed — kama/round-40 content);
> (b) its lane destination now exists and `cmp -s` exited 0 against the fleet copy
>     (byte-identical restoration confirmed in Phase 3);
> (c) it is not under any excluded prefix (Phase 2.1).

```sh
rm "/home/vgpnk/Projects/shokunin/$U" && test ! -e "/home/vgpnk/Projects/shokunin/$U"
echo "deleted_exit=$?"
```

- After deletion, remove only empty directories the misroot created, up to the first
  non-empty ancestor (`rmdir -p` style); never delete a non-empty directory and never
  delete a directory containing another lane's files.
- Everything else is **never** deleted: tracked files, `.ufo/state/*` driver files,
  `.scratch/`, other lanes' files, ignored entries, untracked unknown-owner paths
  (e.g. `.ufo/waves/round-30/`), and any fleet copy whose lane counterpart is missing or
  differs (that path is a data-preservation case → keep, record, escalate).

### Phase 5 — Record under `## Mistakes`

For every deletion (and every collision/out-of-scope flag), add one row to the report's /
lesson's `## Mistakes` table (precedent: round-37 lesson misroot row):

| class | evidence | captured-by | fix |
|---|---|---|---|
| misroot | fleet path + sha256; restored lane path + sha256; `cmp_exit=0` | the wave-context absolute-path rule (stated, still missed) | wave contexts name the exact lane-absolute report path; the misroot sweep (git status at fleet root) runs before every report lands |

Also paste the exact commands run and their exit codes (Phases 1–4) so the sweep is
self-verifying, not prose (round-17 lesson F6 weakness: a prose-only sweep).

### Phase 6 — Post-sweep verification

```sh
git -C /home/vgpnk/Projects/shokunin status --porcelain
ls -l "/home/vgpnk/Projects/shokunin/kama-shokunin/$U"   # for each restored path
```

- Expect: every restored lane path present; fleet-root untracked set now contains no
  kama/round-40 artifact; the delta between the Phase‑1 and Phase‑6 scans equals exactly
  the deletions performed.
- Confirm the sweep wrote nothing at the fleet root (the only writes were the restored lane
  copies, `/tmp` scratch, and the report).

## Limits

- `git status --porcelain` cannot see empty directories; a misroot that left only empty
  dirs is invisible (round-17 sweep) — use `find` only to check a specifically identified
  residue, never as a broad sweep.
- The ownership grep reads content; a binary/undecodable candidate is classified by name
  heuristics; if ambiguous, treat as unknown-owner (leave).
- The sweep cannot see writes outside the fleet root: sibling lane dirs are ignored
  (`*-shokunin/`), and `/tmp`/elsewhere is out of scope.
- Seats that self-disclosed a move leave no residue; cross-check final messages/disclosures
  for "wrote at fleet root then moved" admissions so the Mistakes table records them even
  when the sweep finds nothing (round-16/17 precedent).
