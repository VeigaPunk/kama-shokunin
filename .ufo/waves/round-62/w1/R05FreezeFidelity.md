# Round 62 freeze fidelity — R05FreezeFidelity

Compared the frozen predicate in `.ufo/waves/round-62/controls/freeze.txt` with `git show master:tools/round62-c1-counter.py` and `git show master:tools/round62-c2-counter.py` at `65d7cad0fce90e34de37527cde22e97b63b118bf`. The docstrings copy the respective frozen predicate sentences verbatim (C1 lines 7–14; C2 lines 7–18). The audit below concerns whether executable conditions actually enforce each clause, not whether those sentences match.

## Findings

### C1 — actionable predicate/code gaps

- **“byte-pinned” tool — not enforced.** `main` reads the tool blob from the requested tip (343–354), but there is no expected hash or equality check against a separate frozen tool byte identity. The tip's own bytes are executed; the sentence doesn't state a digest value, but “byte-pinned” implies a stronger pin than selecting the supplied tip.
- **“sha256-verified model and server” — model verification is not independently re-derived.** `grade` compares receipt model/server `sha256` fields to constants (161–164); witness checks likewise compare claimed hashes (204–206). The counter does not itself hash model/server files. It relies on the receipt/tool's assertions for these fields. Thus this check only verifies recorded digest claims, not actual file bytes at the counter boundary.
- **“unregistered loopback port” — loopback is only partially enforced and registry check is absent.** The counter's own POST is hard-coded to `127.0.0.1` (67–70), but it does not independently prove the held server binds only to loopback or that its port is unregistered. It copies the endpoint-consumers registry if present (362–366), but no counter-side check consults it. `listener_owned` is trusted from the receipt for grading (159–160); the outside witness rechecks PID/port ownership via `port_owned_by` (204–205) but does not establish address binding or non-registration.
- **“pdeathsig child” — not enforced.** Teardown checks reject `child_pre_dead` and allow return codes 0/-15 (167–169), but neither this nor witness checks verify the child has a parent-death signal configured. A receipt assertion is not a check.
- **“receipt the counter re-derives from captured bytes” — substantially, but not completely.** Captured-body checks are recalculated from body bytes and body hashes (94–98, 100–158); however `listener_owned` is copied from the stored `checks` field (159–160), and model/server digests are compared as receipt metadata (161–164). Those graded checks are therefore not derived from captured bytes or counter-measured facts.
- **“every graded check recomputed true and agreeing with the recorded verdict” — mismatch: recorded verdict is not linked to per-check recorded verdict.** `grade` marks inconsistent only when a check's stored `passed` is non-null and differs from recomputation (173–183); absent/null `passed` fields do not count as disagreement, and required check membership alone is enforced. Overall recorded `receipt.verdict == REQUEST_OK` is required (193), and all recomputed values must be true (192), but the `checks[*].passed` values are not required to exist/be booleans. Also the frozen clause's “verdict” singular may mean overall verdict, which is checked.
- **“live answer bound to served alias, build fingerprint and fresh nonce” — mostly enforced by witness.** It checks status 200, model and alias, matching PID/port, fingerprint regex, text string, nonce included in prompt, listener ownership and model/server hash constants (194–206), then ties completion capture model and server hash to witness (207–212). This does not establish that the observed answer text is causally responsive to the nonce (only that a string was returned while sending a nonce-bearing prompt); nor does the regex prove the fingerprint is the build fingerprint for the server executable beyond the receipt's stated server digest.
- **“during the hold window” — timing not explicitly checked.** Witness sends after observing `hold/hold.json` (221–244), then releases the hold and waits for process (continuation of `witness_run`). It does not verify server is still alive/listening after the POST; `listener_owned` establishes ownership at the witness check point. No explicit held-state/released-state ordering evidence is independently verified.
- **“all 16 controls are rejected, errors=0” — enforced at the summary gate.** The family total and rejected count must each equal 16 and `errors` must be empty (474–484). Error count is the accumulated setup/live errors, not arbitrary exceptions swallowed within helpers.

### C2 — actionable predicate/code gaps

- **“each ... appears exactly once ... in the newest canonical capabilities section ... with its frozen row prefix” — exact-once enforcement is incomplete for expected capabilities.** `canonical_rows` picks the highest round-numbered canonical heading (136–158). The gate checks duplicate slug across all rows and presence of all expected slugs (395–398), and checks the prefix using `next(...)` (399–403). Because any duplicate slug triggers `canon_mismatch`, this catches repeated expected slugs. It does not require the canonical section to contain *only* those 12; extras are allowed. That is not prohibited by the frozen sentence.
- **“each is covered by a row” — duplicates in registry are not rejected.** `score` counts covered slugs as a set (202–240), and requires coverage equal to population and bound rows at least population (420–426). Two valid rows for one capability can therefore coexist with a valid row for every capability; there is no uniqueness constraint on registry capability rows. Frozen wording says a row covers each capability, not “exactly one registry row,” so this is additional freedom rather than direct sentence violation.
- **“row binds exactly the allowed run template ...” — run/template, binding ID, and pattern enforced.** `score` resolves binding to manifest template, and checks exact run and pattern (217–227); placeholder substitution is applied before execution (184–186, 245–260). Quote is required to be a substring of prefix with length >=8 (209–210), stronger than simply “with its frozen row prefix” only insofar as the registry quote itself is not explicitly required to equal the frozen prefix.
- **“executed live in a scrubbed environment with a scratch TMPDIR” — enforced in normal path.** The counter extracts tip tree, sets TMPDIR to its work/run scratch, removes PYTHONPATH (351–363, 374–383), and executes via `run_bound` (245–274). It does not broadly scrub other inherited environment variables; the phrase “scrubbed environment” is not operationally defined in the sentence, but only PYTHONPATH is explicitly scrubbed. Also `--no-live` deliberately skips execution (409–415); the final predicate can still theoretically pass in that mode only if all checks somehow pass, but score's forced sensitivity false and empty observation mismatch make a conforming populated registry fail. The CLI option is an extra behavior, not a bypass to a met result as implemented.
- **“emitted verdict equals the recorded one” — enforced.** A run verdict requires pattern present, rc=0, and live target; comparison to `verdict.lower() == 'true'` increments mismatches (233–235).
- **“sensitive — replacing the decisive output substring flips the result” — only approximated.** It removes every literal occurrence of the pattern and verifies that the pattern no longer remains with the same successful return code (269–271). It does not re-run the command on modified output or actually recompute a changed emitted verdict; for the implemented predicate (pattern-in-output and rc=0), removal implies false, so the check is logically equivalent for this evaluator. For a pattern occurring multiple times, all are removed, not one decisive substring.
- **“no bound target path is dead” — partial liveness check.** It checks existence only when a regex recognizes a `/tools/<name>.py` target in the unexpanded template (252–257); templates with no match are treated as not dead. Current frozen manifest commands all have such a tool path. It does not check executable permissions, import/dependency availability, or whether a non-tool file target exists; those failures may instead surface through command verdict.
- **“mismatches=0” — enforced.** Verdict mismatch, failed sensitivity, dead target, or nonempty recorded observation absent from output each contributes mismatch (233–238), and final gate requires zero (420–426).
- **“all 8 control families are rejected” — enforced.** Eight mutations are built and scored, with rejected count required equal to total (292–348, 416–426).
- **“errors=0” — enforced for registry parse errors and canonical mismatch; broader execution errors are incompletely represented.** Final gate uses `facts['errors'] == 0` plus `canon_mismatch` empty. A timeout becomes output `TIMEOUT`, rc 124 and thus a mismatch, but is not counted in `errors` (258–274). A subprocess launch exception other than `TimeoutExpired` propagates rather than being converted into a counted error.

## Code checks not named by the predicate

- C1 additionally imposes a particular schema (`SCHEMA`, declared at line 40 but not used in grading), alias `kama-completion-probe`, fixed prompt, fingerprint regex, completion envelope/usage/timing/determinism checks, bad-request handling, teardown return-code set, and exact required-check key set (36–43, 100–158, 167–183). These detailed protocol constraints are implementation checks, not individually enumerated in the frozen sentence. Notably, `SCHEMA` itself is unused and therefore not enforced.
- C1 includes `--no-live` option (335–336) for fixture/control auditing, and requires helper dependency `kama-llamacpp-live.py` to be present (355–361); the latter dependency is not expressly named by the predicate, though needed operationally.
- C2 requires a quote substring of at least eight characters and exact pattern equality, rejects `notobs`, enforces a minimum row count, and accumulates observation-substring consistency (209–227, 233–239, 420–426). These are concrete policy choices not all separately called out in the sentence. The eight controls’ exact mutation definitions are implementation details beyond the general control-family count.
