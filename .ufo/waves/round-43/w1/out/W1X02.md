## 2. Design B (deliberately not the counter's shape)

- Population: one `git ls-tree -r -z --full-tree` (`hexrun-census.py:291`) feeding **one** `git cat-file --batch` session (`:139`, feeder thread, streaming — no per-document subprocess, no full-tree materialisation). The MD5 set is built from that same stream (`:316-329`), never re-read.
- The ledger blob is fetched through the same batch mechanism, parsed before the population pass so evidence blobs are retained as they stream past (`:300-310`, `:328-329`).
- Ledger parsed with `csv.reader(..., delimiter="\t", quoting=csv.QUOTE_NONE, strict=True)` over `io.StringIO(newline="")` (`:213-217`); header = the frozen 7 cells (`:75`).
- Classification is one first-match resolver (`:257`), with a `seen` guard so a `wrong` chain cannot cycle.
- `scan` creates no temporary files at all (no `tempfile`, no `mkdtemp`); only `selftest` does, and it removes its directory in a `finally`.
- Directory mode is a single `os.walk(followlinks=False)` + `lstat` regular-file filter, one read per file for md5/tokens/evidence (`:336-384`).

## 7. Contract ambiguities and how I resolved them

The docstring of `tools/round43-hexrun-audit.py` does not fix these; each is resolved conservatively and exercised where possible.

1. **`selftest` output and exit code** — unspecified. Resolved: `selftest pass=N fail=0` on stdout, exit 0 when all pass, 1 otherwise, 18 checks, temp dir removed (`hexrun-census.py:448-620`).
2. **`--details` format and stream** — the flag is named but never defined, and the contract reserves stdout for one line. Resolved: `detail: <token> len=<L> occurrences=<N> class=<class>` on **stderr**; stdout is always exactly the summary line (`:428-434`).
3. **Both `--dir` and `--repo/--rev`** — not specified. Resolved: usage error, exit 2 (`:417-424`).
4. **`--ledger FILE` source** — "overrides" is not qualified for the two modes. Resolved: an existing filesystem path wins; otherwise, in git mode only, the path is read at `REV`; otherwise exit 2 (`:437-445`). The frozen fixtures never use the flag.
5. **Ledger rows whose token no document cites** — the counts are defined over document tokens only. Resolved: such rows are ignored entirely, so a ledger row alone never adds to a count (probe `uncited`).
6. **A ledger row that is not 7 cells** — parsed as `ledger_bad` when its token is cited; rows whose token cell is not a non-digest hex run are ignored as unparseable for this census (`:226-236`, probe `eight-cells`).
7. **Header handling** — only the exact 7-cell header is skipped; a headerless or BOM'd ledger is treated as data. A headerless tab-separated ledger therefore still parses (probe `headerless`), and a wrong header's first cell is not token-shaped, so it is ignored.
8. **Empty `repo` cell on an `upstream` row** — the literal reading ("bytes contain … the repo cell text") makes an empty cell vacuous. Resolved: the token must always appear; an empty `repo` cell adds no further requirement (`:248-255`).
9. **Evidence path escaping the root** — dir mode rejects `..`/absolute evidence paths as "not a file under DIR" → `ledger_bad` (`:356-358`); git mode matches the exact tree path, so `./ev/x.json` never matches. This asymmetry is deliberate (git tree paths never carry `./`).
10. **Duplicate ledger row vs first match wins** — a duplicated token that is already `lane_oid`/`md5_blob` classifies by the first rule, not `ledger_bad`; duplication is `ledger_bad` only inside the ledger rule (`resolve`, `:257-290`).
11. **`wrong` whose `correct` is another `wrong`** — recursion is allowed with a `seen` guard so a chain ending in an upstream row works; a cycle is `ledger_bad` (`:271-285`; the scale rehearsal covers one hop, `wrong→upstream`).
12. **64-character runs as a `correct` value** — `token_shaped` applies the same `L != 64` rule, so a digest can never be a correction (`:102-103`).
13. **Symlinked documents** — git mode counts a symlink blob (it is "a blob at REV"); dir mode skips it ("regular files … symlinks not followed"). Probe: a `link.md` symlink is not followed; two of the eight symlinks in the lane tree are `.md` (`SCORECARD.md`, `SKILL.md`) and both sit under `.ufo/`, so the two modes agree on all counts.
14. **Occurrence counting for duplicate content** — a blob shared by *k* document paths contributes its token occurrences *k* times (per-path census), matching `git_population` in the counter; verified by `tokens=766` equality.
15. **`note` length** — counted in characters of the UTF-8 (replacement-decoded) cell, not bytes; 10 passes, 9 fails (`:274`, probes `note10`/`note9` in `selftest`).
16. **"the object exists in the repository"** — checked against the object store (`git cat-file --batch-check`), not reachability from `REV`, exactly like the counter's `own_census`, so the `live` comparison is apples-to-apples.
17. **Document exclusion paths** — `registry/hexrun-ledger.tsv` and `registry/digest-ledger.tsv` are excluded as exact root paths; a nested `sub/registry/hexrun-ledger.tsv` is an ordinary document.

## 8. Risks and limits

- The tool cannot verify that an `upstream` row's evidence file really came from the stated upstream; it only checks that a committed blob at `REV` contains the token **and** the `repo` cell text. That is the contract's `out_of_counter_limit`, and it is why the ledger must be written by the data seat from committed API copies.
- `live` will fail closed on any single mis-pathed evidence blob (`ledger_bad>=1`), and 64 of the 73 base runs need an `upstream` row with matching evidence or an honest `unverifiable` note; `upstream_ok >= 40` and `unverifiable + wrong_flagged <= 25` leave only 33 runs of slack, so the ledger's class mix is constrained by the frozen thresholds.
- The `contract` leg is a mirror of the contract (the R42B05/B06 risk class). This build is independent of the counter, but the twelve fixtures still only prove the semantics they encode; the base-equivalence and `git grep` cross-checks above are the compensating evidence.
- My `selftest` is my own extension (the counter never runs it); it is a guard for the tool, not evidence toward any claim.
