# 3. Does the round-19 grid violate tameshi conventions? Yes, in seven ways
1. **Non-verdict exits are kills.** H: a fake gate exiting 1 (traceback), 2, or 3 yields `rejected` for all three rows, with empty stdout for two. Tameshi: exit 2 is never a kill (repeat-control precedence). Kama's own gate selftest requires an `INVALID ` prefix on exit 1 (check-receipt.py:2112-2131), which a traceback fails. The grid has no equivalent. Violates QUALITY:121 ("a kill comes from a traceback, a crashed wrapper or a changed denominator").
2. **A crash counts as expected.** `run.py:66` (`tree-grid-no-pin`, want=1) is met by any exit 1. Observed exit 1 with no summary: non-JSON receipt (E), missing receipt (F), simulated gate `TimeoutExpired` (K). The docstring promises exit 2 for bad input (`install-tree-grid.py:17`); the code does not (`:66` is unguarded).
3. **A red control prints a kill count.** D: `baseline=INVALID members=3 rejected=3/3`, exit 2. Tameshi: no denominator (SKILL.md:148-149).
4. **Silent denominator change.** `:71` drops absent default members. I3 (real gate, `libllama.so.0.7.0` removed, digest recomputed): `baseline=VALID members=2 rejected=2/2`, exit 0, no row for the dropped member. `:72-73` falls back to `sorted(tree)[:3]`. J (default names renamed): `members=3 rejected=3/3` on `LICENSE`, `ggml-rpc-server`, `libggml-cpu-alderlake.so`, not the declared libraries. Tameshi requires the declared count (bash-witness-study.py:453; mutate-and-run.sh:212-214).
5. **Targeted kill is not checked.** Pin rejections do carry `server.install_tree_sha256 … != expected` (C), but `:94` ignores it. `run.py:68` (`tree-pin-negative`, want=1) is exit-only as well.
6. **Evidence is not retained.** C rows are cut at 200 characters mid-digest. stderr is discarded, so crash text is lost (H). No mutant sha256 is recorded. The scratch directory is deleted (`:75`). Tameshi recipe step 6 requires full output, mutant sha256, and duration.
7. **The claimed numbers have no retained run, and the counting command is not runnable.** `.ufo/waves/round-18/runs/commands.json` has no tree-grid entry, and `runs/` has no `tree-grid-*` files; `run.py:65-68` is uncommitted. SCORECARD's `rejected=0/3` is correct.

Also, KQ20 applies "a graded field counts only when something can make that grading fail" to the lane's own measuring instrument (corpus/QUALITY.md:115-116). The grid's `accepted`/`rejected` grading has no detector that fails when that grading is broken, and H shows it grading exit 2 as a kill.
