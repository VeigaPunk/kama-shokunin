## 5. Findings

In the commands below `$T` is the tip's tool extracted read-only from the clone: `git -C <clone> show 3d9bd8d:tools/digest-ledger.py > "$T"` (sha256 `d477333e134d91fa61726cf55fd665b9613705a40ba0df6479438aed08fc2637`, see §3).

### F1 (defect, real, latent for the counter) — a missing or unreadable scan root reports a clean ledger (exit 0)

`tools/digest-ledger.py:112-114`:

```python
def scan_dir(root: str, ledger_file: str | None):
    tokens, blobs, ledger = set(), set(), {}
    for cur, _, files in os.walk(root):
```

`os.walk` on a path that does not exist yields nothing and raises nothing, so the `except (RuntimeError, OSError, ValueError) → return 2` guard at `tools/digest-ledger.py:254-255` never fires. The tool prints a fully clean summary for a path that holds no bytes at all.

Command (reproduced identically under 3.11/3.12/3.13/3.14):

```
python3.11 "$T" scan --dir /fast/scratch/kama-r42/seats/R42B18/does-not-exist
tokens=0 blob=0 external_ok=0 external_absent=0 unverifiable=0 wrong_flagged=0 ledger_bad=0 wrong_unflagged=0 unknown=0
exit=0
```

Same false clean for `--dir` naming a regular file:

```
python3.11 "$T" scan --dir /any/regular/file.py   → tokens=0 … exit=0
```

and for a subtree the process cannot read (`os.walk`'s default `onerror=None` swallows the error). Tree with `ok.md` and `locked/cite.md` both citing the digest of `ok.bin`, then `chmod 000 locked` (uid 1000, non-root):

```
python3.11 "$T" scan --dir $D
tokens=1 blob=1 … unknown=0          # locked/cite.md silently skipped
exit=0
```

Impact: the exit code is the lane's published "no cited digest is unexplained" signal (`SCORECARD.md:128`, "exit 1 on any unexplained digest"), and the capability row now rests on it. A mistyped `--dir` or a partially unreadable export therefore *certifies* a tree that was never read — the same failure class as the round-38 S472 digest the ledger exists to prevent. The counter cannot catch it: the reference implementation has the same walk (`tools/round42-digest-audit.py:152`, `for root, _, files in os.walk(d):`), so tool and reference agree on the empty answer.

Proposed fix (two edits, no contract change — the contract already says "2 usage or git error"):

```python
# tools/digest-ledger.py, in main(), before the try:
if a.dir and not os.path.isdir(a.dir):
    print(f"digest-ledger: not a directory: {a.dir}", file=sys.stderr)
    return 2

# tools/digest-ledger.py, scan_dir():
def _raise(e):        # os.walk swallows errors by default
    raise e
for cur, _, files in os.walk(root, onerror=_raise):
```

(The same `onerror` belongs in `tools/round42-digest-audit.py:152` if the reference is to stay aligned, otherwise a fixed tool would diverge from the reference on unreadable trees.)

### F2 (defect, real, latent today) — an `external` ledger `path` is resolved against the process CWD, not the scan root

`tools/digest-ledger.py:86`: `if p and os.path.isfile(p):` — `p` is used as given. Two scans of the same tree with the same arguments disagree:

```
# fixture: rp/registry/digest-ledger.tsv row  <sha256 of ../ext/outside.bin>  external  x  ../ext/outside.bin
(cd $ROOT/rp && python3.11 "$T" scan --dir .)
tokens=1 blob=0 external_ok=1 external_absent=0 … exit=0
python3.11 "$T" scan --dir $ROOT/rp          # from the seat root, same tree
tokens=1 blob=0 external_ok=0 external_absent=1 … exit=0
```

Latent in the lane today: all four `external` rows carry absolute paths (`awk -F'\t' '$2=="external"' registry/digest-ledger.tsv`). It is nonetheless an audit hazard, because the counter launches the tool with `cwd=export` (`tools/round42-digest-audit.py:265`, `cwd=export`) while computing the reference in the audit process's own CWD (`:119`, `if r["path"] and os.path.isfile(r["path"]):`). A relative `path` would therefore make the `live` leg mismatch *by construction* — a false red on a correct tree, or, on a tree where the export happens to resolve, a green that says nothing about the lane.

Proposed fix: resolve `p` against the scan root when it is not absolute (thread the root into `classify`), or declare relative paths `ledger_bad` with a note, and pass `cwd=repo` in `run_tool` for the `--repo` leg so tool and reference share a base.

### F3 (note, contract-conformant) — duplicate ledger rows are silently last-wins

`tools/digest-ledger.py:63-69` (`rows[c[0]] = …` at `:69` in `parse_ledger`): a second row for the same digest replaces the first with no diagnostic. Edge case 05 shows the consequence shape (`ledger_bad=1` because the *last* row has an unknown class); had the last row been a valid `unverifiable`, a preceding `wrong` flag would disappear silently. Suggested hardening (not required by the frozen contract): count a repeated digest as `ledger_bad`.

### F4 (note, contract-conformant) — the document suffix test is case-sensitive

`is_doc()` (`tools/digest-ledger.py:59-60`) matches `.md` / `.tsv` exactly, so a document named `README.MD` is not scanned (edge case 11: the `.tsv` token is counted, the `.MD` token is not). This matches the frozen wording ("names end .md or .tsv"); recorded as a limit, not a defect.
