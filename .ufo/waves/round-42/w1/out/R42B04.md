## Survivor analysis (coverage findings — not contract changes)

**F1 — M2b, the strongest: the live leg never requires `wrong_flagged >= 1`.**
`tools/round42-digest-audit.py:320-321` gates live on `ledger_bad==0 and wrong_unflagged==0 and unknown==0 and external_ok>=4` against a reference recomputed from the mutant tree. Reclassifying the lane's only `wrong` row (`5585f602f71c…`, the round-38 S472 digest that "hashes nothing") to `unverifiable` keeps every gate satisfied: the token still has a row with a non-empty note (no `unknown`), it is in the ledger so the `wrong_unflagged` prefix check at `tools/digest-ledger.py:92-97` is never reached, and `external_ok` is untouched. Result: `met=True` while the S472 wrong flag and its recorded correction (`correct` column) silently vanish from the ledger's machine-checked surface. The scan's own exit stays 0 (`L+X+K=0`), so even the tool alone accepts it. Proposed fix (for the closure/next round; the counter is frozen after seat scoring per preregistration kill_rule): add `ref["wrong_flagged"] >= 1` to the live gate at `tools/round42-digest-audit.py:320-321`, or pin the frozen live-reference class counts (`wrong_flagged=1`) from the preregistration receipt.

**F2 — M5: the `note` column is validated only for `unverifiable` rows.**
`tools/digest-ledger.py:84-91` (external branch) reads only `path` and the re-hashed file; `:94-97` (wrong branch) reads only `correct`. Blanking the note of external row `e404b91a` leaves every count identical → `met=True`. Severity low: the digest is still re-hashed against the host file on every scan, so the machine check is intact; the note is human provenance. The contrast mutant M5b shows the `unverifiable` note check (`:93`) is live. Proposed fix if the lane wants note provenance enforced for external rows too: extend the non-empty-note requirement to `external` (one line at `tools/digest-ledger.py:91`); contract change, next round.

**F3 — M7: ledger rows whose digest is in the blob set are never consulted.**
`tools/digest-ledger.py:79-80`: classification is first-match-wins over tokens, and a token in the blob set takes the `blob` branch before the ledger is consulted; a row whose digest is uncited is never visited at all. My added row (class `external`, path `/nonexistent/x` — maximally toxic if ever read) changes no count → `met=True`. Severity low: blob classification is stronger evidence than any ledger row, so a junk row cannot misclassify a token; but the ledger can accumulate undetected junk rows. Proposed fix: in `classify()`/`parse_ledger()`, flag any ledger row whose digest is in the blob set (redundant row) as `ledger_bad`; contract change, next round.

**Killed-mutant nuances worth keeping:** M2a shows the tool's own exit code is not a health signal for class swaps (`scan-exit=0` while `external_ok` drops below the counter's floor of 4) — the counter's `external_ok>=4` floor is doing real work. M4 shows external rows are genuinely re-hashed (mismatch → `ledger_bad=1`), not merely existence-checked. M1/M3 show cited-but-unrowed digests surface as `unknown=1` with tool exit 1.
