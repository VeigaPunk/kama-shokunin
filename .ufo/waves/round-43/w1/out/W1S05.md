## Findings

1. **Both counters were unregistered at the freeze commit.** `git grep -n
   'round40-calibration-audit\|round40-operability-audit' 895793e0 -- SKILL.md` returns nothing, and
   the frozen gate receipt records it at `.ufo/waves/round-43/controls/base.c1.out:12-13`. They enter
   the round-43 `pins` NEWSET (`tools/round43-registry-audit.py:73`) precisely because they had no
   row; my two rows are the fix for that pair.
2. **Defect (already routed as D1, `corpus/lessons/round-40-verifier-spotcheck.md:97`) — confirmed by
   my own parse, and wider than the routed text.** `corpus/SOURCES.md` at `895793e0` carries the
   11-column header `| id | source | kind | tier | scope | anchor | teaches | status | opened |
   recheck | used-by |`, so in `[c.strip() for c in line.split("|")[1:]]` the `teaches` cell is
   `row[6]` and `status` is `row[7]`. `tools/round40-calibration-audit.py:63` reads `teaches =
   s474[7]` — the status cell, whose value is `mined`; the real `row[6]` reads `supersedes S472 —
   correct digest of committed ls-remote evidence is 5585f6027df2…e50f2`. D1 quotes only line 63;
   **line 81 repeats the off-by-one on the negative leg** (`row[7].startswith("supersedes S472")`), so
   the `false_corrections == 0` condition is blind to a genuine duplicate `supersedes S472` teaches
   cell and is currently vacuous. Proposed fix (round-44 candidate, *not* applied — the counter is
   frozen): read `row[6]` at lines 63 and 81, tighten the guard at line 62 from `len(s474) >= 9` to
   `len(s474) >= 11`, then re-run base and after with `python3
   tools/round40-calibration-audit.py --repo <clone> --tip <commit>`.
3. **The C1 claim is recorded as unverified in its own receipts, and the row says so.** Round 40's
   SCORECARD row (`SCORECARD.md:2180`) and the verifier spot-check ("Ruling: **unprovable**",
   `corpus/lessons/round-40-verifier-spotcheck.md`) already leave the claim uncredited; the row states
   the routed limit instead of implying `met=True` (receipt: `met=False`, exit 1).
4. **Exit-map honesty.** Neither counter has a could-not-evaluate code and both degrade to exit 1. The
   rows state this plainly, because a reader re-running them on a mistyped `--tip` would otherwise read
   "claim failed" where the instrument merely could not look.
