  the C2 predicate's parenthetical in `preregistration.json`. My `mistakes.md` row 4
  cites the TSV; the lesson/report should not cite `base.c2.out` for this figure.
- **F2 — the TSV that carries the 73 has no producer in the tree.**
  `git grep -n base-unresolved 895793e0` → no reference; `git grep -n first-context
  895793e0` → only `base-unresolved.tsv:1` itself. No committed command emits the
  file, so at the freeze the 73 is a committed assertion, not a rerunnable counter
  output. Reproduced independently here (`hexrun-population.out`). Proposed fix for
  round 44: fold the emitter into `tools/hexrun-census.py` (`scan --unresolved`) and
  re-emit the TSV, or commit the one-off generator. Until then the row cites the TSV
  as carrier, and KQ55 is built on the counter's live leg, not on the TSV.
- **F3 — the clone is not at the freeze commit.** `/fast/scratch/kama-r43/clone` is
  at `1af8d516` ("round-43: C3 API copies … fetched 2026-10-26T01:46:17Z"). The chain
  is `6897ead5` (base) → `da462f94` ("round-43: wip census start + C1 counter, local,
  unpushed") → `895793e0` (freeze) → `1af8d516`; the assignment text says "a fresh
  clone … at the freeze commit". All my evidence was taken in a private clone at
  base, so the discrepancy does not affect it, but any seat that measures "the
  clone" without a checkout is measuring `1af8d516`, not base or the freeze.
- **F4 — no defect found in the frozen counters.** C1, C2 and C3 reproduce their
  base receipts' detail lines byte-for-byte (apart from the throwaway `tip=` and the
  unseeded run's `seed=`), and the seat's independent census of 210 distinct non-64
