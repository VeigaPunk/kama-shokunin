## Findings

- **F1 (LOW — documented convention, no false result at the sample):** the semver regexes fullmatch only plain `vX.Y.Z`, so `.postN` hotfix-style tags (72 in sglang, 10 in vllm) and vllm's four-component tags (`v0.10.1.1`, `v0.9.0.1`) are invisible to the watch. These exist in both engines' tag namespaces as version-ordered releases; if upstream shipped e.g. `v0.5.22.post1` or `v0.32.0.post1`, pin-watch would report `current` and miss the recheck trigger. `engine-pin-watch.md:31-32` states the convention ("rc and `.post` tags and branch refs are ignored"), so this is a deliberate narrowing, not an implementation bug. Bounded today: the highest excluded `.post` is `v0.5.15.post1` (sglang) / `v0.8.5.post1` (vllm), both below the pins; the only excluded tag numerically above a pin is `v0.32.1rc0` — a pre-release of an unreleased version, correctly ignored. Residual: a future hotfix release would be missed until the 30d pin-watch recheck or a row-level recheck fires.
- **F2 (INFO — sourcing asymmetry):** the three pins rows reach the pinned release through different row kinds: sglang cites its tag-inventory row (S474); llama.cpp cites its release-identity row (S038, not the inventory S477); vllm cites two docs rows (S327/S363) whose v0.32.0 is a docs-version pin, with the release-tag attestation (S476) uncited by the pins row. All satisfy the frozen sourced leg and the docstring's "cite the pinned release"; no contract breach — but a reader tracing the vllm pin to a git tag goes one hop further (via S476, which does the tying) than for the other two engines.
- **F3 (INFO):** S038 itself warns the b11755 release is mutable (Pre-release) and should be cited by asset digest, not tag alone (`SOURCES.md:50`). The pins row pins the tag; `engine-pin-watch.md:42-44` correctly frames the resulting `behind` (115 newer builds) as "a recheck trigger, not a falsification" of S038-backed entries.
