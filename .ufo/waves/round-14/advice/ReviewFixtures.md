## Severity-ordered findings

### HIGH

**H1. Fail-closed finding IDs are not mapped by the contract.** Contract says exit 2 is
"unknown / invalid_input" but never says which condition yields which ID. Fixtures would have to
invent the mapping, and then `expected_finding` would be an unsourced literal. Before literals are
written, L1 (with Classifier and Fixtures) must fix one rule. Proposed rule for confirmation:
- `invalid_input`: unreadable or unparseable file; top-level not an object; `models` missing or not
  an array; entry not an object; required identity/digest key missing or wrong type; empty-string
  digest or identity in a selected entry; wrong-type `remote_model`/`remote_host`; missing `--ps`
  input file (unavailable input).
- `unknown`: well-formed evidence that cannot establish a verdict: expected name/alias has no tags
  match; duplicate selected entries (well-formed but ambiguous).
Every exit-2 case must pin one of these IDs literally. Pinning exit 2 alone does not satisfy
"literal expected exits/IDs".

**H2. Overlapping conditions have no stated precedence.** Contract sentences collide in these
cases; each collision needs one pinned expectation, or the case must not be written:
- Remote tags entry + tags/ps digests differ. Contract: "remote ... regardless digest" vs
  "differing matching digests -> identity_conflict". Pick one.
- Remote selected ps marker + name/model conflict in the same entry.
- Malformed field + remote field present. Contract: "remote takes precedence only after schema
  valid" → schema failure must win (exit 2, `invalid_input`). This one is determined by contract.
- Duplicate selected entry + remote marker.
- Tags no-match + selected ps remote marker. Tags no-match is exit 2 under the contract's
  "expected model with no tags match unknown" sentence.
Proposed order for L1 confirmation: schema/unavailable (2) > no-tags-match/duplicate (2) >
identity_conflict (1) > remote_inventory (1) > available_not_loaded (1) > loaded_same_digest (0).
Exit codes match across the two exit-1 rows, so the finding ID is the only thing that differs.

**H3. Denominator risk.** The contract names at least 11 control families. The minimum of 16 is a
floor, not a target. The file must contain every contract-named control, and the harness total must
equal `len(cases)` with no skip path. Coverage matrix, one row per contract clause, is below. A
case set that covers only loaded and available controls passes the "at least 16" count and still
leaves the adversarial clauses unmeasured.

**H4. "No auto-computed expected result."** `expected_exit` and `expected_finding` must be literal
values typed into `cases.json` from the contract table. They must not be generated by a script, a
Python reimplementation of the classifier, or by copying observed output. `measure.py` (Harness)
must compare observed exit/ID to these literal fields only. Any expected field derived from another
field (for example, `expected_exit` derived from `expected_finding`) violates this rule.

### MEDIUM

**M1. Representational gaps in the case schema.** The schema `name, tags, ps, expect,
expected_exit, expected_finding` cannot express three contract controls:
- "missing ps input" (file absent) as distinct from `ps: []`. Suggest `"ps": null` meaning
  "do not write the file" — Fixtures/Harness to document the sentinel in `cases.json` or `measure.py`.
- "malformed envelope" as unparseable JSON bytes. A JSON object cannot carry invalid bytes. Either a
  raw-text field (for example `"tags_raw"`) or an explicit note that this control is an invalid
  top-level type instead. Pick one; do not silently drop it.
- "unavailable tags" (file absent). Same sentinel as above on the `tags` side.

**M2. Expiry control missing from the contract list.** Contract: "No timestamps/expiry/current-
liveness inferences." Docs: `expires_at` is "Time when the model will be unloaded." Add:
- a loaded-same-digest ps entry with `expires_at` in the past → exit 0 `loaded_same_digest`;
- the same entry with `expires_at` in the future → exit 0. The pair proves the field is ignored.

**M3. Digest-only ps match must not count as loaded.** Contract: "no basename identity shortcuts" and
exact name/alias matching. A ps entry with the same digest as tags but a different name/model is no
ps match → exit 1 `available_not_loaded`. Include this as a separate case from name mismatch.

**M4. ps remote markers are not doc-backed.** `/api/ps` schema has no `remote_model`/`remote_host`.
The contract still requires "selected ps markers → remote_inventory". Keep the case (contract
mandates it), but label it contract-synthetic in the fixture notes so no reader treats it as
documented ps behavior.

**M5. Empty and null remote fields.** Contract says "nonempty". Specify in fixtures:
- `remote_host: ""` with local matching digest → not remote → exit 0 possible (adversarial control);
- `remote_model: null` → decide. Recommend treating null as wrong type → `invalid_input`, since
  null is not an absent key and not a string. Pin the choice.

**M6. Implicit `:latest` is not in the contract.** Contract: exact name or model alias match,
case-sensitive. `expect: "llama3"` against tags name `llama3:latest` → exact-only → no match →
exit 2 `unknown`. Do not claim the Ollama CLI's implicit-tag behavior. Pin the exact-only outcome
and record it as an L1 decision.

**M7. Required-ness of `name` and `model`.** Docs schema marks neither required. Contract's
"conflicting name/model within selected entry" needs both present. Propose: selected entries require
`name`, `model`, `digest` as strings; missing `model` → `invalid_input`. Pin with one case
(name present, model absent).

**M8. Digest comparison is exact string.** Do not add a `sha256:` prefix-normalization case unless
the contract adds it. A tags digest with a prefix and a ps digest bare hex compare unequal under
exact matching → `identity_conflict`. Include only if L1 confirms this is the intended behavior.

### LOW

**L1. Finding vocabulary must be exact.** Use only these IDs: `loaded_same_digest`,
`available_not_loaded`, `remote_inventory`, `identity_conflict`, `unknown`, `invalid_input`.
Every case also implies `readiness: "unknown"` and `scope: "offline-captures-not-runtime"`; if the
harness checks those, they must be literal too.

**L2. Case names must be unique and descriptive.** Duplicate `name` values break `measure.py`'s
per-record map and hide denominator loss.

## Advice to owners (bounded)

- **Fixtures:** write all 30 rows as hand-typed literals; use the exact six finding IDs; choose
  the `"ps": null` sentinel (or equivalent) for absence; pin per-row expected_finding from the
  confirmed H1 table, not from observed output.
- **Classifier:** implement the H1 mapping and H2 precedence exactly as confirmed; do not add a
  basename or digest-only identity shortcut; ignore `expires_at`.
- **Harness:** total = `len(cases)`; compare literal exit and finding only; absent tool = failed
  cases, not skips.
- **L1:** decide H1 mapping, H2 precedence, M5 null, M6 implicit tag, M7 required keys, M8 digest
  format, before the Fixtures literals are finalised.
