## Survivors — the findings

All four survivors are gaps in the counter's checks, not in the claim's facts (the facts themselves are true at the tip). Per contract these are reported, not fixed in place.

1. **E2a — the `max_model_len` count check has an incidental second satisfier.** `tools/round42-capacity-audit.py:146` searches `max_model_len[^\n]{0,80}\b0\b` over the whole entry; the entry's own command echo `` (`grep -o max_model_len <copy> | wc -l` → 0, 2026-10-25) `` (entry:20) contains a second `max_model_len` followed within 80 chars by `→ 0`, so the check passes no matter what the prose count states. Stating `occurs 1 times` (false) leaves `met=True` (receipt `E2a.out`). Only when both sites are falsified (E2b) does the leg fire. Proposed fix: require the exact phrasing of the computed count, e.g. additionally demand `` `max_model_len` occurs <mm> times `` (or exclude backtick command echoes from the scan window).
2. **G2b — the S479 gate quote check is satisfiable by an incidental span.** `round42-capacity-audit.py:202-204` takes every double-quoted span ≥8 chars on the sid's line and accepts if **any** is ≤25 words and located. On the S479 gate line (`corpus/lessons/round-42.md:21`) the backticked literal `` `model_info["context_length"] = meta.n_ctx_train;` `` contributes the span `"context_length"` — 1 word, and it occurs in the copy — so corrupting the located quote (`> 0` → `>= 0`) leaves `gate=1` (receipt `G2b.out`). The S478 line has no such fallback (G2 killed), so the guard is asymmetric. Proposed fix: strip backtick-delimited spans before `findall`, or require **all** quoted spans on the line to be located and ≤25 words.
3. **G4 — the gate never checks the stated line number of a quote.** The gate leg checks URL-in-section, date-in-line and quote-occurrence-in-copy (`round42-capacity-audit.py:202-204`); `Located quote, line 1627:` can say `line 1628` and still pass (receipt `G4.out`). Proposed fix: compute a fourth anchor for the S479 guard line (`if (meta.n_ctx_train > 0) {`, currently 2378) and require each gate line's stated number to equal the computed anchor line.
4. **E5 — only three of the entry's eight line citations are line-checked.** `round42-capacity-audit.py:140-142` requires exactly `kv_cache_utils.py:1627`, `kv_cache_utils.py:2328`, `server-models.cpp:2379`; the entry's other citations (`:1230-1236`, `:2308`, `:1195-1227`, `:2321-2322`, `:2329`, `:2378`) are unchecked, so a wrong `2308` passes (receipt `E5.out`). Proposed fix: extend the check to every `kv_cache_utils.py:<n>` / `server-models.cpp:<n>` token in the entry against the copies (heavier: needs an expected anchor per citation, or at least range/line-count sanity).

Bonus kill observed: R3/R8 (status `mined`→`open`) also flipped `census=0` — grounded in `/home/vgpnk/Projects/shokunin/scripts/sources-census.sh:4` (`# statuses queued|mined|rejected`) and `:27` (`E07 status enum violation`), i.e. the census leg adds defense-in-depth for the status field beyond the rows leg.
