## 2. Unit of the census and the frozen screening rules

**Unit = a digest-citation instance**: one lesson line carrying a digest
payload — a 64-hex digest or an explicit `sha256` token. This is the
granularity at which a digest is *cited*, which is what a 'digest citation
correction' practice acts on. (The lane's own idiom for a bounded search is
`corpus/lessons/round-14.md:78-81`: "two official URLs identified, screened and
included for existing rows, zero excluded" — this sweep uses the same
identified / screened / included / excluded vocabulary.)

Rules, fixed before any instance was read:

| rule | meaning |
|---|---|
| **IN-1** | the instance cites a digest the lane records as **not matching** committed bytes / a fresh rerun, **and** prescribes or performs an **append-style** correction (superseding row / correction row / correction section), not a rewrite |
| **IN-2** | the instance cites a digest **inside** an append-style correction row — the correction is the carrier of the digest |
| EX-1 | digest is the lane's watchdog/dispatch evidence digest |
| EX-2 | digest is an instrument/receipt/counter-file pin; no cited evidence, no correction |
| EX-3 | digest is a **correct** citation on an admitted row; no defect |
| EX-4 | digest is a correct re-verification receipt (fresh fetch reproduces it) |
| EX-5 | digest is a category/truncated token with no digest value (`sha256 sums`, `sha256 advice`) |
| EX-6 | digest is cited **wrong**, but the defect is recorded only later, with no correction accompanying the citation |

## 4. The practice, as the lane actually writes it

The search yields a single, coherent, four-part practice. It is stated at
`corpus/lessons/round-38-verifier-spotcheck.md:73-74` and instantiated at
`corpus/lessons/round-38.md:51`:

1. **Name the wrong digest and the right digest in the same breath.**
   `corpus/lessons/round-38-verifier-spotcheck.md:73` gives the actual
   `5585f6027df2dbc4dbafd4979b61c218ffd94e8af99936733218e0ae989e50f2`
   beside the wrong `5585f602f71c4d4fa5a20125b2b8e4a1132a2d41abf511d7ef09c43a91d950f2`.
2. **Recompute against committed bytes, not against the citation.**
   `:73` says "does not match the committed evidence blob **or a fresh rerun**";
   `:74` says "matches neither current package bytes … nor common variants".
3. **Correct by append, never by rewrite.**
   `:73` — "Correct by a superseding row/recheck (append-only)".
   `:74` — "Correct the citation."
4. **Carry the recomputed value into the correction row itself.**
   `corpus/lessons/round-38.md:51` is the `R36-D2C:` row, a correction row that
   cites the package sha256 as part of the correction.

Two lane criteria already govern this and neither needs editing:

- **KQ31** (`corpus/QUALITY.md:164`) — "A correction to immutable SOURCES
  scope/anchor/teaches is a newly opened row whose teaches starts
  `supersedes S0NN —`; the old row and filed explanation stay intact."
- **KQ22** (`corpus/QUALITY.md:123`) — "Registry cells other than `status`,
  `recheck` and `used-by` stay byte-identical from a row's first commit; a
  regenerated artefact or corrected anchor takes a new row (`supersedes S0NN —`)
  or is recorded in a knowledge entry, never by rewriting t[he row]".

**KQ31 names the `teaches` cell explicitly.** That matters for §5.

### 5.2 The off-by-one

`tools/round40-calibration-audit.py` parses a SOURCES row as:

```python
cell = line.split("|")
rows[cell[1].strip()] = [c.strip() for c in cell[1:]]
```

so the list is `['<id>', '<source>', '<kind>', '<tier>', '<scope>', '<anchor>',
'<teaches>', '<status>', '<opened>', '<recheck>', '<used-by>', '']` — **index 6
is `teaches`, index 7 is `status`**.

The counter then reads:

```python
teaches = s474[7]
if teaches.startswith("supersedes S472") and CORRECT_EVIDENCE in teaches:
```

**`s474[7]` is the `status` cell, not the `teaches` cell.** The frozen
predicate text (`preregistration.json` C1) says "whose `teaches` cell starts
with `supersedes S472`"; the counter's own docstring says "whose `teaches` cell
starts with" and then reads index 7. The docstring and the code disagree.

Verified against the real schema at tip (`corpus/SOURCES.md:11` header
`| id | source | kind | tier | scope | anchor | teaches | status | opened |
recheck | used-by |`), using S040 as a probe row: `r[6]` = `"supersedes S021 — …"`,
`r[7]` = `"mined"`.

### 5.3 The lane convention says index 6

Across all 214 committed rows at tip:

```

status(idx7)  starts with 'supersedes':  0
```

KQ31 (`corpus/QUALITY.md:164`) prescribes exactly index 6. The counter reads

different columns.**

### 5.4 The consequence, measured on fixtures

Each fixture is a throwaway `mktemp -d` + `git init` repo whose tip carries the
real r40 tree plus the amendment `## Correction — round 40` section and the
`corpus/lessons/round-40.md` `R36-D2C:` row, i.e. legs 2 and 3 are satisfied
in every variant.

| variant | S474 row shape | counter | census |
|---|---|---|---|
| **V1** | **lane convention** — `teaches` = `supersedes S472 — evidence digest 5585f6027df…`, `status` = `mined` | `s474_row=0 … met=False` exit 1 | **exit 0, 0 E findings** |
| **V2** | counter's reading — `status` = `supersedes S472 — evidence digest 5585f6027df…` | `s474_row=1 … met=True` exit 0 | **exit 1** — `E07 status enum violation` |
| **V3** | embedded `\|` in the `anchor` cell, shifting `split("\|")` so index 7 lands on `teaches` | `s474_row=1 … met=True` exit 0 | **exit 1** — `E01 fields=12` |

So:

- Writing the row the way the lane writes correction rows (V1) **cannot** pass
  the counter.
- Writing the row the way the counter reads (V2) **fails the census** with
  `E07`, because `status` must be `queued|mined|rejected`
  (`scripts/sources-census.sh:4`, check at `:659`).
- The only way to satisfy both would be to exploit the pipe-split (V3), which
  trips `E01 malformed row (NF!=13)`.

**C1 leg 1 is therefore unsatisfiable jointly with a census-clean
`corpus/SOURCES.md`.** This is not a judgement call about which side to
favour; it is a hard conflict between two frozen artifacts.
