== the scaling law ===========================================================
peak_MiB(object_MiB) fit over lane(216.3, 458.1) B(344.9, 717.6) C(2135.0, 4307.0):
    peak_MiB = 2.006 * object_MiB + 24.2      (B residual 0.2%, C residual 0.2%)
    slope alone: lane 2.12x, B 2.08x, C 2.02x  -> the 2x is capture_output's
    chunk-list + b"".join double buffer of the whole `git cat-file --batch` stdout.
object-count axis: a set of 160,000 64-hex digests (10x the lane's 12,352 blobs) costs +28,764 KB.
    -> count is negligible; uncompressed history bytes alone set the peak.
per-document subprocess axis: 201 `git -C D cat-file -p HEAD:<doc>` spawns = 0.128 s = 0.64 ms each
    (an earlier 4.79 ms reading was taken while fixture C was being built; the clean number is 0.64 ms).
    -> 10x lane = 1300 docs = ~0.8 s; not a problem against the 300 s live-leg timeout.

10x lane projection (10 x 226,852,785 B = 2,268,527,850 B = 2163.4 MiB):
    peak = 2.006 * 2163.4 + 24.2 = 4,364 MiB = 4.26 GiB = 4.58 GB decimal
    empirical cross-check at 9.86x (fixture C): measured 4,307 MiB, predicted 4,317 MiB (-0.2%)
