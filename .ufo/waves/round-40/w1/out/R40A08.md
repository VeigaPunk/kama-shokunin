## 3. Falsification of the C1 predicate as frozen — the counter's cell index is off by one

**This is the most decision-relevant finding for the integration owner (KamaR40).**

The preregistration C1 predicate (`.ufo/waves/round-40/preregistration.json`, `claims[0].predicate`)
says:

> "A SOURCES row S474 exists whose **teaches** cell starts with `supersedes S472` and contains the
> exact evidence digest …"

The frozen counter `tools/round40-calibration-audit.py` implements the same sentence but reads
**`s474[7]`**, while the registry row parser yields the *teaches* cell at **index 6**.

`registry_rows()` parses `line.split("|")` and keeps `cell[1:]`, so for the 11-column contract row
`| id | source | kind | tier | scope | anchor | teaches | status | opened | recheck | used-by |`:

```
list[0]=id  [1]=source  [2]=kind  [3]=tier  [4]=scope  [5]=anchor
list[6]=teaches   <-- the cell the predicate prose names
list[7]=status    <-- the cell the counter actually reads ("teaches = s474[7]")
```

Verified against the **real** `corpus/SOURCES.md` at tip by running the counter's own
`registry_rows()` over the real S472 row: `list[6]` = the `v0.5.22 is the highest release tag …`
teaches text, `list[7]` = `mined` (status). The header the tool's own selftest fixture writes
(`tools/sources-append-only.py:358`) confirms the same 11-column order.

### Fixture matrix (4 fresh repos, `git -C "$D"`, counter run against each)

| variant | digest+prefix placed in | counter `s474_row` | counter `met` | `sources-census.sh validate` |
|---|---|---|---|---|
| A | teaches (`list[6]`) — what the prose demands | **0** | **False** | **exit 0**, clean |
| B | status (`list[7]`) — what the counter reads | 1 | **True** | exit 1 — **E04** + **E07** |
| C | both columns | 1 | True | exit 1 — **E07** |

**The counter and the prose predicate cannot both be satisfied.** Variant A (prose-faithful,
census-clean) makes the counter report `met=False`; variants B/C (counter-passing) make the fleet
census fail with `E07 status enum violation` (status must be one of `queued|mined|rejected`,
`scripts/sources-census.sh:658`) and, for B, `E04 duplicate url … within scope` (the `supersedes`
marker must be in *teaches*, `sources-census.sh:648`).

Corroborating this is the lane's own precedent: all 11 existing `supersedes S0NN` markers in
`corpus/SOURCES.md` live in the **teaches** column, none in status. KQ22
(`corpus/QUALITY.md:123`) likewise says a corrected anchor "takes a new row (`supersedes S0NN —`)".

### Concrete consequence for the frontier step

The C1 counter's `s474[7]` must become `s474[6]` (or the predicate prose must be restated to
"status cell" — which would then contradict both the census E07 rule and every existing
`supersedes` row). **The counter is the frozen artifact, so this is an integration-owner
decision**: the fix is a one-character index change in `tools/round40-calibration-audit.py`, and
the executor (R40E06) needs to know about it before writing the S474 row, otherwise the row
written prose-correctly scores `met=False` and the census scores clean — the exact inverse of
the intended result.

**Note the `false_corrections` leg is unaffected** by this: it scans `row[7]` for *other* rows
starting with `supersedes S472`, and with the digest in teaches the sibling check
`teaches !~ /supersedes S[0-9]{3}/` (census line 648) still suppresses E04 — so variant A keeps
`false_corrections=0`.

### Second, smaller C1 defect: `false_corrections` under-detects a stale digest

The counter computes `false_corrections` only as `WRONG_EVIDENCE in amend and not amend_corrected`.
The prose says the wrong digest must not survive "outside its correction section". The
implementation tests presence anywhere in the file, so the *existing* wrong digest in the
amendment's `source: S472` line 9 (which sits above any appended `## Correction — round 40`
heading) is **not** flagged as a false correction once `amend_corrected` is true. Fixture variant
"wrong digest still in the amendment source line + valid correction section" → `met=True`. Under
KQ3 / append-only (`corpus/QUALITY.md:11`, `tools/sources-append-only.py:63`), the stale line is
legitimately immutable history, so the practical impact is limited — but the counter's semantics
differ from its prose here, and the r40 lesson row / verifier spot-check (which legitimately
retain the stale digest) are already named as the exceptions.
