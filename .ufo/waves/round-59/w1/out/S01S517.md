# S01S517 — `sys.setprofile` claim boundary

Axes: operability; calibration (7, lowest assigned).

## Finding

Python’s `sys.setprofile` documentation supports the narrow statement that profile callbacks receive `call` and `return` events, and that a return event is reported even when an exception has been set. It does **not** establish that a callback observes successful completion, a returned value, or an outcome for an external operation. Thus it cannot by itself support a claim that profiling proves a leg’s successful result/outcome; a `return` event also occurs on exceptional exit. The documentation separately says `call` means a function or other code block is entered and `return` means it is about to return.

Quote (22 words): “only on call and return, but the return event is reported even when an exception has been set”

Source: https://docs.python.org/3/library/sys.html#sys.setprofile (accessed 2026-10-27; Python 3.15.2 docs as served). Relevant section: `sys.setprofile`; exact wording located in the page text at lines 1466–1471. The full event descriptions distinguish entry (`'call'`) and impending return (`'return'`).
