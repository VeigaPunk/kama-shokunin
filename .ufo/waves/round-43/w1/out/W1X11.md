**F2 — the ledger grammar cannot flag a wrong over-long run whose correction is a digest.** `wrong` requires `correct` to be token-shaped and to classify (`tools/round43-hexrun-audit.py:32-35`), while the token rule excludes `L == 64` (`:18`). The lane's only 65-hex citation is demonstrably wrong and demonstrably corrected, yet the frozen grammar forces it into `unverifiable` — so `wrong_flagged` can report 1 while two of the nine runs are wrong. Proposed fix (not applied; counters are frozen): accept a 64-hex `correct` when `len(token) != 64`, or add a `wrong_digest` class. Exact defect site: `tools/round43-hexrun-audit.py:18` and `:32-35`.

**F3 — `md5_blob` is REV-only, so four verifiable historical digests consume the `unverifiable` budget.** Rows 1-4 are MD5s of blobs at `83bee7fa` and `c6199a25`, reproducible today with `git show <c>:<path> | md5sum`; the class is defined over blobs at REV only (`:22-23`), so they must be filed `unverifiable`. That is 4 of `UNVERIFIED_MAX = 25` (`:81`) spent on citations that are not unexplained at all, plus 4 more spent on non-digest strings (rows 5-7) and row 9. Budget arithmetic for the integration: this fragment contributes `unverifiable=8, wrong_flagged=1`; keep the sum ≤ 25.

**F4 — dedup on `35ce313293052f8362e0829e7512bc9bc3d336c9`: resolved, measured.** The 40-hex token is also row 11 of `base-unresolved.tsv`, so the oid workstream owns it; W1X03 emitted the row and W1X04 measured mine as a duplicate.
