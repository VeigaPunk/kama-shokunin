# S02S518 — Re-open ld.so(8): secure execution and tokens

**Axes:** operability; calibration (7, lowest assigned). **Attacked claim/clause:** S518's scoped claim that `LD_AUDIT` is ignored in secure-execution mode and that audit-list values expand `$ORIGIN`/`$LIB`/`$PLATFORM`; S513 rejection for overlap on the narrower LD_AUDIT-name-only claim.

## Findings

**S518 is source-supported for its stated narrow behavior; S513 remains rejected for its original narrow use.** The live man7 page identifies itself as Linux man-pages 6.19 dated 2026-08-03, agreeing with the S518 row's revision marker. Under “Dynamic string tokens” it says the loader expands tokens in `LD_AUDIT` and defines `$ORIGIN` as the executable/shared-object directory, `$LIB` as architecture-dependent `lib`/`lib64`, and `$PLATFORM` as the processor type. Under “Secure-execution mode” it says nonzero `AT_SECURE` causes selected environment variables to be voided/modified and stripped; the listed variables include `LD_AUDIT`. The `LD_AUDIT` subsection explicitly says it is ignored in secure-execution mode. Thus the source supports the distinction: an environment gate rejecting `LD_AUDIT` by name is conservative even though secure-execution ignores it; the token rule describes expansion, not an assurance that an insecure environment setting is honored under secure execution.

The S518 row's language “honours ... tokens in the audit list” is best read as loader token-expansion semantics, not an unconditional guarantee that an `LD_AUDIT` environment setting takes effect in secure-execution mode. The adjacent secure-mode rule defeats that overbroad reading. The page also warns tokens need shell quoting.

S513 was rejected because its broad loader manual duplicated S512 (`rtld-audit(7)`) for the original predicate needing only identification of `LD_AUDIT` as the auditor-library variable. S518's added secure-execution/token facts are beyond that predicate and are explicitly the flip condition recorded for S513, so S518 supersedes the rationale only for this expanded claim; it does not rehabilitate S513 for the narrow name-only claim. The current round's freeze separately states the external S517/S518 spot-check is not recorded: this source re-open is not a claim of round-59 discernment progress or an external spot-check verdict.
