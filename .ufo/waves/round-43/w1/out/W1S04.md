## Findings

**F1 — Any row that merely names another counter's path hijacks that counter's registration (routed to the
L1; my rows avoid it).** `tools/gate-registry-check.py:196` registers a path by occurrence
(`matched = [r for r in rows if any(path in c for c in r)]`) and `tools/round43-registry-audit.py:155` grades
`pins` against *any* row containing the path (`hit = [l for l in rows if path in l]`, `:161-170`). My first
draft named `tools/round37-statement-audit.py` and `tools/round37-coverage-audit.py` inside the C3 row's
self-test cell, which produced:

```
$ python3 tools/gate-registry-check.py --repo .        # first draft
registered 17 unregistered 14 defective 0
EXIT=1
```

— five counters registered by three rows. Those two r37 counters would then have been graded by the pins leg
against the *operability* counter's `sha256 cef6f21983a2`, i.e. 2 pin mismatches and a false claim of
registration, while the honest `unregistered` signal disappeared. Fix applied in the deliverable: the C3 row
now reads "the two inherited round-37 counting instruments (statement and coverage)" with no path token.
Rule for integration: a row may name a helper counter's path only if that row also pins the helper's own
blob; otherwise the r37/r35/r36/r40/r41/r42 rows must be written on their own.

**F2 — pre-existing `flags=2`, unrelated to round 38; two rows name no `--flag` at all.**
`SKILL.md:1227` (Round-27 C1 counter) and `SKILL.md:1313` (Round-30 hold counter) have Kind/entry cells with
no `--flag`, while their counters declare flags. Command that shows it (same clause as
`tools/round43-registry-audit.py:136-143`, run over the freeze tree):

```
FLAGS-MISMATCH ('.ufo/waves/round-27/count-c1.py', ['--lane','--out','--repo'], [])
FLAGS-MISMATCH ('.ufo/waves/round-30/count-c1.py', ['--list','--oracle','--out','--repo','--tip'], [])
```

Proposed fix (one cell each, no counter change): in `SKILL.md:1227` cell 2 add `--out <receipt.json>`; in
`SKILL.md:1313` cell 2 add `--out <receipt.json>`. Both are declared. This removes the residual `flags=2`
from the C1 base receipt.

**F3 — the frozen C2 predicate text does not name the paths the counter measures (known, documented
deviation; nothing to fix in a frozen counter).** `tools/round38-coverage-audit.py:41-48` spells the two
artifacts `knowledge/sglang-docs-version-pinning*.md`, while `ENTRIES` at `:49-51` spells them
`corpus/knowledge/...`; `.ufo/waves/round-38/preregistration.json` carries the same `knowledge/` wording. The
counter's own docstring (`:22-28`) and `corpus/lessons/round-38.md` ("Instrument repair (C2, wave 1)") record
that the `knowledge/`-at-root lookup was the repaired defect and that `PREDICATE` was deliberately left
verbatim. Consequence for the registry: my row must not restate the predicate path, so it says "an entry
file absent at the tip or already present at base" and names no artifact. Proposed fix, for a later round
(counters are frozen here): align `PREDICATE` to `corpus/knowledge/...` and re-run the two controls, or keep
the verbatim text and add the deviation to the row's self-test cell.

**F4 — residual C1 surface after integration of my three rows** (context, not a defect): `unreg 19→16`,
`pins 19→16`, `flags 2` unchanged, and `selftest/dc/spot/hidden` untouched — those legs belong to other
seats. The rows are on exactly three of the 19 `NEWSET` counters
(`tools/round43-registry-audit.py:69-77`).

**F5 — the round-38 receipts cannot prove their own provenance.** No argv, revision, digest or exit code is
recorded in `.ufo/waves/round-38/{c1,c2,c3}/after.out` or in `controls/*.out`, and there is no `.exit`
sidecar. My rows therefore state the receipts' lines and the code's exits, never "receipt records exit N".
