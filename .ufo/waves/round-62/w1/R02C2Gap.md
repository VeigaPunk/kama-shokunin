# R02C2Gap — C2 measurement gaps

Axes: **operability + calibration**. Reviewed `tools/round62-c2-counter.py` and `registry/capability-claims-r62.tsv` at `master` tip `65d7cad0fce90e34de37527cde22e97b63b118bf`; review is read-only.

## Findings

1. **Recorded `verdict=true` cannot make a failing command pass the live check (with a caveat).** `run_bound` computes verdict as `not dead and pattern in output and rc == 0` (counter lines 245–274); `score` requires this computed Boolean to equal the recorded verdict (lines 193–242). Thus a command that exits nonzero is computed false, so a `true` row mismatches. Caveat: this is process/pattern success, not a semantic proof that a check's underlying assertion is sound; the check itself is the frozen template. Also, false is a valid recorded value, and the scorer does not require a true verdict or successful run for every capability: a false verdict can match a failing command and still be scored as bound/covered if the frozen pattern is present in its output. This permits a failing check to be represented as a correctly calibrated false row; it does not satisfy an implicit “all capabilities pass” criterion, which the frozen predicate does not explicitly impose.

2. **Manifest/registry fields trusted or weakly constrained.** The executable binding is fixed to a manifest entry's `id`, exact `run`, exact `pattern`, and a `quote` that is merely any >=8-character substring of the frozen prefix (lines 40–115 and 193–229). `parse_registry` only requires the first two header cells to match and then zips rows to whatever header is supplied (lines 161–181); extra/reordered/duplicate column names are not rejected as a canonical schema. Scoring never validates `note`; it treats `observed` as optional, only checking it when nonempty and then only as a substring of captured output (lines 230–242). Consequently the narrative note and omitted observation carry no measured evidence, and quote is a fragment, not a whole-row attribution. The current TSV uses all eight expected columns and records `true` plus observations (registry lines 1–13), but the counter does not enforce all those properties. `verdict` is interpreted solely as `row['verdict'].lower() == 'true'`; any other value silently means false (counter line 228), rather than being rejected as malformed.

3. **Sensitivity check is a textual predicate, not re-execution.** It replaces every occurrence of the exact frozen pattern in captured output and tests that the pattern is absent afterward (counter lines 268–272). For a nonempty frozen pattern this is mechanically true whenever that pattern appeared, independent of whether removing it changes the command's actual semantic result. It does not re-run the check against modified output/state. This makes `sensitive` weaker than a demonstrated causal sensitivity.

4. **`_EXEC_CACHE` makes current control re-scoring internally sound, but only for this process's fixed execution context.** Cache key is `(tip, cap)` (lines 132, 277–289); all controls use the same fixed manifest commands and same tip/context, so reusing each live execution is appropriate when evaluating mutated registry fields. The control families change registry structure/claims, not the allowed command, and their scoring still checks coverage/errors/mismatches (lines 292–348). It is not an independent second execution and the key omits `tip_tree`, `scratch`, `repo`, and environment; if reused across contexts in one Python process or expanded to multiple contexts, results could be stale. Present `main` invokes one tip and one context per process (lines 366–413), so no demonstrated stale-context escape in this invocation.

5. **`run_bound` environment is not fully hermetic.** `main` copies the caller's entire environment, overrides only `TMPDIR`, and removes only `PYTHONPATH` (counter lines 377–383). Commands inherit other variables (e.g. `PATH`, locale, proxy/configuration variables, Python runtime variables); subprocess uses that `env` directly (lines 245–274). Therefore “scrubbed environment” is overstated: TMPDIR is isolated and PYTHONPATH absent, but behavior can still depend on caller environment. No isolated HOME/PATH or explicit allowlist is established.
