### Why the frozen C2 counter cannot catch this

The counter is not broken and the claim is not falsely met; the row simply passes the counter's rule. `tools/digest-ledger.py:153` builds the blob set from raw blob bytes only —

```
153:            blobs.add(hashlib.sha256(buf[j + 1:j + 1 + size]).hexdigest())
```

— so a *decompressed member* can never enter it. The gz's own stored bytes hash to `c68132fb…`, not to `38e4ab…`. With no blob match the token falls to the ledger row, and `unverifiable` is accepted on the sole condition that `note` is non-empty (`tools/digest-ledger.py:92-93`, mirrored in `tools/round42-digest-audit.py:26,124-125`). A non-empty but false note scores `unverifiable`, hence:


| D | row kept `unverifiable` with **truthful** subject and note (non-empty note still passes `digest-ledger.py:92-93`) | summary line identical to the frozen one — `tokens=96 blob=86 … unverifiable=5 …`, no reference-line churn | **0** |

C is the only shape where the counter itself **verifies** the digest; D stays green on truthful prose alone (`R42B08/scan-D-truthful-prose.out`, byte-identical summary to `scan-head-unpatched.out`). D corrects the false note and the misdated subject and needs no re-freeze, but the `class` column stays false against the tool's own definition at `tools/digest-ledger.py:27` — the tool never compares a class to reality, it only tests that the note is non-empty (line 92-93), which is exactly the blind spot D leaves in place. Ranking: **C** if the L1 will accept the reference-line change, **D** as the no-re-freeze fallback with the false class recorded as a known limitation. Concrete patch (exactly what `R42B08/digest-ledger-patched.py` does; +13 lines (266 -> 279), `gzip` import, no behaviour change for non-`.gz` blobs):

1. `tools/digest-ledger.py` — add `import gzip` beside the existing imports, and in `scan_git` add, before the `tokens, ledger = set(), {}` block:

```python
    for line in git(repo, "ls-tree", "-r", "-z", rev).decode(errors="replace").split("\0"):
        if not line or "\t" not in line:
            continue
        meta, path = line.split("\t", 1)
        if not path.endswith(".gz"):
            continue
        oid = meta.split()[2]
        try:
            blobs.add(hashlib.sha256(gzip.decompress(git(repo, "cat-file", "-p", oid))).hexdigest())
        except OSError:
            pass
```

   mirror it in `scan_dir` (decompress files ending `.gz` before adding their digest).
2. Docstring `tools/digest-ledger.py:16-18` — say the blob set is the SHA-256 of every blob reachable from REV **plus the decompressed member of every `.gz` blob** (else the frozen contract text and the code disagree).
3. `registry/digest-ledger.tsv:9` — delete the row (with C the token classifies as `blob`, and an in-ledger row is unreachable anyway, so keeping it only preserves the false statement).
4. If the L1 prefers to keep an explanatory row, the honest alternative is a new class `packed` with `path` = the gz and a `note` naming the member size — but that needs the same tool change plus a `packed` branch, so C is the smaller fix.
5. Side effect to re-freeze knowingly: C changes the C2 reference line from `blob=86 … unverifiable=5` to `blob=87 … unverifiable=4` (tokens stay 96). Because `prefixes` is derived from `blobs` (`tools/digest-ledger.py:77`), a decompressed digest can in principle make an unrelated near-miss token `wrong_unflagged`; measured at HEAD that does not happen (`wrong_unflagged=0`).
