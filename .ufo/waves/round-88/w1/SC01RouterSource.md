## Findings

**(1) Status values the router can emit — a 7-value enum, not the 6 S581 documents.** `tools/server/server-models.h:33-41` `enum server_model_status` = DOWNLOADING, INCOMPLETE, **DOWNLOADED**, UNLOADED, LOADING, LOADED, SLEEPING; `server-models.h:52-66` maps them to `"downloading","incomplete","downloaded","unloaded","loading","loaded","sleeping"` (default `"unknown"`); emitted per entry at `server-models.cpp:2345-2348` → `:2363-2370`. **NOTE** — `"downloaded"` is set only at `:1635`, flagged `need_reload` (`:1636`); the next `get_all_meta()` (`:1277-1281`) reloads and **erases** it (`:1119-1122`) — a transient internal marker. `README.md:2059-2121` and `corpus/knowledge/router-mode-readiness.md:19` list only six, so S581 must not be re-read as exhaustive; the frozen rule is safe (probe's `*)` arm catches it) but the knowledge entry is incomplete. **NOTE** — `status.progress` does not exist in the listing: S581's `README.md:2098-2110` shows it nested in `status`, the code never writes `status["progress"]` (progress rides `meta.progress` `:1601-1602` → SSE only `:1618-1619`), and counter cell C06 (`counter-M.py:68-70`) grades that fictional shape.

**(2) `/v1/models` vs `/models` — byte-identical in router mode.** `server.cpp:283-284` registers both to the same `routes.get_models`, replaced in router mode by `get_router_models` (`server.cpp:269`); live `A_v1_eq_models: true`. Router listing = `{"data":[…],"object":"list"}` with `status` per entry (`:2363-2380`), no `models[]`. **Single-model mode differs**: `server-context.cpp:5196-5227` returns *both* `models[]` (ollama-shaped `name`/`model`) and `data[]` (OAI `id`) and **no `status`** — that is what keeps single-model verdicts unchanged under the frozen rule. The probe reads `data[]` first (`probe-M.sh:464-489`).

**(3) Completion for an unloaded model.** `router_validate_model` (`server-models.cpp:2163-2179`) resolves alias→canonical (`:2173-2174`), then **`if (!models_autoload && !meta->is_running())`** → `res_err(..., format_error_response("model is not loaded", ERROR_TYPE_INVALID_REQUEST))` (`:2176`); `server-common.cpp:91-131` → code 400 / type `invalid_request_error`; `res_err` (`:2159-2161`) sets HTTP status from that code. Autoload default/override: `is_autoload` (`:2182-2189`), only `"true"`/`"1"` count. Live: `--no-models-autoload` → **400** `{"error":{"code":400,"message":"model is not loaded","type":"invalid_request_error"}}`; default (autoload on) → **200** real completion (status flips to `loaded`); `?autoload=true` overrides the server default → **200**; unknown name → **400** `model 'X' not found`. `is_running()` (`:98-100`) counts LOADED/LOADING/SLEEPING, so `loading`/`sleeping` also pass the guard.

**(4) Do `sleeping` instances serve without a reload? They serve, but they DO reload the model.** The router does not respawn (`ensure_model_ready` `:1741-1743`: *"child is sleeping but still running; new request will wake it up"*); the **child** reloads — `server-context.cpp:1064-1080` `handle_sleeping_state`: sleep→`destroy()` (`:1071-1072`), wake→`load_model(params_base)` (`:1076-1077`); child log proves it (`router-sleeping-child.log`: `server is exiting sleeping state` then `load_model: loading model '…/stories260K.gguf'`). Wake is request-triggered (`server-queue.cpp:115-127`, `:326-350`).

**BLOCKER — the frozen verdict rule and the frozen oracle disagree on `sleeping`, and the frozen counter cannot detect it.** The counter's live oracle derives expectation from a real completion (`counter-M.py:170-178`: 200→`MODEL_OK`, 400+`"model is not loaded"`→`MODEL_UNLOADED`). Running the **frozen probe bytes** (`git show 138a7543:tools/kama-probe.sh`) and the **frozen oracle logic** on a lane-owned `sleeping` child (`attack-sleeping-oracle.json`): `"MATCH": false`, `oracle_expected: MODEL_OK`/http 200, `probe_verdict: MODEL_UNLOADED`/`router-sleeping`. The counter avoids this only because its three live cells are `unloaded→loaded→unloaded` (`counter-M.py:200-202`) and **never enter `sleeping`**, while canned cell C05 asserts `sleeping→MODEL_UNLOADED` by authorship (`:67`). The lane's own measured receipt already contradicts it: `.ufo/waves/round-88/measured/router-lifecycle.out` step 3 records `sleeping` → probe `MODEL_UNLOADED` → completion **HTTP200**. Reachable **even under `--no-models-autoload`**, i.e. the counter's own configuration — any router with `--sleep-idle-seconds` (the operator's live router runs `--sleep-idle-seconds 600`, `router-mode-readiness.md:30`) reports drift (exit 2) for a fully serviceable endpoint; `sleeping` is a retained-instance state (`is_ready_or_sleep`, `server-models.h:102-104`).

**BLOCKER — the same contradiction exists for `unloaded` under autoload ON (the router default).** `counter-M.py:196` starts the child with `--no-models-autoload`, so the oracle's 400 branch is always taken; under the default (`--models-autoload`, enabled per `README.md:233`) an `unloaded` model completes with **200** (`router-probe-live.json` `B_completion_unloaded_autoload_on` code 200; `attack-exit-codes.json` `autoload_on_unloaded`: probe `MODEL_UNLOADED` vs oracle `MODEL_OK`/200). The frozen rule and oracle agree **only because of that flag**. **(5) Surfaces the frozen rule ignores.** The rule reads only `status.value` and `status.failed`: `status.exit_code` (`:2358-2361`, set only when `is_failed()` = UNLOADED **and** exit_code≠0, `server-models.h:105-107`) is **discarded** — crash(1) vs OOM-kill(137) indistinguishable (probe keeps only a `-failed` suffix, `probe-M.sh:506`); `status.args` (`:2347`), `status.preset` (`:2350-2357`) ignored; **`model_info.aliases` (`:2365`) never read** (`grep -c aliases probe-M.sh` → 0) although the router resolves aliases on every request (`:1267-1272`, `:2173-2174`) — live: a preset with `alias = kama-alias` lists `{"id":"stories260K","aliases":["kama-alias"],…}` and a completion addressed to `kama-alias` resolves (it fails only `model is not loaded`, i.e. past alias resolution; an unknown name gives `model 'X' not found`), yet the frozen probe returns **`MODEL_MISMATCH`/`served-id-mismatch`** — a false negative on a servable model; `?autoload=true|false` per request (`:2182-2189`) never varied; `source`/`can_remove`/`context_length`/`architecture`/`tags` ignored; **`GET /props` never fetched** (`probe-M.sh:521` fetches only `/v1/models`) though router mode exposes `role`/`models_autoload`/`max_instances` (`:2241-2244`); `POST /models/load|unload` (`:2310-2331`, `:2463-2479`) and `GET /models/sse` (`:2470-2482`) ungraded, so `MODEL_UNLOADED` carries no operator action; `hidden` models (`:2341-2343`, `:1017-1021`) are excluded from the listing yet still accepted if requested.
