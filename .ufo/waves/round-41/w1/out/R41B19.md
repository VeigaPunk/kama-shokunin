## Tag pushed between the two calls

Yes. Counter and tool fetch independently, sequentially: reference calls for each row at `round41-pinwatch-audit.py:252`, then tool's calls begin at `:258` (tool loops rows in `pin-watch.py:108-132`). If an upstream adds a matching tag after the reference call but before the tool call, both sides can be healthy yet disagree (e.g. reference says newest `v0.5.22`; tool sees `v0.5.23`), making `live=0` for that run. In reverse order of a delete/move, similarly. Calls are not atomic across the three engines either, so the “same-moment” description is approximate, not a shared snapshot. This creates a race-induced false negative / flaky evaluation; a tag addition cannot yield a false pass under this mechanism, because equality still needs both observations to match. No direct tag-race was induced in this review; this is a source-derived counterexample, not a claimed observed incident.
