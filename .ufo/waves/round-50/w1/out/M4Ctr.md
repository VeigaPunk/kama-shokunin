## Survivors — coverage findings (proposed killing cases; counter frozen, findings only)

Common root cause for the fence/CR group: the counter's `fence_open`/`fence_close`/`sections`/`key()` run **only against lane blobs in the lane leg**, and the only two events with ungraded lines touch SCORECARD.md blobs with **0 fence lines and 0 CR lines**. The fence/CRLF semantics of the *tool* are pinned by the fixture leg (M20/M21 kill), but the *counter's own parser* has no negative sample anywhere.

- **M01/M02/M03/M04/M06** (fence helpers, lines 103/311/322/330): native counts byte-identical (23/72) because there are no fences to mis-parse. Killing case: any lane blob where a mis-parsed fence swallows or fakes a `## Axes` heading over deleted lines (e.g. a `    ```-indented opener, a ```info-with-backtick line, an exact-n closing fence under M03, or a `## Axes` inside a fence under M06) with a tool that over-ungrades those lines. Proposal: a synthetic fence-parser unit leg (fixture-style) would arm all five; on the frozen inputs they are dead code paths.
- **M07** `key()` CR-blind (line 344): 0 CR lines in sampled blobs. Killing case: a lane file moved with CRLF (the exact F5 hazard) — today only the tool's fixture scenario pins CR handling; the counter's own `key()` is unexercised.
- **M08** split_lines phantom line (349-351): effect confined to empty-line keys (extra birth of `b""`); no lane event deletes a blank line whose origin matters. Killing case: an event deleting a trailing blank line under an exempt-parent-section whose origin must exclude it.
- **M09/M10** origins widening (455/454): native identical (23/72) — for every counted line, every commit holding the key holds it under an exempt title, so birth-tightness never binds on this history. Killing case: a key held under a non-exempt title in some non-birth commit (or a merge where the union differs from last-parent), with the tool ungrading at the widened bound.
- **M11** shortcut removed (450-452): **equivalent** — if a parent's blob equals the child's, the union of parent keysets is a superset of the child's keys; when the union equals the child keyset the birth-skip is reproduced (`k not in pkeys` never true adds nothing), otherwise `pkeys ⊋ keys` makes every `k` fail `k not in pkeys`, so no births are recorded — identical origin map either way. Outputs identical on both inputs, as the proof predicts (performance-only difference).
- **M12** native origin-conjunct dropped (489): native identical (23/72) — at tip+base every parent-section-exempt deleted line already satisfies `origin ∩ exempt`. The origin conjunct is vacuous on the frozen lane; the binding constraint is the parent-section test (M13/M05 kill). Killing case: a deleted line under an exempt parent section but born under a non-exempt title, with a tool that over-ungrades it.
- **M16** numstat `!=`→`<` (473): no lane event under-reports deletions, so the loosened oracle is indistinguishable. The oracle is armed but carries no negative lane sample (consistent tool at both commits). Killing case: a tool reporting `deleted < numstat` — not reachable against the frozen tip tool.
- **M17** fixture arithmetic off (213-217) / **M18** lane arithmetic off (467-470): all events internally consistent on both inputs, and every fixture scenario additionally pins the discriminating event's exact counts + exit. Belt-and-braces with no discriminating power against the frozen tool (the K2Cheat-class defect it guards would need a defective tool to exercise it).
- **M19** order expectation pin dropped (279): tip grades 0 anyway; base order-b still fails via exit/status/deleted. The `graded: 0` pin is redundant given the other pins.
- **M23** bad_declarations neutralized (397): tool reports `bad_declarations 0` at both commits — check unexercised. Killing case needs a tip-state tool with a bad declaration; not reachable.
- **M28** binder NEG3 emptied (105): the counter's own v4 binder only affirms rows that bind cleanly; `says()` is never consulted negatively on this contract. Matches V2Ctr's noted limit (the counter still copies the v4 rule).

**Net reading:** the counter's discriminating core at these inputs is exactly {parent-section conjunct + strict `>` at an exactly-tight bound (M05/M13/M14), numstat deleted-column oracle (M15), events>=5 (M24), fixture scenario pins incl. exit contracts (M20), the order-b/fence/crlf constructions vs base (M21/M22/M25-crash M26/M27 incidentals), and the `met` conjunction (M25)}.
